# clearcut — Clear Cut Challenge (いあいぎりがっせん / 포켓몬 스타디움 2, N64) 디자인 스펙

> 이 문서만으로 게임을 재구현할 수 있도록 작성. 원작 자료에 없는 값은 `불명 — 추정:` 으로 표시하고 리뷰어가 유튜브 영상과 비교할 수 있게 근거를 적었다.
> 좌표/시간 값은 셸 캔버스 960×540 기준(`g.W`, `g.H`).

---

## 1. 한 줄 요약 · 등장 캐릭터와 플라밍고 대체안

**한 줄 요약**: 거미(페이검/Spinarak)가 실로 매달아 떨어뜨리는 통나무(log)를, 각 플레이어가 **A 버튼 한 번**으로 `Cut(이아이기리)` 해서 통나무에 그어진 **흰 선(white line)에 최대한 가깝게** 자르는 타이밍 게임. 5라운드 합계 점수로 승부.

| 원작 요소 | 원작 | 플라밍고 대체안 |
|---|---|---|
| 플레이어 캐릭터 | 스라크(Scyther) / 쁘사이저(Pinsir) 무작위 배정, 트랜스퍼팩 시 핫삼(Scizor) | 플라밍고 4마리(슬롯 색 `palette.players[i]`). 대기 = `idle`, 공격(베기) = `hit` 포즈 0.35s, 만점 = `jump` 1.0s, 낮은 점수 = `idle`, 감점/헛스윙 = `dizzy` 1.0s |
| 통나무를 매단 페이검(Spinarak) | 화면 상단에 매달린 거미가 실로 통나무를 들어올린 뒤 놓는다 | 상단에 매달린 작은 플라밍고(`fly` 포즈, scale 0.9, 회색 `#777`)가 부리로 끈을 물고 있다가 놓는다. 끈은 세로선(`#e8dcc0`, 2px) |
| 통나무(log) | 세로로 긴 갈색 원통, 나이테 있는 단면, 중간 어딘가에 얇은 흰 가로선 | 동일. 갈색 `#8b5a2b`, 껍질 줄무늬 `#6b4320`, 흰 선 `#ffffff` 3px, 단면 `#d9b27c` |
| Cut 이펙트 | 가로 섬광 한 줄, 통나무가 두 조각으로 갈라져 위 조각이 튀어 오름 | 동일(흰색 섬광 1프레임 + 두 조각 분리 애니메이션) |
| 무대 | 숲속 공터, 나무 데크/통나무 받침대 4개 | `bg()` 위에 초록 배경 + 나무 바닥판, 받침대 4개 |

## 2. 인원 · 시간 · 라운드 구조

- **4인 동시 플레이**(사람 1~4, 나머지 CPU). 각자 자기 통나무를 자르며 서로 간섭 없음.
- **제한 시간 없음. 종료 조건 = 5라운드 완료.** (`duration: 0`, 게임이 `g.finish()` 호출)
- 원작 확정: "five tries / five rounds" (Bulbapedia, StrategyWiki, Fandom 모두 일치).
- 라운드 1회 흐름(추정 시간, 원작 영상 길이 기준 — 비평가 보정, 문서 끝 「비평가 보강」 참조):
  1. **들어올리기(raise)** 2.0s — 거미가 통나무를 실로 천천히 끌어올려 상단 대기 위치까지 올린다.
  2. **대기(hold)** 0.8~2.4s 난수 — 통나무가 상단에서 살짝 흔들리며 정지. (페이크 드롭 없음 — §5)
  3. **낙하(drop)** ≈ 0.55s — 자유낙하에 가까운 등가속 낙하(v0=360, g=900 → 대기 하단 y=250에서 받침대 y=430까지 약 0.4s, 흰 선이 칼날에 닿기까지 0.19~0.43s). 통나무 하단이 받침대(y=430)에 닿으면 “쿵” 하고 정지(놓친 것). 4명 동시에 떨어진다.
  4. **판정·표시(result)** 2.0s — 각 플레이어 머리 위에 `+20` / `+7` / `-4` / `-10(놓침)` 숫자 팝업. 통나무 조각 정리.
  5. 다음 라운드. 라운드 사이 텀 1.0s.
- 총 플레이 시간 ≈ 5 × (2.0+1.6+0.55+2.0+1.0) ≈ **36~38초** + 시작/종료 연출 ≈ 50초. 원작 플레이 영상은 메뉴·결과 포함 110초(d_2WvEWZ5RM), 195초(RjBekyDnfE4, 퍼펙트 영상)로, 한 라운드가 6~9초의 느긋한 템포다. 이전 초안의 28~32초는 너무 빠르므로 수정.

## 3. 조작

| N64 | 원작 기능 | 우리 액션 |
|---|---|---|
| **A** | Cut(베기). 한 번 누르면 즉시 칼날 높이에서 가로로 자른다 | `a` (hit) |
| B | 없음 | `b` = A와 동일 취급(편의) |
| 스틱 / C / Z / R | 없음 | 무시 |

- **연타 무효 / 홀드 무효**: 라운드당 **딱 1회**만 유효. 첫 `hit('a')` 에서 베기 발동, 그 라운드의 이후 입력은 무시. `down('a')` 유지로는 발동하지 않는다(프레임 hit만).
- **베기 가능 시점**: 들어올리기·대기(hold)·낙하 중 언제든 A를 누르면 즉시 휘두른다(라운드당 1회 소진). 통나무 몸통이 칼날 높이에 없을 때(아직 안 내려옴 / 이미 지나감) 휘두르면 **헛스윙(miss) = -10**. **원작 확정**: 일본어 포켓몬Wiki “반응이 늦거나 너무 빨라서 통나무를 못 자르면 감점 폭이 더 크다” → 이른 헛스윙도 놓침과 같은 최대 감점. 통나무가 받침대에 닿아 정지한 뒤에는 입력 무시(이미 miss 확정).
- **판정 기준**: 플레이어 칼날 높이는 고정 `BLADE_Y = 300`. 베는 순간 통나무의 흰 선 y좌표 `lineY` 와 `BLADE_Y` 의 차이 **`d = BLADE_Y − lineY`**(px, 양수 = 선이 아직 칼날 **위**(화면 y가 작음) = 일찍 벤 것, 음수 = 선이 이미 칼날 아래로 지나감 = 늦게 벤 것). (초안은 부호가 반대였음 — 2차 비평에서 정정.)
- **입력 수용 상태**: `준비/시작` 연출, `result`, 라운드 텀 동안의 A는 무시(소진되지 않음). `raise/hold/drop` 중에만 유효하며 1회 소진. 통나무 정지 후(miss 확정)도 무시.
- 입력 지연 보정 없음(타이밍이 곧 실력). 단 `hit`는 프레임 단위이므로 60fps 기준 ±8ms 오차.

## 4. 규칙과 점수

원작 확정 사항(출처 3개 일치):
- 선 위 정확히 = **+20점(최대)**.
- 선 **아래**(=일찍 벰, 선이 칼날보다 위에 남음) = 거리에 따라 **+1 ~ +10점**.
- 선 **위**(=늦게 벰, 선이 이미 칼날 아래로 지나감) = **감점**(거리에 따라).
- 통나무를 아예 못 벰(놓침·헛스윙) = **-10점**.
- 5라운드 합계 최다 득점 승. 점수는 음수도 가능.

수치화(불명 — 추정, 통나무 길이 200px 기준. 퍼펙트 창은 낙하 속도 기준 약 2프레임(60fps)이 되도록 잡음):

| 조건 | `d = BLADE_Y − lineY` | 점수 |
|---|---|---|
| 퍼펙트 | |d| ≤ 12px (≈±1프레임) | **+20** |
| 일찍(선 아래 베기) | 12 < d ≤ 112 | `10 − floor((d−12)/10)` → 10,9,…,1; d > 112 이어도 통나무 몸통이 칼날에 있으면 최소 **+1** |
| 헛스윙(통나무 하단이 아직 칼날 위: `logBottomY < BLADE_Y`, 또는 통나무 상단이 이미 칼날 아래: `logTopY > BLADE_Y`) | 몸통이 칼날에 없음 | miss **−10** (원작 확정) |
| 늦게(선 위 베기) | −112 ≤ d < −12 | `−ceil((−d−12)/10)` → −1,−2,…,−10; 그보다 늦어도 몸통에 맞으면 **−10** 상한 |
| 놓침 | 안 누름 / 통나무 정지 후 | **−10** |

- 이유: 원작에서 "일찍"은 안전(양수), "늦음"은 손해라 플레이어가 살짝 이르게 누르는 심리전이 생긴다. 이 비대칭을 그대로 유지. (공략 원문: "If you can't get right on the line, try to get under it.")
- 흰 선이 통나무 하단 가까이 있으면 “선 아래” 구간(+1~+10)이 물리적으로 짧아진다(예: 하단에서 30px면 +9~+10 구간만 존재하고 그보다 이르면 헛스윙). 이것이 원작이 말하는 “선이 통나무 끝 근처에 그어지면 어렵다”의 실체이므로 구간 폭(10px/점)은 통나무 길이와 무관하게 고정한다.
- **원작 점수 예시**: 5라운드에서 20+8+20+(-3)+12 = 57점. CPU Hard는 60~90점대, 사람 초보는 20~40점대가 나오는 것이 자연스럽다. 만점 100점.
- **동점 처리**: **원작 확정** — 미니게임 공통으로 동점자끼리 랜덤 퀴즈 1문제로 승자 결정(챔피언 모드 한정 아님). 셸에 퀴즈가 없으므로 셸의 동순위 표시를 그대로 두고 `text`에 "동점!" 표기.
- 결과 `result()`: `{ scores: 합계 4개, text: '최고 ${max}점 · 퍼펙트 ${n}회' }`(§7과 동일 문구), `lowerIsBetter` 없음. 동점이면 text 앞에 `동점! ` 추가.

## 5. 난이도 곡선 · CPU 난이도

**원작 확정(일본어 포켓몬Wiki)**: 난이도 곡선은 **라운드가 아니라 CPU 난이도 설정**에 걸려 있다 — “난이도가 높으면 낙하 속도가 빨라지고, 감점되기 쉬운 위치(통나무 끝 근처)에 흰 선이 그어진 통나무가 떨어진다.” 라운드 1→5 안에서 속도가 빨라진다는 기록은 어느 출처에도 없다. 따라서 **낙하 속도는 한 판 안에서 고정**하고, 셸에 난이도 설정이 없으므로 원작 Normal~Hard 사이의 값을 쓴다. 다만 5라운드가 밋밋하지 않도록 **흰 선 위치의 범위만** 라운드가 갈수록 넓힌다(우리 재량 — 원작의 “끝 근처 선” 요소를 후반 라운드에 배치).

| 항목 | 값 | 근거 |
|---|---|---|
| 낙하 초기속도 | 360 px/s (전 라운드 동일) | 불명 — 추정. 원작 Normal 체감. 셸에 난이도가 생기면 Easy 300 / Hard 440 / Very Hard 520 |
| 중력 | 900 px/s² (전 라운드 동일) | 불명 — 추정 |
| hold 난수 | 0.8~2.4s 균일, 4명 공통 | 불명 — 추정 |
| 흰 선 위치(통나무 상단 기준 %) | R1 40~60, R2 35~65, R3 30~70, R4 20~80, R5 15~85 | 우리 재량(원작은 난이도별) |
| 페이크 드롭 | **없음** | 어느 출처·영상 설명에도 없음. 초안의 페이크 항목 삭제 |

- 흰 선이 칼날에 도달하기까지 걸리는 시간: 대기 위치(통나무 상단 y=50)에서 선까지 거리 80~220px → 낙하 시작 후 **0.19s(선이 하단 85%) ~ 0.43s(상단 15%)**. 선 통과 속도 ≈ 530~750px/s → **±12px 퍼펙트 창 ≈ 32~45ms(약 2프레임)**. 일찍 구간(+1~+10) 폭 100px ≈ 130~190ms(8~11프레임). 늦은 구간도 같은 폭.
- 4명 통나무의 **선 위치는 각자 다르게** 난수(원작: “four separate logs… a thin white line marked somewhere on them”). 낙하 타이밍(hold 길이)은 4명 **동일**(거미가 동시에 놓음 — 추정, 영상에서 4개가 동시에 떨어짐).

**CPU 난이도(Easy/Normal/Hard/Very Hard/Hyper)**: 원작 스타디움 2는 Easy/Normal/Hard + 해금 Very Hard(스타디움 1은 Hyper). 셸에는 난이도 설정이 없으므로 **기본 Normal**, CPU 3명에게 Normal/Hard/Very Hard를 하나씩 섞어 배정(슬롯 순서 1→Normal, 2→Hard, 3→Very Hard)해서 원작의 "이길 만하지만 만만치 않은" 느낌을 낸다. 행동 차이는 §8.

## 6. 화면 구성

- **카메라**: 정면(약간 위에서 내려다보는 3/4 정면). 횡스크롤 없음, 고정 화면.
- **배치(좌→우 1P~4P)**: 플레이어 x = `150, 370, 590, 810`(간격 220). 플라밍고 발 y = 430, scale 1.8, 통나무 오른쪽 옆에 서서 오른쪽을 본다(`flip` 없음, 통나무는 x−70 위치). 통나무 중심 x = `px − 70`.
  - 받침대(둥근 나무 그루터기): 폭 90, 높이 26, y=430~456, 색 `#a0703c`.
  - 통나무: 폭 56, **길이 200**. 상단 대기 위치 = 통나무 **상단 y=50, 하단 y=250**(전부 화면 안, 칼날 y=300보다 50px 위). 낙하 종료 = 하단 y=430. 들어올리기 시작 위치 = 하단 y=430(받침대 위에 새 통나무가 놓여 있고 거미가 끌어올림).
  - 칼날 높이 `BLADE_Y=300`: 플라밍고 부리/날개 높이. 화면에 **얇은 점선 가이드는 그리지 않음**(원작에 없음). 대신 플라밍고 옆에 작은 빨간 삼각 마커(▶, x=px−100, y=300)만 표시 — 불명, 편의 추가.
  - 거미(회색 플라밍고 `fly`, scale 0.9): 각 통나무 위 x=px−70, **y=22**에 매달림. 실은 y=0 → 거미 → 통나무 상단(y=50, 들어올리는 중엔 통나무 상단을 따라 늘어남). 낙하 시작 시 실이 끊기고 거미는 제자리에서 흔들린다(0.5s).
- **HUD**:
  - 상단 중앙: `라운드 3 / 5`(폰트 28, `palette.gold`).
  - 각 플레이어 발밑 y=470: `drawPlayerTag` + 그 아래 y=500 합계 점수(폰트 24, 흰색, 음수면 `palette.red`).
  - 라운드 결과 팝업: 플레이어 머리 위 y=200에서 2.0s 동안 위로 20px 떠오르며 페이드. `+20`은 금색 `palette.gold` 크기 40, 양수 흰색 32, 음수 빨강 32, 놓침은 `놓침 -10`.
- **배경 소재·색감**: 숲속 공터. 하늘 `#bfe3ff` 상단 → 나무 실루엣 진초록 `#2f6b3a`, 바닥 잔디 `#5aa14a`, 나무 데크 `#c08a4e`. 통나무·그루터기 갈색 계열, 흰 선은 순백으로 대비 강하게.

## 7. 연출

- **시작**: 셸 타이틀 → `init()` 후 화면 중앙 `준비…`(0.8s) → `시작!`(0.5s, `sfx.go`). 이 동안 4마리 `idle`. 원작 아나운서 "Ready? Go!" 대응.
- **들어올리기**: `sfx.tick` 0.3s 간격 4회(실 감는 소리). 통나무가 y 위로 등속 이동.
- **낙하 시작**: `sfx.pop`(실 끊김).
- **베기**: 입력 즉시 플라밍고 `hit` 포즈 + 흰 가로 섬광(폭 90, 높이 4, 2프레임) + `sfx.hit`. 통나무는 그 y에서 두 조각으로 갈라져 **위 조각**은 오른쪽으로 40px 튀며 회전(0.4s) 후 낙하, 아래 조각은 그대로 받침대까지 떨어짐. 절단면에 단면색 나이테를 그림.
- **판정 피드백**(판정 단계 2.0s):
  - +20: `jump` 포즈, **샤미센 “베베벤~” 풍 효과음**(원작 체감 기록: “白線ピッタリに切れた時とか三味線でベベベ~ンみたいな音”) → `sfx.beep(440,0.08,'sawtooth',0.4)` → 60ms 뒤 `sfx.beep(392,0.08,'sawtooth',0.4)` → 60ms 뒤 `sfx.beep(330,0.25,'sawtooth',0.5)` 3연타 + `sfx.good`, 팝업 금색 `+20` + 작은 `퍼펙트!` 텍스트.
  - +1~+10: `idle`, `sfx.tap`, 흰 팝업.
  - 음수: `dizzy`, `sfx.bad`, 빨간 팝업.
  - 놓침: 통나무가 받침대에 “쿵”(`sfx.beep(90,0.15,'square',0.5)`), `dizzy`, `놓침 -10`.
- **종료**: 5라운드 판정 후 1.0s 정지 → 1위 `jump` 반복, 나머지 `idle`, `sfx.win` → `g.finish()`. 원작 아나운서 요지: "가장 정확하게 벤 것은 ○P!" → 셸 결과 화면 `text`로 `최고 ${max}점 · 퍼펙트 ${n}회` 표시.
- 셸 하단 바 조작 문구: `A 버튼: 베기 (라운드당 1번)`.
- `howto`: `['통나무가 떨어지면 A 버튼으로 베기', '흰 선에 딱 맞추면 20점, 늦으면 감점', '5라운드 합계로 승부']`.

## 8. AI 행동 모델 제안

CPU는 "선이 칼날에 도달하는 예상 시각"을 기준으로 **반응 지연 + 정규분포 오차**로 누른다. 라운드마다 `targetOffset`(양수=일찍)을 미리 뽑아 두고, 낙하 중 `d = BLADE_Y − lineY`가 **`targetOffset` 이하로 내려오는 첫 프레임**(`d <= targetOffset`)에 `hit`. (초안의 `lineY ≤ BLADE_Y + off`는 낙하 시작 즉시 참이 되어 CPU가 곧바로 휘두르는 버그 — 2차 비평에서 정정.) 낙하 전(raise/hold)에는 절대 누르지 않는다.

| 난이도 | 목표 오프셋 평균 (px, +=일찍) | 오차 σ (px) | 반응 지연 (ms, 낙하 시작 후 최소 대기) | ~~페이크에 속을 확률~~(페이크 삭제로 미사용) | 완전 실수(놓침) 확률 | 기대 라운드 점수 |
|---|---|---|---|---|---|---|
| Easy | +55 | 45 | 250 | 0.35 | 0.12 | ≈ +4 |
| Normal | +30 | 28 | 180 | 0.20 | 0.06 | ≈ +8 |
| Hard | +12 | 14 | 120 | 0.10 | 0.02 | ≈ +13 |
| Very Hard | +4 | 7 | 80 | 0.04 | 0.00 | ≈ +17 |
| Hyper(미사용) | +1 | 3 | 40 | 0.00 | 0.00 | ≈ +19 |

- 구현: 라운드 시작 시 `off = mean + gaussian()*sigma`; 낙하 시작 후 `delay` 경과 전에는 절대 누르지 않음(그래서 늦은 라운드일수록 낮은 난이도는 자연스럽게 감점). `off`가 통나무 하단보다 아래(=몸통이 아직 칼날에 안 옴)를 가리키면 자연히 이른 헛스윙(−10).
- 완전 실수는 그 라운드 입력 안 함(놓침 −10). 낮은 난이도의 “이른 헛스윙”은 `off`가 통나무 하단을 넘을 때 자연히 발생.
- 각 CPU에 고정 시드 없이 매 라운드 새로 뽑아 결과가 매판 달라지게 한다.

### 추가(구현에 필요한데 빠져 있던 것)
13. **상태 머신**: `ready(0.8) → go(0.5) → [raise(2.0) → hold(0.8~2.4) → drop(하단이 y=430에 닿을 때까지, ≈0.55) → result(2.0) → gap(1.0)] ×5 → end(1.0) → g.finish()`. 라운드 카운터는 raise 진입 시 증가. `init()`은 셸이 타이틀 뒤 첫 프레임과 매 시작마다 부르므로 모든 상태·점수·난수를 `init()`에서 초기화. 4명 모두 베더라도 drop은 조각이 받침대에 닿을 때까지 유지.
14. **입력 수용 범위(§3)**: raise/hold/drop에서만 유효, 라운드당 1회. 그 외 상태의 A는 무시(소진 안 됨). `b`는 `a`와 동일.
15. **아이템·장애물 없음** 재확인(모든 출처). 4명 통나무 독립, 서로 간섭 없음.
16. **난이도 램프**: 원작은 난이도 설정으로만 험해짐(1차 비평 인용, 미검증). 우리 판 안에서는 낙하 속도 고정, 선 위치 범위만 R1 40~60% → R5 15~85%로 확장(재량). CPU는 슬롯별 Normal/Hard/Very Hard 고정.
17. **미검증 항목 표시**: “이른 헛스윙 −10”, “난이도↑=낙하 속도↑·선 끝 근처”는 1차 비평의 일본어 Wiki 스니펫에만 의존(2차 접근 실패). 구현은 그대로 하되, 리뷰어가 유튜브 d_2WvEWZ5RM 에서 이른 헛스윙 장면을 보면 확인 바람.
18. **템포 감**: 낙하 자체는 0.5초 안팎으로 빠르고, 라운드 사이가 느긋한 “정적→한 순간” 리듬이 이 게임의 핵심. hold 난수(0.8~2.4s)를 절대 고정하지 말 것(예측 가능해지면 원작 긴장감이 사라짐).

## 구현 메모 (games/clearcut.html, 2026-09-10)

스펙대로 구현하되 실제로 돌려보고 고친 점. 나머지 수치(라운드 5회, 들어올리기 2.0s, 대기 0.8~2.4s, v0=360/g=900, 판정 ±12px·10px/점, CPU 모델 §8)는 그대로다.

1. **착지 깊이 = 하단 y=500(받침대 구멍 속으로 70px)**. §6의 "낙하 종료 = 하단 y=430"이면 정지 시 상단이 y=230이라 흰 선이 통나무 위쪽 35% 안에 있으면(R3~R5의 15~35%) **칼날 y=300에 영영 도달하지 못해** 누구도 자를 수 없다(시뮬레이션에서 Hard CPU가 20% 라운드를 강제 놓침). §2·§5의 "선까지 80~220px 낙하" 계산은 사실 하단 y≈500까지 떨어져야 성립하므로, 받침대를 구멍 뚫린 홀더로 그리고 통나무가 그 안으로 꽂히게 했다(구멍 아래 부분은 클립으로 가림). 낙하 시간 ≈0.45s.
2. **낙하 전(들어올리기·대기) 스윙은 무조건 헛스윙 −10**. 들어올리기는 통나무가 받침대에서 칼날 높이를 천천히(90px/s) 지나므로 기하 판정을 그대로 두면 퍼펙트가 공짜가 된다. §3의 "너무 빨라 못 자르면 큰 감점" 규칙을 낙하 전 전체에 적용.
3. **CPU 발동 = 반 프레임 예측** `d − vy·dt/2 ≤ off`. "첫 프레임에 d ≤ off" 그대로면 오차가 항상 늦는 쪽(0~v·dt, 60fps에서 평균 −5px, 저사양에서 −15px)으로 치우쳐 Hard가 스펙 기대치(≈13/라운드)에 못 미친다. 예측식은 편향 0.
4. **CPU 배정**: 사람 바로 다음 슬롯 1명만 Hard, 나머지 Normal(1인 플레이 = Hard 1 + Normal 2 ≈ 65 / 45 / 45점). Very Hard(≈85점)는 초보가 이기기 어려워 미사용. 사람/CPU 여부는 `init()` 스냅샷이 아니라 매 프레임 `g.isHuman(i)`로 읽는다(셸이 타이틀에서 숫자키와 SPACE를 같은 프레임에 받으면 `start()`가 먼저 돌아 스냅샷이 어긋남).
5. **연출 소소한 차이**: 플라밍고는 통나무를 바라보게 `flip:true`(부리가 칼날). 위 조각은 오른쪽으로 튀어 착지 후 0.5s에 사라짐(판정 단계의 "조각 정리"). 샤미센 비프 볼륨 0.15/0.15/0.2(스펙 0.4/0.5는 다른 효과음 대비 과함). "준비…→시작!"은 셸 카운트다운·GO! 위에 1.2s 대기로 대체. 종료 `sfx.win`은 셸이 재생하므로 생략. 라운드 표시는 통나무·거미와 겹치지 않는 왼쪽 상단 빈 띠에 배치.

6. **검수(2차, 2026-09-10)**: 흰 선 가시성 버그 수정 — `drawPiece`가 선 위치를 조각 중심 기준으로 계산하고는 상단 기준 범위(4~h−2)로 검사해 **조각 위쪽 절반의 선이 안 그려졌다**(R1에서도 절반가량의 통나무가 선 없음, CPU는 `frac`을 직접 읽어 영향 없음 → 사람만 불리). 그 외 낙하 중 안내 문구 `베라!`→`베어라!`, 타이틀 오버레이 문구와 겹치는 발밑 점수 줄은 타이틀 상태에서만 숨김. CPU 모델 시뮬(60fps·30fps 동일): Normal 평균 43점(p10 21·p90 65), Hard 평균 66점(p10 46·p90 88) — §8 기대치와 일치.
