## 1. 한 줄 요약 · 등장 요소와 플라밍고 대체안

**한 줄 요약**: 잉어킹 4마리가 나란히 서서 A 버튼을 "눌렀다 떼며" 튀어 올라(Splash) 머리 위에 매달린 **스위치**를 치고, 제한 시간 안에 위의 **카운터(counter)** 숫자를 가장 많이 올린 쪽이 이긴다. [확인 — Bulbapedia/StrategyWiki/Serebii]

| 원작 요소 | 역할 | 플라밍고 대체안 (셸 포즈) |
|---|---|---|
| 잉어킹(Magikarp) ×4 | 플레이어 캐릭터. 땅 위에서 퍼덕이다 튀어 오름 | 플라밍고. 대기 `idle`, 홀드(힘 모으기) `harden`(움츠림·부들부들), 상승 `jump`, 정점~하강 `fly`(날개 펼침), 착지 순간 `hit` 1프레임 후 `idle`, 스위치에 맞은 직후 `dizzy` 0.2초 |
| 스위치(switch) — 카운터 밑에 매달린 둥근 버튼/추 | 잉어킹 머리가 닿으면 위로 눌리며 카운터 +1 | 매달린 **종(bell)** 또는 빨간 원형 버튼. 맞으면 위로 8~10px 튀고 좌우로 흔들림 |
| 카운터(counter) — 스위치 위의 2자리 기계식 숫자판 | 각 플레이어 점수(HUD 겸용) | 그대로. 2자리 플립 카운터, 플레이어 색 테두리 |
| 지면(모래/잔디) + 물튀김 이펙트 | 착지 시 작은 먼지/물방울 | 착지 시 물방울 파티클 6~10개 + 파문 1개 |
| 타이머 | 상단 중앙 | 그대로(초 단위) |

(잉어킹 이외의 포켓몬·소품은 등장하지 않는다. [확인])

## 2. 인원 · 시간 · 라운드

- **4인 동시 플레이** [확인 — "All mini-games are played with four players", 인간 1~4 + 나머지 COM]. 4레인 고정, 슬롯 순서 왼쪽부터 1P→4P.
- **제한 시간: 20초** [확인 — KoopaTV 미니게임 티어 리스트: "Twenty seconds (though the timer is invisible)"]. ~~30초 추정~~은 비평가 검증에서 수정됨. 교차 검증: 풀 플레이 영상 39초 = 인트로·Ready-Go 약 8초 + 플레이 20초 + 결과 약 10초로 딱 맞고, NTSC 세계기록 32점(RecordSetter, 2011)은 20초 ÷ 32 ≈ 0.63초/사이클로 "착지 즉시 재점프" 리듬과 일치한다. **원작은 타이머가 화면에 보이지 않는다**(플레이어가 남은 시간을 모름). 우리 셸은 `duration>0`이면 상단에 초를 자동 표시하므로 그대로 두되, 게임 쪽에서 별도 큰 타이머를 그리지 않는다.
- 단일 라운드. 시간 종료 = 게임 종료. 연장·서든데스 없음.
- 셸 설정: `duration: 20`.

## 3. 조작

| N64 | 원작 동작 | 우리 액션 |
|---|---|---|
| **A** (누름) | Splash 준비: 누르고 있는 동안 힘을 모음(잉어킹이 몸을 움츠리며 부들거림) | `a` 홀드 |
| **A** (뗌) | 튀어 오름. **홀드 시간에 비례해 높이 상승.** 짧게 탭하면 "스위치까지 절반"밖에 못 감 [확인 — GameFAQs/Serebii 인용] | `a` 릴리즈 |
| **A** (착지 순간 누름) | 즉시 재점프, "시간 낭비 없음" [확인 — "press the A Button the moment your Magikarp lands"] | 착지 전 0.12초 이내 입력은 버퍼링 |
| B, 스틱, C, Z, R | 없음 [확인 — "A to Splash/Jump"만 명시] | 미사용. `b`는 `a`와 동일 취급해도 무방(권장: 무시) |

**입력 규칙 (수치는 추정, 원작 영상 리듬에 맞춤)**
- 홀드 시간 `h` → 점프 초속도 `v0 = lerp(700, 1600, clamp(h/0.20, 0, 1))` px/s, **G = 5000 px/s²** (최대 높이 = v0²/2G = 256px → 지면 430에서 스위치 하단 190까지 240px를 16px 뚫음). 즉 **0.20초 이상 홀드 = 최대 높이** (원작 팁 "hold for a split second"). 최대 홀드 이후는 더 눌러도 높이 증가 없음 — 대신 시간만 낭비되므로 자연스러운 페널티. (2차 비평가 수정: 1차가 적은 G=2600·v0 1150은 실제로 계산하면 상승 0.34초+낙하 0.36초로 사이클이 1.0초가 되어 20초에 19~20점밖에 안 나온다. G=5000·v0 1600이면 상승 0.24초 + 타격 반동 낙하 0.23초 = 공중 0.47초, 홀드 0.18초 → **사이클 0.65초 → 20초에 30~31점**으로 세계기록 32점과 정합.)
- 탭(≤0.05초) → v0 ≤ 925, 높이 ≤ 86px ≈ 스위치까지 거리의 36% ("halfway" 이하). 절반 높이(120px)는 v0≈1095, h≈0.07초. 스위치에 닿는 최소 v0 ≈ 1550 → **최소 홀드 ≈ 0.18초** — 즉 거의 최대 홀드가 필요해 "확실히 꾹" 눌러야 한다. 0.18~0.20초 사이가 "정확히 닿는" 창이고 그 이상은 시간 손실만.
- 공중에서는 입력 무효(연타로 추가 상승 없음). **원작은 연타 게임이 아니라 타이밍·홀드 게임**이다. 기존 구현의 "SPACE 연타로 게이지" 방식은 원작과 다르므로 교체 대상.
- 홀드 중 캐릭터는 이동 불가. 좌우 이동 없음(레인 고정).
- ~~착지 후 경직 0.1초~~ → 2차 비평가 폐기(§4 참조). 착지 시점에 `down('a')`이면 착지 프레임부터 바로 홀드가 시작된다. **단 공중에서 "새로" 누른 입력(공중에서 hit→down 유지)만 인정하고, 이전 점프의 릴리즈 없이 계속 누르고 있던 상태는 인정하지 않는다** — 즉 릴리즈로 뛴 뒤 다시 눌러야 한다. 이것이 원작의 "착지 순간 A" 리듬이다. 릴리즈 판정은 `prevDown && !down('a')` 로 자체 추적한다(셸에 release API 없음).

## 4. 규칙과 점수

- **점수 단위: 스위치 1회 타격 = 1점.** [확인 — "earning a point each time"] 감점·페널티 없음. 헛점프는 시간 손실만.
- 타격 판정: 상승 중(vy<0) 머리 상단이 스위치 하단에 닿으면 1점. 같은 점프에서 중복 판정 없음(점프당 `hitDone` 플래그; 스위치가 위로 눌려 있는 0.25초 동안 재판정 없음). 스위치에 맞으면 캐릭터가 **곧바로 아래로 튕긴다: `vy = +450`(px/s, 아래 방향 고정값)** → 낙하 0.23초. (2차 비평가 수정: 1차의 `-vy*0.25+120`은 낙하가 0.36초로 늘어져 리듬이 무너진다.) 낙하 착지 속도 ≈ 1600 px/s이므로 `y`는 매 프레임 `min(y, 0)`로 클램프해 관통을 막는다.
- **승리: 시간 종료 시 카운터 최다.** [확인] 1위~4위 순위 표시.
- **동점: 불명 — 추정: 공동 순위(둘 다 1위)로 처리.** 원작 Kids Club 순위판은 같은 점수를 같은 순위로 표기하므로 셸에 동일 점수를 그대로 넘긴다.
- **원작 점수 예시**: NTSC 세계기록 **32점**(RecordSetter, Kenny McKee 2011; 2023년 유튜브 재현 영상 있음), PAL 최고 26점(Cyberscore 10명 동률 = PAL 상한), 22~25점이 상급, 처음 하는 사람은 8~14점 정도. [RecordSetter/Cyberscore 확인 / 초보 수치는 추정]
- 이론 최대 계산(2차 비평가 재산정, 위 상수 기준): 최적 사이클 = 홀드 0.18초 + 상승 0.24초 + 반동 낙하 0.23초 ≈ 0.65초 → 20초에 30~31회(첫 점프는 홀드부터 시작하므로 31). **구현 후 검증 기준: 완벽 플레이(착지 프레임에 이미 A 홀드, 0.18~0.20초 홀드) 30~31점, 착지마다 0.1초 늦으면 26점, 0.2초 늦으면 23점, 홀드가 들쭉날쭉한 초보 8~14점.** 셸 `duration:20`. 착지 경직은 두지 않는다(입력 버퍼가 있으면 경직은 리듬을 깨기만 함) — §3의 "착지 후 경직 0.1초"는 **폐기**, 착지 프레임에 `down('a')`면 그 프레임부터 홀드 시작.

## 5. 난이도 곡선 · CPU 난이도

- 시간에 따른 룰 변화 **없음** [확인 — 어떤 출처도 가속을 언급하지 않음]. 스위치 높이·중력·타이머 속도 모두 고정. 난이도는 오직 상대 CPU의 숙련도.
- 원작 Kids Club 난이도: Easy / Normal / Hard + 숨김 **Hyper**(Hard로 3 COM 상대 5연승 시 해금) [확인 — Bulbapedia/Serebii]. Very Hard는 Stadium 2 용어이나 요청대로 5단계로 정의한다.

| 난이도 | CPU 예상 점수(20초) | 행동 |
|---|---|---|
| Easy | 8~12 | 홀드가 들쭉날쭉(탭으로 헛점프 잦음), 착지 후 한참 쉼 |
| Normal | 14~18 | 대체로 닿을 만큼 홀드, 착지 후 0.25초쯤 쉬고 재점프 |
| Hard | 20~24 | 거의 매번 성공, 착지 후 짧게 쉼 |
| Very Hard | 25~27 | 실수 드묾, 거의 즉시 재점프 (Stadium 1엔 없는 단계 — Hard/Hyper 보간) |
| Hyper | 29~31 | 인간 최적 플레이와 동일(2차 비평가: KoopaTV 글에서 이 미니게임에 한정한 Hyper 언급은 재확인되지 않음 — Kids Club 전반의 인상으로 격하) |

(점수 열은 20초 기준으로 비평가가 재산정. 표 8의 파라미터와 함께 읽을 것.)

우리 게임은 셸에 난이도 선택이 없으므로 3 CPU에 **Normal / Hard / Very Hard 를 각각 배정**하고(2P=Normal, 3P=Hard, 4P=Very Hard), 시작 시 ±1단계 랜덤 셔플을 권장. Hyper는 사용하지 않는다.

## 6. 화면 구성

- **카메라: 정면 고정(횡 배치, 스크롤 없음).** 4레인이 화면 가로를 균등 분할. [영상 기준]
- 배치(960×540 기준): 레인 중심 x = 150, 370, 590, 810. 지면 y ≈ 430. 스위치 하단 y ≈ 190, 카운터 박스 y ≈ 90~150(레인 위쪽에 매달림). 최대 점프 시 머리 상단이 스위치를 20~30px 뚫고 올라가는 정도.
- **HUD**: 각 레인 상단의 **2자리 카운터가 곧 점수판**(1P 색 테두리 + `drawPlayerTag`). ~~타이머는 화면 상단 중앙 큰 숫자, 마지막 5초 빨강~~ → 비평가 수정: 원작은 타이머 비표시. 셸 HUD의 작은 초 표시만 남기고 게임은 타이머를 그리지 않는다. 셸 요구대로 4명의 점수가 항상 노출된다.
- 배경: 원작은 야외(모래/잔디 색 지면, 밝은 하늘) — **불명 — 추정: 옅은 하늘색 그라데이션 + 모래빛 지면 띠 + 뒤쪽 얕은 물가**. 색감은 밝고 채도 높은 파스텔(N64 특유의 원색). 플라밍고 버전은 `bg` 헬퍼의 해변 톤 사용.
- 카운터·스위치는 나무 기둥/받침에 매달린 형태(놀이공원 힘측정기 느낌).

## 7. 연출

- **시작**: 화면에 4마리가 퍼덕이며 대기 → 아나운서 "Ready…" → "Go!"(원작 Kids Club 공통, 한국어 "준비… 시작!") 후 타이머 가동. 시작 전 입력은 무시. 셸 카운트다운(`sfx.count`→`sfx.go`)을 그대로 사용.
- **홀드 중**: 캐릭터 `harden` 포즈로 살짝 낮아지며 좌우 1~2px 떨림, 발밑 먼지.
- **점프**: 상승 시 `jump`, 정점 이후 `fly`. 착지 시 물방울 파티클 + 파문 + `sfx.pop`(작게).
- **성공(스위치 타격)**: 스위치가 위로 튀고 카운터가 "딸깍" 넘어감(`sfx.good`, 숫자 플립 0.15초), 카운터 박스가 0.2초 노랗게 점멸, `+1` 텍스트 상승. 캐릭터는 `dizzy` 0.2초 후 낙하.
- **실패(못 닿음)**: 별도 연출 없음(원작도 없음). 정점에서 그냥 떨어진다. 선택적으로 아주 작은 "…" 말풍선.
- **종료**: 타이머 0 → "끝!"(원작 "Finish!"/"Time's up!" — 정확 대사는 불명) 표시 0.8초, 모든 입력 차단, 카운터 최종값 강조. 1위 캐릭터 `jump` 반복, 나머지 `sleep` 또는 `idle`. 이후 셸 결과 화면으로.
- **아나운서 요지**(원작은 실황 해설이 있음 [확인]; 정확 문구는 불명): 경기 중 "1P가 앞서 나갑니다!", "대단한 연속 스플래시!", 종료 "승자는 ○P!". 우리 버전은 텍스트 자막 1~2줄로 대체 가능.

## 8. AI 행동 모델 제안

CPU는 인간과 같은 물리로 움직이며, 다음 세 파라미터만 다르다.

| 난이도 | 착지→홀드 시작 지연 (ms) | 홀드 시간 목표(ms) ± 오차(σ) | 실수 확률(탭·과소홀드로 헛점프) | 예상 점수 |
|---|---|---|---|---|
| Easy | 450 ± 200 | 170 ± 60 | 30% | 8~12 |
| Normal | 250 ± 120 | 200 ± 35 | 15% | 14~18 |
| Hard | 110 ± 60 | 210 ± 20 | 6% | 20~24 |
| Very Hard | 50 ± 30 | 215 ± 12 | 2% | 25~27 |
| Hyper | 0~15 | 210 ± 5 | 0% | 29~31 |

(2차 비평가 재산정: §3 상수(최대 홀드 0.20초, 스위치 도달 하한 0.18초) 기준. 홀드가 0.18초 아래로 떨어지면 헛점프, 0.20초 위는 시간 손실만. 검산: Hard = 0.11 + 0.21 + 0.47 = 0.79초/회 → 25회 × 94% ≈ 23점, Normal ≈ 0.92초/회 → 21회 × ~70%(실수 15% + σ 미달) ≈ 15점, Very Hard ≈ 0.735초/회 → 27 × 98% ≈ 26점, Hyper 0.69초 → 29점.)

- 지연·홀드는 정규분포 샘플, 매 점프마다 새로 뽑는다. 실수 발생 시 홀드를 40~150ms로 강제(절반 이하 높이).
- 인간보다 잘하지 않도록 **Hyper 이외에는 최소 지연 40ms 보장**.
- 후반(남은 시간 <10초) Easy/Normal은 실수 확률 +5%p(지친 연출, 선택).

## 비평가 보강

독립 재검증 출처: Bulbapedia `Magikarp's_Splash`·`Pokémon_Stadium_series_mini-games`, Serebii Kids' Club, StrategyWiki(검색 스니펫), GameFAQs JosiahIsBack·HGamer 가이드(스니펫), archive.org **닌텐도 공식 플레이어스 가이드** 전문, KoopaTV 미니게임 티어 리스트(2023), CBR·DualShockers 리뷰, RecordSetter 세계기록, Cyberscore PAL 차트, gamemasterplc NTSC-U 치트 코드 목록.

### 수정한 것(잘못됐던 항목)
1. **제한 시간 30초 → 20초** [확인 — KoopaTV "Twenty seconds (though the timer is invisible)"]. 39초 영상 구성, NTSC 기록 32점/20초 ≈ 0.63초 사이클 모두 20초와 정합. §2·§4·§9·셸 `duration` 전부 20으로 고침.
2. **이론 최대 26점 → NTSC 기록 32점**. PAL 26점은 PAL판(50Hz) 상한일 뿐이다. 물리 튜닝 목표를 "완벽 플레이 30~32점"으로 교체.
3. **사이클 1.15초 → 0.63~0.75초**. 원작은 훨씬 빠른 "통통" 리듬이다(공중 체류 약 0.45초). 중력 1500 → 2600, v0 범위 560~1150, 최대 홀드 0.35 → 0.25초, 표 8의 CPU 지연·홀드 값 재산정.
4. CPU 예상 점수표를 20초 기준으로 재산정(Easy 8~12 … Hyper 29~31).
5. Very Hard 행은 Stadium 1에 없는 단계(공식 가이드도 "Easy, Normal and Hard" 3단계 + 숨김 Hyper)임을 명시. 5단계 요구 때문에 유지하되 "Hard와 Hyper 사이 보간"으로 정의.
6. §6의 "상단 중앙 큰 타이머 + 마지막 5초 빨강" 폐기(원작은 타이머 비표시).

### 추가한 것(빠져 있던 항목)
7. **원작 게임 내 설명문 원문** [확인 — KoopaTV 인용]: "Press and hold the A Button to make MAGIKARP SPLASH high. Press the A Button just as MAGIKARP lands for quick SPLASHes." → 우리 howto의 정본. 공식 가이드 원문: "Timing is everything in Magikarp's Splash… hit the A Button again right as Magikarp lands on the ground to send it back up to the counter quickly."
8. **타이머 비표시** [확인]: 원작은 남은 시간을 화면에 보여주지 않는다. 셸 HUD는 어쩔 수 없이 표시되지만 게임 캔버스에는 큰 타이머·경고 연출을 넣지 않고, 종료 직전 신호 없이 뚝 끊기는 원작 느낌을 유지한다.
9. **소리가 게임의 절반** [확인 — DualShockers·CBR·KoopaTV 공통]: 점프할 때마다 잉어킹이 "카프!" 하고 울고, 4마리가 겹쳐 "cacophony"가 된다. 배경음은 초조한 빠른 템포. 플라밍고 버전: **모든 점프(성공·실패 무관, CPU 포함)** 에 `sfx.beep`로 짧은 "꽥"(플레이어별 주파수 다르게, 예 1P 660Hz/2P 590/3P 720/4P 540, 60ms, 'square', 0.08)을 넣고, 스위치 타격에만 `sfx.good`. 이걸 빼면 원작 느낌이 안 난다.
10. **동점 규칙** [확인 — KoopaTV/Bulbapedia]: Kids Club "Who's the Best?"에서 동점자는 모두 승리 처리된다(예외는 Rock Harden뿐). §4의 "공동 순위" 추정을 확정으로 승격. 셸 `result().scores`에 동일 점수를 그대로 넘긴다. 서든데스·연장 없음.
11. **시작·종료 흐름 상세**: Kids Club 공통 연출 — 미니게임 제목 카드 → 4마리 대기 퍼덕임 → 아나운서 "Ready… Go!" → 20초 → 시간 종료 시 즉시 입력 차단, 공중에 있던 캐릭터는 그대로 낙하(종료 후 타격은 카운트 안 됨) → 결과 화면에서 1위가 승리 모션, 나머지는 축 처짐. 정확 대사는 여전히 불명이므로 한국어 "준비… 시작!" / "끝!"으로 대체.
12. **버튼 정리** [확인 — Bulbapedia "A to Splash/Jump" 단일 조작]: B·C·Z·R·스틱 전부 무효. `b`는 완전히 무시(A와 동일 취급하지 않음). 홀드 중 A를 떼지 않으면 절대 뛰지 않는다(뗌 = 점프 트리거). 카운트다운 중 미리 홀드해 두었다가 "시작!"과 동시에 떼는 선입력은 허용하지 않는다(시작 시점에 `down('a')`면 한 번 뗐다 다시 눌러야 홀드 시작).
13. **홀드 상한 후 자동 점프 없음**: 최대 높이에 도달해도 떼기 전까지 계속 웅크린다(시간 낭비가 곧 페널티). 홀드 중 `harden` 포즈에 1~2px 떨림.
14. **레이아웃 보강**: 4마리가 같은 지면선에 나란히(카메라 고정, 스크롤 없음), 각 레인 위에 자기 카운터+스위치. 카운터 숫자는 2자리(00~99), 0으로 시작. 카운터 색=플레이어 색, `drawPlayerTag`를 카운터 위에 붙인다. 물튀김은 착지 시에만.
15. **특수 아이템·장애물·방해 요소 없음** [확인 — 어떤 출처도 언급하지 않음]. 다른 플레이어와 상호작용(충돌·방해) 없음. 순수 개인 타이밍 경쟁.
16. **난이도 상승 없음** [확인]: 20초 내 속도·높이·중력·스위치 위치 변화 없음. 유일한 압박은 "타이머가 안 보이는" 긴장과 음악.
17. **CPU 파라미터의 원작 근거**: 공식 가이드는 CPU 행동을 서술하지 않으므로 표 8은 모델링. 단 Hyper "이기는 게 가끔 불가능"(KoopaTV)·Hard 5연승으로 Hyper 해금(Serebii/Bulbapedia)은 확인. 셸엔 난이도 선택이 없으므로 2P Normal·3P Hard·4P Very Hard 고정 배정을 유지하되, **1P가 인간 완벽 플레이(30점대)로 4P를 근소하게 이길 수 있어야 한다.**
18. **감각(feel) 체크리스트**: (a) 최적 리듬은 약 0.65초마다 "꾹-딱"; (b) 탭은 눈에 띄게 낮게(절반 이하), "실패했다"가 즉시 읽혀야 함; (c) 스위치 타격 시 캐릭터가 뚝 꺾여 떨어지고 스위치가 위로 눌리며 카운터가 딸깍 넘어감; (d) 착지 프레임에 이미 A가 눌려 있으면 경직 없이 바로 웅크림(입력 버퍼 0.12초); (e) 4마리 울음이 겹치는 소음.
19. **기존 games/splash.html과의 차이(교체 지점)**: 연타 게이지·공중 연타 상승·`rate` 기반 CPU·`duration:30`·"SPACE 연타" 안내 문구 전부 원작과 다름. 홀드-릴리즈 물리, 20초, 표 8 CPU, 액션 이름 표기(`A 버튼`)로 재작성한다.

## 비평가 보강 (2차 독립 검증)

2차 비평가가 직접 다시 연 출처: Bulbapedia `Magikarp's_Splash`·`Pokémon_Stadium_series_mini-games`, Serebii Kids' Club, KoopaTV 티어 리스트, RecordSetter, DualShockers, CBR (StrategyWiki·GameFAQs·Cyberscore는 403/파싱 실패, 검색 예산 소진으로 스니펫 재확인 불가). 1차 보강의 핵심 주장은 모두 재확인됨: 20초·타이머 비표시·게임 내 설명문 원문(KoopaTV), 조작 A 단일·4인·Easy/Normal/Hard/Hyper(Bulbapedia), 홀드=높이·착지 탭=즉시 재점프·Hard 3COM 5연승 해금(Serebii), NTSC 기록 32점·NTSC 한정 규정(RecordSetter), 홀드-릴리즈 조작·잉어킹 울음 소음(CBR·DualShockers).

### 수정한 것
1. **물리 상수 오류 정정(가장 중요)**: 1차가 적은 G=2600·v0max 1150·반동 `-vy*0.25+120`을 실제로 풀면 상승 0.34초 + 낙하 0.36초 + 홀드 0.22초 + 경직 0.1초 = **1.0초/사이클 → 20초에 19~20점**으로, 스스로 세운 "완벽 30~32점" 목표를 못 채운다. §3·§4를 **G=5000, v0=lerp(700,1600,h/0.20), 타격 반동 vy=+450, 경직 0** 으로 고쳐 사이클 0.65초·30~31점이 되게 했다. 검산은 §4에 적음.
2. **홀드 창 재정의**: 스위치 도달 최소 홀드 0.18초, 최대 0.20초. 탭(≤0.05초)은 36% 높이. §8 CPU 홀드 목표/σ를 이에 맞춰 전부 재산정(검산 포함).
3. **착지 경직 폐기**: 입력 버퍼 + 경직은 서로 충돌해 리듬을 흐린다. 착지 프레임에 A가 눌려 있으면 즉시 홀드. 대신 "공중에서 새로 누른 입력만 인정"(이전 점프의 홀드 상태를 그대로 유지한 것은 무효)으로 원작의 "착지 순간 다시 누르기"를 강제.
4. Hyper "이기는 게 가끔 불가능" 인용은 이 미니게임 한정 문장으로 재확인되지 않아 Kids Club 전반 인상으로 격하. Cyberscore 신뢰도 하향.
5. DualShockers는 "A를 반복해서 누른다"고 쓰지만 CBR·KoopaTV·Serebii·공식 가이드 4곳이 "홀드-릴리즈 + 착지 탭"으로 일치하므로 **연타 해석은 채택하지 않는다**(리뷰의 느슨한 표현).
6. Kids Club 대전 모드 이름: Serebii "Who's the Best?", Bulbapedia "Who's The Champion?"로 출처가 갈림. 게임 규칙에 영향 없음 — 화면에 쓰지 않는다.

### 추가한 것(구현 계약 관점에서 빠져 있던 것)
7. **셸 계약 위반 목록(기존 games/splash.html)**: `input.hit('Space')` 직접 키코드 사용(금지), `result()`가 `{score,win}` 반환(계약은 `{scores:[4], text}`), 인간 1명 고정(`g.slots()`·`g.isHuman(i)` 미사용), 안내 문구 "SPACE 연타"(액션 이름 `A 버튼` 사용해야 함), 상단 `<span>조작: SPACE 연타</span>`. 재작성 시 전부 교체.
8. **인간 2~4명일 때 CPU 배정**: 난이도는 **슬롯 번호에 고정**(2P=Normal, 3P=Hard, 4P=Very Hard, ±1단계 셔플). 인간이 3명이면 4P만 CPU(Very Hard). 인간끼리는 물리 동일. `g.slots()`를 돌며 `human`이면 `g.p(i).down('a')`, 아니면 §8 모델.
9. **result() 정의**: `{ scores: lanes.map(l=>l.count), text: '1P 12 · 2P 9 · …' 또는 '승자 ○P — 종 N번' }`. 동점은 동일 점수 그대로 넘겨 셸이 공동 순위 처리(원작 동점=모두 승리와 일치). `lowerIsBetter` 없음.
10. **종료 순간 처리**: 셸이 `duration:20` 경과로 끝내면 그 프레임 이후 `update`는 오지 않으므로 별도 차단 로직 불필요. 단 마지막 `update`에서 `g.timeLeft<=0`이면 타격을 카운트하지 않는다(종료 후 타격 무효 규칙). 공중의 캐릭터는 결과 화면 전 마지막 `draw`에서 그 자리에 그대로 둔다.
11. **HUD 고정 배치**: 카운터 박스 `L.x-44, 20, 88×56`, 그 위에 `drawPlayerTag(ctx, L.x, 12, i)`. 셸 상단 타이머와 겹치지 않도록 화면 상단 중앙(x 400~560, y<40)은 비운다. 카운터는 항상 4개 노출(계약 요구), 1위에는 왕관 대신 테두리 `palette.gold` 2px(원작엔 순위 강조가 없으므로 최소화).
12. **포즈 매핑 확정**: 대기 `idle`, 홀드 `harden`(y+4px 내려앉음·x ±1px 떨림), 상승 `jump`, 정점 이후 `fly`, 타격 직후 0.2초 `dizzy`, 착지 프레임 `hit` 1프레임. 스케일 1.3, 머리 상단 = `GROUND + y - 45`(기존 값 유지). 스위치 하단 y=190 → 타격 조건 `vy<0 && GROUND+y-45 <= 190`.
13. **효과음 확정**: 릴리즈(점프) 시 플레이어별 `sfx.beep(660/590/720/540, 0.06, 'square', 0.08)`(CPU 포함, 이게 원작 "카프!" 소음), 타격 `sfx.good`, 착지 `sfx.pop`(작게, 인간만). 홀드 시작엔 소리 없음. 종료 시 셸이 `win/lose`를 낸다.
14. **시작 선입력 처리 구체화**: 첫 `update`에서 `down('a')`가 이미 true면 `armed=false`로 두고, 한 번 떼어진 뒤(`!down`)에만 `armed=true`. 홀드 시작 조건은 `armed && hit('a')`.
15. **CPU 첫 점프**: 시작 후 난이도별 지연(§8 지연값 ×1.5)을 두고 첫 홀드 시작 — 4마리가 동시에 뛰지 않게 하는 원작의 어긋난 리듬.
16. **파일 예산**: 물리·CPU·연출을 합쳐 300줄 이내 가능(기존 116줄 구조 유지, 연타 게이지/`hitTimes`/`rate` 로직 삭제, 홀드 상태기계 추가).

## 구현 메모 (games/splash.html v2, 2026-09-10)

- **좌표**: 본문 §6의 "지면 430 / 스위치 하단 190"은 머리 상단 기준 195px밖에 안 돼 §3·§4의 240px 물리(최소 홀드 0.18초)와 맞지 않는다. 구현은 240px을 우선해 `GROUND=460`, 종 하단 `SW_Y=158`, 머리 상단 `GROUND+y-62`(스케일 1.3 실측)로 두었다. 카운터 박스는 §11대로 상단(`x-44, 26, 88×52`), 태그 `y=14`, 들보 `y=100`.
- **물리**: §3·§4 그대로(`v0=lerp(700,1600,h/0.20)`, `G=5000`, 반동 `+450`). 적분은 등가속 정확식(`y += vy·dt + ½G·dt²`)이라 정점 높이가 프레임레이트에 흔들리지 않는다. 최소 도달 홀드 ≈ 0.19초. 오프라인 시뮬(60fps): 완벽 플레이 28점, 착지마다 0.1초 지연 24점, 0.2초 22점 — §4 목표(31/26/23)보다 2~3점 낮은데 프레임 양자화 때문이며 기울기는 같다.
- **CPU 표 조정**: 표 8 그대로 두면 쉬움 중앙값 5점, 보통 12점으로 예상 구간에 못 미친다(홀드 σ가 0.19초 문턱에 많이 걸림). 쉬움 `지연 380±180ms · 홀드 210±40 · 실수 28%`, 보통 `250±120 · 215±25 · 12%`로 바꿔 중앙값 10 / 16을 맞췄고 어려움(21)·매우 어려움(25)은 표 8 그대로. 완벽 인간 28 > 매우 어려움 최대 26 — §17 조건 충족. **배정(v2.1)**: 2P 보통 · 3P 보통/어려움(반반) · 4P 어려움. 키보드로 괜찮게 치는 사람(반응 150ms·홀드 0.22초)이 시뮬 중앙값 20점이라 매우 어려움(25점)은 1인 플레이에서 사실상 못 이겨 제외했고, 어려움(21점)이 "어렵지만 이길 수 있는" 상대다. 쉬움·매우 어려움·하이퍼 미사용.
- **포즈(v2.1)**: 홀드는 §12대로 `harden`. 다리가 접히는 포즈라 `fy+20`으로 내려 몸이 땅에 붙은 웅크림이 되고, x ±1.2px(충전 완료 ±2.5px) 떨림 + 발밑 먼지. 몸이 회색이 되지만 0.2초뿐이고 레인·태그·카운터 색으로 누구인지 읽힌다(v2는 `dig`였음). 홀드 0.19초 이상이면 머리 위에 금색 스파크(지금 떼면 닿는다는 신호).
- **입력 버퍼**: "착지 전 0.12초" 창 대신 "공중에서 새로 누른 A를 착지까지 유지"하면 착지 프레임부터 홀드(창 제한 없음). 창을 두면 조금 일찍 누른 플레이어가 "누르고 있는데 왜 안 웅크리지"가 되어 더 헷갈린다. 착지 전에 뗀 공중 탭은 무효.
- **연출**: 못 닿은 점프는 §7의 선택 항목대로 정점에서 작은 "…"(잉크색, 0.6초 상승)만. 종료 시 "끝!" 대신 셸 결과 화면이 바로 덮이므로, 결과 화면 뒤에서 1위(공동 포함)는 `jump`로 튀고 나머지는 `sleep`. 아나운서 자막은 하단 필(단독 선두 교체 시 "○P가 앞서 나갑니다!", 연속 5회 타격마다 "대단한 연속 스플래시!"). 3P 카운터가 금색이라 점멸은 흰색, 선두 테두리는 잉크색으로 예외 처리.
