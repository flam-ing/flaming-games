# dynamo — 번개 발전기 (원작: Thundering Dynamo, Pokémon Stadium 1 / N64 Kids Club)

> 신뢰도 표기: [확정] = 복수 출처 일치, [추정] = 출처 침묵 → 원작 영상·장르 관행 기반 추정치. 구현자는 [추정] 수치를 튜닝 가능 상수로 두고, 리뷰어는 유튜브 영상(§10)과 비교한다.

## 1. 한 줄 요약 · 등장 캐릭터 · 플라밍고 대체안

**한 줄 요약** [확정]: 발전기(dynamo) 위 램프가 **파랑이면 A 연타, 초록이면 B 연타**로 전기를 충전한다. 틀린 버튼을 누르면 모아둔 전기가 빠져나가고(drain), **자기 발밑의 충전 게이지를 가장 먼저 100% 채운 플레이어가 승리**. 진 쪽은 감전된다.

원작 인게임 설명문(KoopaTV 인용) [확정]:
> "When the lamp is blue, tap the A Button repeatedly to charge electricity. Tap the B Button when it's green. Pressing the wrong button drains your stored electricity. The first one to be fully charged wins."

**등장 포켓몬** [확정]: 피카츄(Pikachu) 또는 찌리리공(Voltorb). 플레이어마다 시작 시 **무작위 50/50** 배정(캐릭터 차이는 외형뿐, 성능 동일). 4명 모두 같은 종이 될 수도 있다(영상: 찌리리공 3 + 피카츄 1 조합 목격).

**플라밍고 대체안** (셸 포즈: idle jump run sleep dig eat dizzy harden fly ball hit):

| 원작 요소 | 플라밍고 대체 | 포즈/표현 |
|---|---|---|
| 피카츄(꼬리에 전기 모음) | 기본 플라밍고 | 대기 `idle` / 연타 중 `run` 프레임을 제자리에서 빠르게(발 구르기, 램프색 스파크를 부리 끝에) / 게이지 25·50·75% 마다 `jump` 1회 |
| 찌리리공(몸을 회전하며 충전) | "공 플라밍고" | 연타 중 `ball` 포즈로 회전(rot += 연타 속도 × 12 rad/s), 정지 시 `idle` |
| 틀린 버튼 → 방전 | 흔들림 | `dizzy` 0.4초 + 몸에서 회색 스파크가 아래로 빠지는 파티클 |
| 승자: 발전기로 번개 쏘고 포즈 | 승리 | `fly`(위로 살짝 떠오름) 후 `jump` 반복, 머리 위에 노란 번개 |
| 패자: 발전기 꼭대기 전구에서 내리꽂히는 번개에 감전 | 감전 | `hit` ≈2초(검은 실루엣으로 부들부들, 흰빛 배경) → `dizzy` ≈1.5초 |
| 발전기(은색 캡슐 + 계기판 + 큰 원형 램프, 위에 코일·전구) | 그대로 "발전기" 소품 | 화면 중앙, 램프 색 = 파랑 `#3A7BFF` / 초록 `#3FD35A` / 소등 `#101010` |

플레이어별 종 배정은 원작처럼 시작 시 랜덤(50/50)으로 "기본형 / 공 포즈형"을 나누되, 규칙 차이는 없다.

## 2. 인원 · 시간 · 종료 조건

- **4인 동시 플레이** [확정]. 사람 1~4명, 나머지 CPU. 셸 규칙대로 항상 4슬롯 생성.
- **제한 시간 없음, 선착 종료(race)** [확정]: 누군가 게이지 100% 도달 → 즉시 종료. `duration: 0`으로 두고 `g.finish()` 직접 호출.
- **한 판 길이** [확정: 영상 프레임 계측]: 램프 점등→승자 만충까지 **7.4초 / 8.2초 / 7.4초(Hyper)** (§11 참고). 목표: Normal에서 사람이 성실히 연타하면 **7~9초**에 결승. (기존 "8~15초·10±3초"는 너무 길어 원작보다 늘어진 느낌이 되므로 폐기.)
- **안전장치** [추정]: 아무도 30초 안에 못 채우면 게이지 최대인 플레이어 승(원작엔 없지만 방치 방지). CPU가 항상 연타하므로 실제로는 발동되지 않는다.
- **라운드 구조**: 단판. 원작 "Who's the Champion?" 토너먼트는 셸 밖 문제이므로 미구현.
- 동점(같은 프레임 100% 도달) 처리는 §4.

## 3. 조작

원작 N64 [확정]:

| N64 | 기능 |
|---|---|
| **A 버튼** | 램프가 **파랑**일 때 연타 → 충전 |
| **B 버튼** | 램프가 **초록**일 때 연타 → 충전 |
| 스틱 / C버튼 / L·R / Z | 사용 안 함 |

우리 액션 매핑:

| 우리 액션 | 역할 |
|---|---|
| `a` | 원작 A = **파랑 버튼** |
| `b` | 원작 B = **초록 버튼** |
| up/down/left/right | 없음 |

입력 규칙:
- **연타(mash)** 방식. `hit()`(그 프레임에 새로 눌림)만 카운트, `down()` 홀드는 무효 [확정: "tap repeatedly"].
- 같은 키 반복은 **유효**(연타 게임이므로 제한 없음). 단 **연타 상한** [추정]: 초당 15회 초과분은 무시(키 반복/오토파이어 방지).
- 틀린 색의 버튼 `hit` → 방전 페널티(§4). 두 버튼을 같은 프레임에 누르면 **틀린 것으로 처리** [추정].
- 램프 색 전환 직후 잘못 누른 입력에 유예(grace)는 **없음** [확정: KoopaTV — 전환 순간의 연타 관성이 그대로 페널티가 된다고 불평]. 재현을 위해 유예 0ms. (접근성 옵션으로 사람에게만 80ms 유예를 줄 수 있으나 기본은 0.)

## 4. 규칙과 점수

- **점수 단위**: 충전량 0~100(%) [단위 자체는 추정; 원작은 게이지 그래픽만 표시].
- **가산** [영상 계측으로 뒷받침]: 올바른 버튼 `hit` 1회 = **+2.0%** → 50회 연타로 만충. Hyper 영상(HD)에서 게이지가 한 번에 약 1.6~2%씩 계단식으로 오르는 것을 확인(§11). N64 실기 영상에서 사람·CPU 모두 전환 사이 구간에서 **약 20%/초**(≈10회/초)로 차오름 → 순수 연타 약 5초 + 전환 손실 = 7~8.5초.
- **감산(방전)** [확정: 존재 / 수치는 영상 역산]: 틀린 버튼 `hit` 1회 = **−4.0%**(정답 2회분). 영상에서 전환 직후 0.3~0.5초 관성 연타(3~5회)로 게이지가 **10~18%** 떨어지는 것을 확인(§11) → 1회당 약 −3.5~−4.5%. ScreenRant "rapidly drains"와 일치. 게이지는 0 미만으로 내려가지 않는다. 방전 중 추가 애니메이션 잠금(stun)은 **없음** [추정 — 원작은 입력을 막지 않고 단지 깎기만 함]. 즉 잘못 누르고 있으면 계속 깎인다.
- **자연 감소(idle decay)**: **없음** [추정 — 출처 어디에도 언급 없음. 안 누르면 그대로 유지].
- **승리 판정** [확정]: 최초로 100% 도달한 플레이어 1명이 승. 나머지는 도달 시점의 충전량으로 2~4위 정렬.
- **동점** [확정(간접): Bulbapedia — Rock Harden이 "동점 시 점수를 못 받는 유일한 미니게임"이라 명시 → 나머지 게임(Dynamo 포함)은 **동점이면 동점자 전원이 승자**]: 같은 프레임에 둘 이상 100% → **모두 승자**(`scores` 모두 100, 배너 "1P·3P 만충전!"). 셸 순위표는 공동 1위로 표시된다. 임의의 타이브레이크(누적 연타 수·슬롯 번호)는 두지 않는다.
- `result()`: `scores = 충전량(승자 100, 나머지 0~99 정수)`, `text = '⚡ N P 만충전!'`.
- **원작 점수 예시**: 원작은 숫자 표기 없이 게이지만 보여 준다. 승패 결과 화면에 "WIN/LOSE" 표기 [확정(영상)].

## 5. 난이도 곡선 · CPU 난이도

**시간에 따른 변화** [확정: 램프 색이 "무작위로, 때로는 빠르게" 바뀜(GameFAQs) / 수치 추정]:
- 램프 색 유지 시간 `hold` [영상 계측, §11]: **{1.0, 1.5, 2.0}초 중 랜덤**(0.5초 단위로 양자화된 값만 관측: 0.93·2.0·1.5·2.0·1.46 / 1.94·1.93·1.43·1.46초). 0.3~0.6초짜리 "페인트"는 관측되지 않음 → 넣지 않는다. 전환 시 램프가 **약 0.07초(2프레임) 꺼졌다가** 반대색으로 켜진다. 일반 난이도 영상 9회 전환 모두 반대색으로 바뀜(전환 = 반대색). Hyper 영상에서는 5.0초 유지 후 **같은 색으로 재점등**(깜빡임만)한 사례 1회 → 선택 구현: 5% 확률로 같은 색 재점등.
- 시작 색은 50/50(영상 3편 모두 초록 시작이었으나 표본이 작음). 첫 전환도 같은 분포(1.0/1.5/2.0초).
- 시간 경과에 따른 가속: **없음** [추정 — 한 판이 10초 안팎이라 곡선을 둘 여지가 없음]. 대신 난이도(CPU 설정)가 난이도 곡선을 대신한다.

**CPU 난이도** [Hyper의 존재·"현대 TV로는 못 이김"은 확정, Hyper의 연타 속도·무오입력은 영상 계측, 나머지는 보간]. 원작 Stadium 1은 **Easy/Normal/Hard/Hyper 4단계**(일본판 かんたん/ふつう/つよい/すごい) [확정: Serebii·Bulbapedia·Gfinity]. Hyper 해금 = "Who's the Champion?"에서 CPU 3명 상대로 Hard 5연승 [확정]. Very Hard는 Stadium 1에 없다 — 우리는 Hard와 Hyper 사이 보간으로만 제공:

| 난이도 | 연타 속도(회/초) | 색 전환 반응 지연 | 오입력 확률(전환당) | 결과 |
|---|---|---|---|---|
| Easy | 8.0~9.0 (※) | 450~600ms | 전환마다 관성 연타 4~5회(≈ −15%) | 사람이 대충 해도 이김 |
| Normal | 9.0~10 | 300~450ms | 3~4회(≈ −10~−14%) | 성실히 연타하면 이김 |
| Hard | 9.5~10.5 | 150~250ms | 1~2회(≈ −5%) | 실수 없이 연타해야 이김 |
| (Very Hard — 원작 Stadium 1에 없음, 우리 보간) | 10~11 | 80~150ms | 0~1회 | 매우 어려움 |
| Hyper | 10~11 | 30~70ms | 0회(오입력 없음) | 사실상 못 이김(원작 트리비아 재현) |

※ Easy/Normal의 연타 속도를 10회/초보다 낮게 둔 것은 **키보드 사람(≈8~9회/초)이 이길 수 있게 하는 의도적 밸런스 조정**이다(원작 N64 A/B 연타보다 키보드가 느림, §11-13). 원작 재현이 아니라 체감 난이도 재현이 목적.
※ 영상 계측(§11) 결과 **CPU의 연타 속도는 난이도와 무관하게 사람과 비슷한 ≈20%/초(≈10회/초)**이고, 난이도 차이는 거의 전적으로 **전환 반응 지연(=관성 오입력 횟수)** 에서 나온다. 일반 난이도 영상의 CPU는 전환마다 10~17% 잃었고, Hyper CPU는 0% 잃고 7.4초에 만충했다.

셸에 난이도 선택 UI가 없으면 **기본 Normal**, CPU 3명에게 각각 표 범위 안의 값을 랜덤 배정해 개성 부여.

## 6. 화면 구성

[영상 기반 확정 + 세부 수치 추정]
- **카메라**: 정면, 약간 위에서 내려다보는 3/4 시점. 스크롤 없음, 한 화면 고정.
- **발전기** [영상 확정]: 화면 중앙(W/2), 몸통 중심 y≈H×0.42. 은색 캡슐형 몸통(폭≈W×0.3, 높이≈H×0.2)에 검은 격자 통풍구(위), 왼쪽에 흰 계기판 2개, **오른쪽에 큰 원형 램프(반경≈H×0.06)**. 몸통 위로 분홍 코일 + 보라색 원반 2~3장(테슬라 코일)과 꼭대기에 노란 전구. 램프는 **꺼져 있으면 검정**, 켜지면 파랑/초록 단색 원 + 하이라이트. 전환 순간은 흰 플래시가 아니라 **0.07초 소등**(검정) 후 반대색 점등. 몸통 양옆에 노랑·검정 사선 띠.
- **램프 안내 텍스트**(원작에는 없지만 컨트롤러 색 힌트가 없는 우리 환경에 필요): 램프 아래 "파랑 = A" / "초록 = B"를 현재 색으로 크게(48px) 표시.
- **플레이어 4명** [영상 확정]: 화면 하단, 가로로 등간격 4열(x = W×(0.17, 0.39, 0.61, 0.83), y = H×0.78). 각자 노랑·검정 사선 테두리의 원형 발판(안쪽 초록 원) 위. 발판에서 발전기 하단으로 **플레이어 색 전선**(1P 파랑, 2P 초록, 3P 빨강, 4P 주황 — 배지 색과 동일)이 직선으로 이어진다. 연타 중 전선이 밝게 빛나고(굵어짐) 스파크가 발전기 쪽으로 흐른다. 우리 구현은 셸 플레이어 색을 전선에 쓴다.
- **충전 게이지** [영상 확정]: 각 플레이어 **발판 아래** 가로 바(폭 W×0.15, 높이 14px, 각진 모서리). **배경 파랑, 채움 노랑(왼쪽부터)**, 어두운 회색 프레임. 배지("1P"/"COM")는 원작에서 발판 앞면에 붙어 있음 → 우리는 바 바로 위에 `drawPlayerTag`. 원작 바는 프레임마다 갱신되며 정답 1회에 약 2px씩 계단식으로 늘어난다.
- **HUD**: 타이머 없음(선착 종료). 원작 HUD는 배지+게이지뿐. 상단 좌측에 "먼저 채우면 승리!" 소형 문구. 퍼센트 숫자는 게이지 옆에 작게(14px) 표기(원작엔 없음, 가독성용).
- **배경** [영상 확정 — 기존 "어두운 남색 발전소"는 틀림]: **밝은 공장 복도**. 위쪽 벽은 연한 세이지 그린 `#9DB58A`에 더 진한 초록 `#6F8F63` 사각 패널이 체크무늬로 박힘. 벽 중간 높이에 **검정 바탕 + 노랑 `#F2C500` 사선 경고띠**가 물결치듯 좌우로 지나감(원근 있음). 바닥은 회색 금속 패널 `#8C8F93`/`#6E7175` 타일. 램프 글로우 반사는 약하게만.

## 7. 연출

- **시작** [영상 확정]: 원작은 발전기 앞에 분홍 풍선 글씨 **"3" → "2" → "1" → "GO"**(각 약 1초)가 뜨고, GO 표시 중(약 0.3초 뒤) 램프가 첫 색으로 점등된다. 셸 카운트다운을 쓰되 점등 시 `sfx.go`. 점등 전 입력은 무시(램프 소등 상태 = **검정**).
- **정답 연타**: 캐릭터 진동(±3px, 60Hz 느낌) + 스파크 파티클 4~6개(램프색) + `sfx.tap`(사람만). 게이지 25/50/75% 통과 시 `sfx.pop` + 작은 점프.
- **오입력**: 캐릭터 `dizzy` 0.3초 + 회색 스파크가 바닥으로 흩어짐 + 게이지가 붉게 0.2초 깜빡이며 감소 + `sfx.bad`(사람만). 텍스트 "찌릿!" 팝업 (0.5초).
- **램프 전환**: 램프 0.07초 소등(검정) 후 반대색 점등 + `sfx.tick`. 안내 텍스트도 즉시 바뀐다. 소등 프레임 동안의 입력은 **새 색 기준**으로 판정(원작에서 소등 중 게이지가 1~2% 줄어드는 것이 관측됨 = 이전 색 관성 연타가 이미 오답 처리).
- **종료** [영상 계측]: 100% 도달 즉시 **램프 소등(검정)**, 모든 입력 무시. 약 0.5초 뒤 발전기 꼭대기 전구에서 **굵은 노란 번개가 패자 3명에게** 내리꽂히며 화면이 흰빛으로 뒤덮이고 패자는 검게 그을린 실루엣으로 부들부들(`hit`) **약 2초**. 승자는 그동안 제자리에서 `jump` 반복. 번개가 끝나면 패자는 `dizzy`로 주저앉고(약 2초), 이어 "N P WINS" 배너(노란 큰 글씨 + 배지)가 표시된다. 우리 구현: 승리 확정 → 0.5초 정지 → 2.0초 감전 연출 → 1.5초 dizzy → `g.finish()`(총 ≈4초) → 셸 순위 화면. `sfx.win`(승자 사람일 때) / `sfx.lose`.
- **아나운서 대사 요지**(원작은 음성 없이 텍스트/효과음, 우리는 텍스트): 시작 "파랑은 A, 초록은 B!", 오입력 잦을 때 "색을 잘 봐!"(선택), 종료 "N P 만충전!".

## 8. AI 행동 모델 제안

CPU는 "램프 색을 지연 후 인지 → 인지한 색에 맞는 버튼을 일정 주기로 연타" 모델. 상태: `seen`(인지 색), `rate`(회/초), `delay`(ms), `errK`(전환당 오입력 횟수 분포).

```
전환 발생 시: reactAt = now + delay(난이도 범위 랜덤, ±30% 지터)
매 프레임: if now >= reactAt: seen = lampColor
연타 타이머 cd -= dt; if cd <= 0: press(seen); cd = 1/rate × (0.85~1.15 랜덤)
전환 후 첫 반응 프레임에서 확률 P(err)로 잘못된 색을 errK회 더 누른 뒤 정정
```

| 난이도 | delay(ms) | rate(회/초) | P(err) | errK | 정확도(정답 비율) |
|---|---|---|---|---|---|
| Easy | 450~600 | 8.0~9.0 | 1.0 (지연 자체가 오입력) | 지연 동안 4~5회 | ≈ 80% |
| Normal | 300~450 | 9.0~10 | 1.0 | 3~4회 | ≈ 86% |
| Hard | 150~250 | 9.5~10.5 | 1.0 | 1~2회 | ≈ 93% |
| Very Hard(보간) | 80~150 | 10~11 | 1.0 | 0~1회 | ≈ 97% |
| Hyper | 30~70 | 10~11 | 0 | 0 | ≈ 100% |

※ 별도의 P(err) 주사위는 두지 않는다 — 원작 영상에서 CPU 오입력은 **오직 전환 직후 관성 구간**에서만 발생하고, 색이 유지되는 동안엔 오입력이 전혀 없다(§11). `delay` 동안 예전 색으로 계속 누르는 것만으로 표의 errK가 자연히 나온다.

지연 중(전환~reactAt)에는 예전 색으로 계속 연타하므로 자연스럽게 오입력이 발생한다 — 이것이 원작의 "전환 직후 관성 페널티"를 CPU에도 똑같이 적용하는 핵심. 기대 소요 시간(Normal): 50회 정답 ÷ 9.5회/초 ≈ 5.3초 + 전환 4~5회 × 손실 12%(≈0.6초분) ≈ 8초 → 영상의 7.4~8.2초와 일치.

## 11. 비평가 보강 (2026-09-09, 독립 검증)

검증 방법: Bulbapedia(미니게임 페이지·Walkthrough Part 5), Serebii Kids Club, KoopaTV, ScreenRant, CBR, Gfinity, 일본어 검색(ビリリはつでんきょうそう)을 재조회했고, 유튜브 영상 3편(odTFoXZjpsQ 27초·N64 / aP2STL8dFbA 31초·N64 / d2Gqk4njJu8 48초·Switch NSO **Hyper**)을 내려받아 **프레임 단위로 램프 색과 4개 게이지의 노란 채움 폭을 계측**했다. GameFAQs·Fandom·StrategyWiki·니코니코·아니오타wiki는 403/402로 열람 실패.

### 추가·수정한 사실 (모두 본문에 인라인 반영)

1. **한 판 길이 수정**: 램프 점등→만충 = 7.4초 / 8.2초 / 7.4초(Hyper). 본문의 "8~15초, 10±3초"를 **7~9초**로 교정. 원작 특유의 "눈 깜짝할 새 끝나는" 느낌의 핵심.
2. **램프 유지 시간 분포 확정(관측)**: {1.0, 1.5, 2.0}초로 양자화된 값만 나옴(9회). 균등분포·짧은 페인트(0.3~0.6초)는 폐기. 전환 사이 **0.07초 소등(검정) 블링크**가 있고, 흰 플래시는 없음. Hyper 영상에서만 5.0초 유지 + 같은 색 재점등 1회 관측(선택 구현).
3. **정답 1회 충전량**: Hyper HD 영상에서 게이지 계단 폭 ≈ 1.6~2%/회 → **+2%/50회** 채택(추정→계측 뒷받침).
4. **오입력 감소량**: 전환 직후 관성 연타(0.3~0.5초, 3~5회)로 10~18% 감소 관측 → **−4%/회** 채택. 사람 1P가 18%, 2P가 17% 잃은 장면(N64 영상 첫 전환)이 있어 사람도 예외 없음.
5. **CPU 행동 모델 수정**: CPU 연타 속도는 난이도와 무관하게 ≈20%/초(≈10회/초)로 사람과 같다. 난이도 = **전환 반응 지연**뿐. 일반 난이도 CPU는 전환마다 10~17% 잃고, Hyper CPU는 0% 잃고 7.4초에 만충(사람 1P는 같은 시간에 74%). 표의 Easy 4~5회/초·Hyper 12~14회/초는 근거 없어 교체. 색 유지 중 무작위 오입력(P(err))도 관측되지 않아 제거.
6. **난이도 단계 확정**: Easy/Normal/Hard/Hyper(かんたん/ふつう/つよい/すごい). Hyper 해금 = Who's the Champion? Hard 5연승. Very Hard는 존재하지 않음(우리 보간임을 표에 명시).
7. **배경 수정**: "어두운 남색 발전소"는 틀림. 실제는 **밝은 세이지 그린 체크 벽 + 검정/노랑 사선 경고띠 + 회색 금속 바닥**의 공장 복도. 색값 제시.
8. **발전기 외형 수정**: 은색 캡슐 몸통, 왼쪽 계기판 2개, **오른쪽 큰 원형 램프**(꺼지면 검정), 위에 분홍 코일+보라 원반+노란 전구. 램프는 화면 중앙(y≈H×0.42)이지 "중앙 상단 H×0.22"가 아님.
9. **전선 색 수정**: 회색이 아니라 **플레이어 색**(1P 파랑·2P 초록·3P 빨강·4P 주황, 배지 색과 동일). 연타 중 밝게 빛남.
10. **게이지 색 수정**: 배경 파랑 + 채움 노랑(왼쪽부터), 발판 아래. "1P/COM" 배지는 발판 앞면.
11. **시작 연출**: 분홍 풍선 글씨 3·2·1·GO(각 ≈1초), GO 중 램프 점등. 소등 램프 = 검정(회색 아님).
12. **종료 연출 타이밍**: 만충 → 램프 소등 → ≈0.5초 뒤 꼭대기 전구에서 패자 3명에게 굵은 번개 ≈2초(화면 흰빛, 패자 검은 실루엣) → 패자 dizzy ≈2초 → "N P WINS" 배너. 우리 `g.finish()`는 만충 후 ≈4초.
13. **사람 vs CPU 밸런스 주의**: 키보드 연타는 N64 A/B보다 느릴 수 있다(Switch 영상의 사람은 10%/초). 사람 만충 시간이 9초를 넘기면 정답 충전량을 2.2~2.5%로 올리는 튜닝 상수 권장(CPU는 2% 고정).
14. **캐릭터 표현 추가**: 피카츄는 연타 중 제자리 뜀+볼 스파크, 찌리리공은 **회전해 흰 공처럼 흐려짐**. 감전 시 둘 다 검게 그을린 실루엣.
15. **아이템·장애물 없음** [확정]: 영상 3편 어디에도 보너스/방해 요소 없음. 램프만이 유일한 변수.

### 여전히 불명 (합리적 추정 유지)
- 두 버튼 동시 입력 처리, 정확한 동점 처리(같은 프레임 만충) — 영상에 사례 없음. §3·§4의 추정 유지.
- 램프 유지 시간의 정확한 확률 가중치(1.0/1.5/2.0 각 1/3로 둠), Hyper에서 5초 유지가 규칙인지 우연인지.
- 정답 1회 충전량이 정확히 2%인지 1/60인지(계단 폭 1.6~2%). 튜닝 상수로 둔다.
- 아나운서/텍스트 원문: 결과 배너는 "1P WINS"/"COM WINS" [확정], 그 외 텍스트 없음.

## 12. 비평가 보강 2차 (2026-09-10, 독립 재검증)

재조회한 출처: Bulbapedia 미니게임 목록 페이지(Thundering Dynamo·Kids Club 항목), Bulbapedia Walkthrough Part 5, Serebii Kids Club, KoopaTV. StrategyWiki·GameFAQs 50319는 이번에도 403. 유튜브 영상은 §11 계측값을 그대로 신뢰하되 **내부 모순**을 아래에서 짚었다.

### 확인된 것(§1~§7과 일치)
- 피카츄/찌리리공 랜덤, 파랑=A·초록=B 연타, 오입력 시 방전, 만충 선착 승, 제한 시간 없음, Easy/Normal/Hard + 숨김 Hyper(Who's the Champion? Hard 5연승) — Bulbapedia·Serebii·KoopaTV 3곳 일치.
- Hyper 트리비아 원문(Bulbapedia): "virtually impossible to beat the CPU players in the Hyper difficulty ... due to LCD input lag preventing the player from being able to press the A and B buttons **as fast as the CPU**" — 즉 Hyper CPU는 **연타 속도 자체가 사람 이상**이라는 함의. §5·§8의 "난이도 차이는 반응 지연뿐"은 일반 난이도 관측에는 맞지만 Hyper에는 부족하다(아래 3번).

### 추가·수정 사항
1. **동점 규칙 확정(간접 근거)**: Bulbapedia가 Rock Harden을 "동점 시 점수를 못 받는 유일한 미니게임"이라 적었으므로 Dynamo는 동점(같은 프레임 만충) 시 **동점자 전원 승**. §4를 "모두 승자, scores 전원 100"으로 교정. 임의 타이브레이크 삭제.
2. **§11 계측치의 내부 모순 해소**: "정답 +2% × ≈10회/초 = 20%/초 → 순수 5초"인데 Hyper CPU가 **오입력 0으로 7.4초** 만충이라면 실효 속도는 13.5%/초(≈6.8회/초)뿐이다. 일반 난이도 8.2초(전환 손실 ~40~50% 포함)와 비교하면 Hyper 쪽이 오히려 느린 셈이라 두 영상(N64 실기 vs Switch NSO 녹화)의 프레임레이트/GO 기준점이 다르게 계측됐을 가능성이 크다. **구현 지침**: 회/초 수치보다 "체감 목표 시간"을 기준으로 상수를 맞춘다 — Normal CPU 만충 8~9초, Hard 7~8초, Hyper **5~6초**(오입력 0). 사람이 완벽하게 연타해도 Hyper에 지는 원작 감각을 살리려면 Hyper `rate`를 **12~13회/초**(사람 연타 상한 15회/초 바로 아래)로 올리고 `delay` 30~70ms를 유지한다. §5·§8 표의 Hyper 10~11은 하한값으로 본다.
3. **사람 오입력 페널티는 원작 그대로**: 유예 0ms는 유지하되, 전환 후 첫 0.07초 소등 프레임 동안 사람이 이미 누르고 있던 버튼의 `hit`은 새 색으로 판정(§7). 이것이 원작의 "관성 페널티" 감각이며 완화하면 원작과 달라진다. 접근성 옵션(80ms 유예)은 기본 off.
4. **연타 판정의 프레임 독립성**: `hit()`은 프레임당 1회만 잡히므로 60fps 기준 최대 60회/초, 15회/초 상한 로직은 `lastPress` 타임스탬프로 66ms 미만 간격 입력을 무시하는 식으로 구현(프레임 스킵 시에도 동일 체감).
5. **게이지 자연 감소 없음 재확인**: 4개 출처 모두 "wrong button drains"만 언급, idle 감소 언급 없음. 현재 `games/dynamo.html`의 `p.bar -= dt*0.15` 자연 감소는 **삭제**해야 한다.
6. **현 구현 대비 필수 변경 체크리스트**(재구현 시 확인): ① 노랑→**초록**, ② `input.hit('KeyA'/'KeyL')`→`g.p(i).hit('a'/'b')`(계약 위반 항목), ③ `duration:30`→`0` + 선착 `g.finish()`, ④ `stun 0.7초` 삭제(원작은 입력 잠금 없음), ⑤ 자연 감소 삭제, ⑥ 배경 `#2A1F3D` 남색→세이지 그린 공장 복도(§6), ⑦ 램프 안내 텍스트 "파랑 = A / 초록 = B", ⑧ CPU 슬롯이 사람 슬롯 색·배지 `drawPlayerTag` 사용, ⑨ 종료 4초 감전 연출 후 `finish()`.
7. **난이도 선택**: 셸에 UI가 없으므로 기본 Normal. 단 CPU 3명의 `delay`를 표 범위 안에서 서로 다르게 뽑아 "한 명은 바짝 붙고 한 명은 뒤처지는" 원작 레이스 감각을 만든다(전원 동일 파라미터 금지).
8. **한 판 길이 상한**: KoopaTV "약 10초"와 §11 7.4~8.2초를 합쳐 목표 **7~10초**. 사람 포함 4명 중 최소 1명은 10초 안에 만충해야 하며, 안전장치 30초는 사실상 미사용.
9. **일본어 원제 신뢰도 하향**: 「ビリリはつでんきょうそう」는 검색 요약만이며 Stadium 2 「ピチューのはつでんきょうそう」와 혼동됐을 수 있음. 제목 결정에 사용하지 않는다(한국어 제목 "번개 발전기" 유지).
10. **아이템·해저드 없음 재확인**: Bulbapedia·Serebii·KoopaTV 어디에도 보너스/방해 요소 없음. 램프 색 전환이 유일한 변수.

### 여전히 불명
- 두 버튼 동시 입력(같은 프레임) 처리 — "틀린 것으로 처리" 추정 유지.
- Hyper CPU의 정확한 연타 속도(영상 7.4초 vs 트리비아 "사람보다 빠름"의 충돌) — 위 2번 지침으로 체감 우선.
- 램프 유지 시간 가중치, 같은 색 재점등 빈도 — 각 1/3, 5% 유지.

## 13. 구현 메모 (games/dynamo.html, 2026-09-10 재작성)

- **계약 v2 준수**: 4슬롯 고정, 사람은 `g.p(i).hit('a'/'b')`, CPU는 §8 모델, `duration: 0` + 선착 `g.finish()`, `result()` = `{scores:[충전량×4], text:'⚡ N P 만충전!'}`, 배지는 `drawPlayerTag`. 자연 감소·스턴·직접 키코드·"나/라이벌" 표기 모두 제거(§12-6 체크리스트 전부 반영).
- **채택 상수**: 정답 +2.0%(CPU, §4·§11-13 고정, v3) / +2.5%(사람, §11-13 상한값 — 키보드 연타 보정), 오답 −4%, 연타 상한 15회/초(`lastPress` 66ms), 램프 유지 {1.0, 1.5, 2.0}초, 소등 0.07초, 같은 색 재점등 5%, GO 0.3초 뒤 첫 점등, 안전장치 30초(최다 충전 승) + 38초 강제 종료.
- **CPU 보정 v3 (QA 반영, 60fps 로직 시뮬 1,000회/셀)**: 전원 Normal, 연타 9.0~10회/초(§5·§8 표), 정답 CPU +2.0% · 사람 +2.5%. 지연 지터는 ±15%. **편차**: §5 Normal 지연 300~450ms로는 전환마다 약 3.5회×4% 손실이 나 +2.0%에서 만충이 ≈20초가 되므로(§8 기대치 계산의 0.6초 손실 가정이 과소), 세 CPU 지연을 [0.20~0.25]/[0.25~0.30]/[0.30~0.35]초로 당겨 §12-8을 맞춤. 결과(1P 방치, CPU끼리): 결승 중앙값 8.8초 · p10 7.3초 · p90 10.5초(20fps 중앙값 9.3초). **알려진 트레이드오프**: 레이스 시간과 사람 승률은 둘 다 가장 빠른 CPU가 결정하므로 함께 움직인다. 반응 0.35초에 전환 중에도 옛 색을 계속 누르는 사람 모델은 9회/초 ≈12% · 10회/초 ≈38% 승. 전환 깜빡임(0.07초)에 잠시 손을 떼는 사람은 훨씬 유리. 쉽게 하려면 GAIN.human이 아니라(이미 상한 2.5) DSPREAD 하한을 0.23으로 올리면 9회/초 ≈30%지만 p90 ≈11.9초. 4 CPU(사람 0)도 안전(`DSPREAD` 복사본 셔플, 인덱스 순환).
- **점수 반올림**: 비승자는 `min(99, floor(charge))`만 보고(게이지 라벨 포함) → 99.5% 패자가 100으로 공동 1위가 되는 문제 제거(§4). 30초 안전장치에서 전원 0이면 승자 없음 + 결과 문구 '무승부'.
- **UI**: 게임 화면에는 키 이름을 표시하지 않음(CONTRACT — 키는 셸 타이틀에 표시). 첫 점등음은 `sfx.go` 대신 880Hz beep(**§7 편차**: 셸이 GO 순간에 이미 sfx.go를 재생하므로 0.3초 뒤 같은 소리를 겹치지 않음). '찌릿!' 팝업은 머리 위, 안쪽 레인(2P·3P)은 ±70px 바깥으로 비켜 램프 안내 문구와 겹치지 않게. 램프 안내·아나운서 문구는 count/play 상태에서만. 공 회전 = 12 × 최근 연타 속도(§1).
- **저프레임 보호**: CPU 연타 타이머는 상한(66ms)에 걸린 프레임에서 소모되지 않는다(20fps에서도 평균 연타 속도 유지). 헤드리스 검증 환경은 rAF가 느려 게임 시간이 실시간의 0.5~0.9배로 흐르므로 6초 스크린샷에서 게이지가 30~50%로 보이는 것이 정상.
- **미구현/생략**: Hyper 5초 유지 규칙(선택 항목), 접근성 80ms 유예(기본 off), 난이도 선택 UI(셸에 없음 → 기본 전원 Normal).
