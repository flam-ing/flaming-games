# rollout — 돌돌 레이스 (원작: Rampage Rollout, Pokémon Stadium 2 · N64 Mini-Game)

## 1. 한 줄 요약 + 등장 포켓몬과 플라밍고 대체안

**한 줄 요약 [확인]**: 코뿌리(Donphan) 4마리가 **탑다운 사각 트랙을 9바퀴** 도는 경마식 레이스. 매 바퀴 결승선을 통과할 때 **순위가 낮을수록 먼지회오리(dust cloud / whirlwind / dust tornado)를 많이 받고**(1위 0개 · 2위 1개 · 3위 2개 · 4위 3개), A 버튼으로 트랙에 놓아 뒤따르는 상대를 멈춰 세운다. **마지막 9바퀴째는 코뿌리가 몸을 말아 「구르기(Rollout)」로 달린다**(속도 상승). 9바퀴를 가장 먼저 완주하면 승리. 이동은 십자키로 **90° 단위 방향 전환만 가능**한 “스네이크(Snake)식” 조작이다(TheGamer/TikTok 설명: “everyone moving at strict 90° angles, so it controls like Snake”).

| 원작 요소 | 역할 | 플라밍고 대체안 (셸 포즈) |
|---|---|---|
| 코뿌리 ×4 (1P~4P 색 배지) | 플레이어 캐릭터 | 플라밍고 ×4, `palette.players[i]` 색. 달릴 때 `run`(진행 방향으로 `flip`/`rot`), 대기(Ready) `idle`, 마지막 바퀴 구르기 = `ball` 포즈에 `rot`를 매 프레임 누적 회전(구르는 공), 먼지회오리에 걸림 `dizzy`, 골인 `jump` 반복, 최하위 `sleep` |
| 먼지회오리(dust cloud) | 트랩 아이템 | 회오리 = 갈색(#b8894f) 반투명 원 3~4개가 나선으로 도는 스프라이트(반경 18px), 그 위에 흙 파티클. 놓을 때 `sfx.pop`, 맞을 때 `sfx.hit` |
| 소지 회오리 표시 | 보유 개수 | 원작은 **캐릭터 머리 위에 도는 별(swirling star)** 로 표시 [확인: StrategyWiki] → 플레이어 태그 위에 작은 별 0~3개 회전 + HUD 아이콘 0~3개 병행 |
| 트랙(흙길 + 잔디 안뜰, **울타리**) | 경기장 | 탑다운 링 트랙. 형태는 출처가 갈림: Bulbapedia “circular track” / StrategyWiki “small, fenced area” / TikTok “square track” → **둥근 모서리 사각(스타디움형 오벌)** 채택(90° 조작과 직선 구간이 필요).  바깥 잔디(#5cb85c) / 흙길(#d9b27a) / 안쪽 잔디섬. 바깥·안쪽 경계에 흰 울타리 말뚝(4px, 24px 간격). 결승선은 흰-검 체크무늬 |
| 바퀴 수(LAP) 표시 | 진행 HUD | `n/9 바퀴` 텍스트 |
| 심판/아나운서 | 연출 | 한국어 텍스트 오버레이(7절) |

## 2. 인원·시간·라운드

- **4인 동시 플레이 [확인]**: 1~4명 사람 + 나머지 CPU. 항상 4슬롯.
- **종료 조건 [확인]**: 제한 시간 없음. **누군가 9바퀴를 완주하는 순간** 승자 확정. 나머지는 [추정] 그 순간의 진행도(바퀴 + 바퀴 내 거리)로 2~4위 판정, 즉시 정지.
- **라운드 구조**: 단판. `duration: 0`, 게임이 `g.finish()` 호출.
- **한 판 길이 [추정]**: 원작 영상 기준 “Go!” 후 **약 55~75초**(9바퀴, 바퀴당 6~8초). 트랙 둘레와 속도는 이 목표에 맞춘다(6절 수치).
- **안전장치 [추정]**: 180초 경과 시 강제 종료, 진행도 순.

## 3. 조작

원작 N64 [확인] (Serebii: “D-Pad: Direction / A Button: Dirt”, GameFAQs·CheatCodes: “Control Pad: Move, A Button: Use a dust tornado”):

| N64 | 기능 |
|---|---|
| **십자키(Control Pad) ↑↓←→** | 진행 방향을 그 방향으로 바꿈. **누르고 있을 필요 없음** — 한 번 누르면 그 방향으로 계속 달림(Snake식) [확인: 90° 이동 / 추정: 자동 전진] |
| **A** | 보유 회오리 1개를 **자기 바로 뒤 트랙에** 놓음(보유 0이면 무반응) |
| B / 스틱 / C / L / R | 사용 안 함 [확인: 언급 없음] |

우리 매핑:

| 우리 액션 | 역할 |
|---|---|
| `up down left right` | 방향 전환(`hit` 또는 `down` 모두 인정: 누르고 있어도 됨, 눌리는 순간 방향 확정) |
| `a` | 회오리 설치 (`hit`만) |
| `b` | [추가안] `a`와 동일(편의) |

입력 규칙 (정확히 이대로):
1. 캐릭터는 항상 **현재 방향 `dir ∈ {U,D,L,R}`로 자동 전진**. 방향키를 누르면 다음 프레임부터 `dir` 교체. **역방향(180°) 입력은 무시** [추정 — Snake 관례. 원작 영상에서 역주행 장면 없음].
2. 트랙 경계: 흙길 밖(바깥 잔디·안쪽 잔디섬)으로는 나갈 수 없다 — 벽에 닿으면 **그 자리에서 정지**(속도 0)하고 방향키 입력을 기다린다 [추정: 원작에서 코너에서 늦게 꺾으면 벽에 박혀 멈추는 것이 주된 실수 요소]. 멈춰 있는 동안 상대에게 추월당한다. 정지 프레임에 `sfx.beep(180,0.06,'square',0.08)`.
3. 트랙은 **반시계 방향(CCW)** 주행이 정방향 [추정 — 영상에서 좌하에서 우로 출발]. 역주행해도 막지 않지만 진행도가 줄어든다(코너 커팅 방지 겸).
4. `a` `hit` → (누르고 있어도 연속 설치 안 됨, **1회 누름 = 1개**) 보유 ≥1 이면 보유 −1, 캐릭터 중심에서 **진행 반대쪽 36px** 위치에 회오리 생성. 회오리는 **설치자 본인에게는 영구히 무해** — 자기 회오리는 통과해도 아무 일 없음 [확인: GameFAQs FAQ “you won't be affected by your own tornadoes”, Fandom “The dust clouds won't harm the player using them”]. 회오리 스프라이트는 설치자 색(`palette.players[owner]`)으로 살짝 틴트해 누구 것인지 보이게 한다. 생성 위치가 흙길 밖이면 트랙 안쪽으로 클램프(코너 직후 설치 대비). 이미 회오리가 있는 자리에도 겹쳐 놓을 수 있다(각각 독립 1회용).
5. **타인**의 회오리 접촉(중심 거리 < 26px) 시 **STUN 1.2초** [추정 — Psypokes “Donphan will stop” / Serebii·영상 설명 “slow down”: ‘멈춤’ 채택]: 한 회오리는 **최초 접촉자 1명**만 맞히고 소멸(같은 프레임 2명 접촉 시 슬롯 번호 낮은 쪽). 속도 0, `dizzy` 포즈, 회오리는 **소멸**(1회용) [확인: “Avoid the dust clouds, or your Donphan will stop”]. 스턴 중 방향키 입력은 버퍼링되어 스턴 해제 시 적용. 스턴 후 0.3초 무적(연속 피격 방지).
6. 회오리는 놓인 뒤 **20초 후 자연 소멸** [추정 — 원작은 트랙이 회오리로 “littered”될 정도로 오래 남음(비평가 보강 7)]. 화면에 동시 최대 12개(초과 시 가장 오래된 것 소멸).
7. 골인(9바퀴) 이후 입력 무시.

## 4. 규칙과 점수

- **점수 단위**: 원작 HUD 숫자 점수 없음. 내부는 **진행도 `prog = lap + s/PERIM`**(s = 결승선부터 트랙 중심선을 따라 잰 거리, PERIM = 둘레).
- **바퀴 판정 [확인+추정]**: 트랙을 하단·우측·상단·좌측 4개 **섹터**로 나눠 `sector`를 추적하고, 결승선(체크 라인)을 정방향으로 통과할 때 **직전에 4섹터를 순서대로(0→1→2→3) 거쳤으면** `lap += 1`(앞뒤로 왔다갔다 하며 라인만 반복 통과하는 꼼수 방지). `s`는 “섹터 시작 거리 + 그 섹터 직선 위 투영 거리”로 계산. 역방향 통과 시 `lap -= 1`(0 미만 불가). 라인 통과는 중심점 기준. 시작 위치는 결승선 **바로 앞(직전)** 나란히 4열이며 첫 통과는 카운트 안 함(lap 0 → 결승선 통과 → lap 1은 “1바퀴 완료”) [추정: 원작은 결승선 뒤에서 출발].
- **회오리 지급 [확인 — Psypokes/CheatCodes 일치]**: 결승선 통과 시점의 **현재 순위**에 따라 1위 +0, 2위 +1, 3위 +2, 4위 +3. 보유 상한 **3** [확인: “save up to three”]. 지급 시 `sfx.good` + HUD 아이콘 팝. (첫 바퀴 완료 시부터 지급.)
- **순위 계산**: 매 프레임 `prog` 내림차순. 동률이면 슬롯 번호 낮은 쪽 상위.
- **마지막 바퀴 구르기(Rollout) [확인]**: `lap == 8`(9바퀴째 진입)인 플레이어는 `ball` 포즈로 바뀌고 **속도 ×1.35** [추정]. 구르기 중에도 회오리에 걸리면 똑같이 스턴 [추정]. 회오리 설치는 계속 가능.
- **감산/페널티**: 회오리 피격 = 1.2초 정지(시간 손실). 벽 충돌 = 정지. 그 외 감점 없음.
- **승리 판정**: `lap >= 9` 를 먼저 만족한 플레이어. 같은 프레임 동시 골인 시 `s` 큰 쪽 → 슬롯 순 [추정].
- `result()`: `scores = [1위 100, 2위 60, 3위 30, 4위 10]` 순위 점수화, `text: '{이름} 9바퀴 완주! ({t.toFixed(1)}초)'`, 안전장치 종료 시 `'시간 종료!'`.
- **원작 점수 예시 [확인·요지]**: Mini-Game Mode 토너먼트는 미니게임 1승 = 1포인트, 지정 승수 도달 시 우승. 이 셸은 단판이므로 순위 점수만 사용.

## 5. 난이도 곡선

- **시간 경과 가속 [확인·요지]**: 원작에는 시간에 따른 트랙 변화·가속 없음. 유일한 페이즈 변화는 **9바퀴째 Rollout(속도 상승)**. 회오리는 바퀴가 지날수록 트랙에 쌓이므로 후반이 자연스럽게 위험해진다(러버밴딩: 하위권일수록 회오리를 많이 받음 [확인]).
- **속도 상수 [추정·2차 정정]**: 기본 주행 속도 `V = 270 px/s`(6절 트랙 중심선 둘레 PERIM ≈ 1,890px 기준 바퀴당 ≈7.0s, 8바퀴 56s + 구르기 바퀴 5.2s ≈ **61s**). (구 서술의 V=165/둘레 1,150은 6절과 모순이라 폐기.) 코너 안쪽으로 붙으면 실제 거리 단축(CheatCodes: “stay on the inside of the track to get faster laps”) → 트랙 폭을 넉넉히(96px) 둬서 인코스 이점이 바퀴당 ≈0.4s 나게 한다.
- **CPU 난이도 [확인·정정]**: Stadium 2 미니게임은 **Easy / Normal / Hard / Very Hard** 4단계(Very Hard는 Hard 난이도·7토큰 설정으로 미니게임 챔피언십 우승 시 해금 — StrategyWiki). ‘Hyper’는 Stadium 1의 명칭이므로 Stadium 2에는 없다(8절 표의 Hyper 행은 선택 사양 최상위 값으로만 남김). 행동 차이 [추정]: 낮을수록 코너를 늦게 꺾어 벽에 박히고, 회오리를 아무 데나(또는 안) 쓰며, 트랙 위 회오리를 피하지 못함. 높을수록 인코스 주행, 회오리를 **바로 뒤에 상대가 붙었을 때만** 설치, 앞의 회오리를 레인 변경으로 회피.
- 셸에 난이도 UI가 없으므로 CPU 3명을 **Normal / Hard / Very Hard**로 섞어 배치(남는 CPU 슬롯 순서대로) [추정안]. 사람이 Hard에게 가끔 지고 Very Hard에게 자주 지는 정도가 목표.

## 6. 화면 구성

- **카메라 [확인+추정]**: **탑다운(약간 기울인 조감)** 고정, 스크롤 없음. 트랙 전체가 한 화면. 우리 구현은 순수 탑다운 2D.
- **트랙 기하 [추정]** (960×540):
  - 바깥 경계 사각형: x 120~840, y 70~500 (모서리 반경 60px 둥근 사각).
  - 트랙 폭 96px → 안쪽 잔디섬: x 216~744, y 166~404.
  - 중심선 둘레 PERIM ≈ 2×(624+334) − 코너 보정 ≈ **1,850px** 라면 V=165 로 11초/바퀴가 되어 길다 → **V = 270 px/s**로 조정(바퀴당 ≈6.9s, 9바퀴 ≈60s, 구르기 ×1.35). 구현자는 `V`와 트랙 치수만 상수로 맞추면 됨.
  - 결승선: 하단 직선 구간 중앙 x=480, 폭 16px 체크무늬(흰/검 8px 격자), 트랙 폭 전체를 가로지름.
  - 출발 위치: 결승선 왼쪽 30px 지점에 4명이 트랙 폭 방향으로 나란히(간격 22px), 방향 `R` (하단 직선은 좌→우 진행 = 반시계).
- **플레이어 배치**: 캐릭터 scale 0.42(높이 ≈40px). 같은 위치에 겹쳐도 충돌 없음 [추정: 원작에서도 캐릭터 간 충돌 없음]. 각 캐릭터 머리 위(−34px)에 `drawPlayerTag`.
- **HUD**: 상단 띠(y 8~60)에 4명 패널 가로 배치(x=20, 250, 480, 710, 폭 220): 배지 + `3/9 바퀴` + 보유 회오리 아이콘 3칸(빈 칸은 회색 테두리) + 현재 순위 `2위`. 우측 상단 대신 하단 중앙(y=525)에 경과시간 `00.0` 작게. **마지막 바퀴 진입 시 그 플레이어 패널에 「구르기!」 배지**(주황).
- **배경 색감 [추정]**: 밝은 초록 잔디, 모래빛 흙 트랙, 트랙 가장자리 흰 라인 3px, 안뜰에 작은 꽃·관중석 대신 잔디 무늬. 회오리는 갈색 반투명. 전체적으로 채도 높은 만화풍.

## 7. 연출

1. **시작**: `init()` → 4명이 출발선에 `idle`. 화면 중앙 “준비…”(1.0s, `sfx.count`) → “시작!”(0.5s, `sfx.go`). “시작!”부터 자동 전진 시작·입력 유효. 원작 아나운서 “Ready… Go!” [요지].
2. **주행**: `run` 포즈, 뒤에 작은 먼지 파티클 2개/0.1s. 방향 전환 시 `sfx.tap`(작게). 벽에 박힘: 캐릭터 0.15s 흔들림 + 낮은 beep.

4. **회오리 설치**: `sfx.pop`, 회오리가 0.2s 동안 0→1 스케일.
5. **피격**: `sfx.hit`, 회오리 터짐 파티클(흙 8개), 캐릭터 `dizzy` 1.2s + 머리 위 별 아이콘.

### A. 인라인 정정 (본문 반영 완료)
1. **속도 상수 모순 제거**: 5절 `V=165 px/s / 둘레 1,150px`와 6절 `V=270 / PERIM≈1,850`이 충돌 → **V=270, PERIM≈1,890** 으로 통일. 실측: 중심선 사각 624×334, 코너 중심선 반경 12px → 2×(624+334) − 96 + 2π·12 ≈ 1,895px. 직선 시간: 긴 변 2.3s, 짧은 변 1.24s → 한 바퀴 ≈7.0s, 총 ≈61s.
2. **트랙 형태 출처 충돌 명시**: Bulbapedia는 “circular track”, StrategyWiki는 “small, fenced area”, TikTok은 “square track”. 90° Snake 조작(TheGamer)과 인코스 전략(cheatcodes)이 성립하려면 직선+코너 구조가 필요하므로 **둥근 모서리 사각(오벌)** 유지. 코너 반경 60px는 [추정].
3. **바퀴 판정을 섹터 순서 기반으로 확정**: 라인만 왕복하는 꼼수를 막고 `s`(진행 거리) 계산법을 명시(4절).
4. **회오리 1회용의 정확한 의미**: 최초 접촉자 1명만 스턴, 같은 프레임 동시 접촉은 슬롯 순. 겹쳐 놓기 허용, 트랙 밖 생성 위치는 클램프(3절).
5. **A 버튼 = 1회 누름당 1개**(홀드 연속 설치 금지) 명시(3절).

### B. 새로 확인·보강된 사실
6. **“먼지회오리” 지급 UI는 ‘엠블럼’ [확인: Serebii “you collect emblems which allow you to create a dirt tornado”]** → HUD 보유 아이콘을 작은 엠블럼(회오리 문양 원형 배지)으로 그리고, 캐릭터 머리 위 회전 별(StrategyWiki)과 병행. 지급 순간 엠블럼이 결승선 위에서 캐릭터 쪽으로 날아가 HUD에 꽂히는 0.3s 연출 추가.
7. **Serebii “complete laps without being hit” 문구**는 다른 4출처(순위 기준 고정 지급)와 어긋나므로 **채택하지 않음**. 단 이 표현이 시사하는 “맞으면 손해 = 순위 하락 → 다음 바퀴에 더 받음”은 순위 기준 지급으로 자연히 재현된다.
8. **“slow down”(Serebii·영상 설명) vs “stop”(Psypokes)**: 정지 1.2s로 채택하되, 정지 해제 후 **0.4s 동안 속도 0→V 선형 가속**을 넣어 “느려진다”는 서술과도 어긋나지 않게 한다(총 손실 ≈1.4s). 구르기 바퀴에서도 동일(가속 목표는 V×1.35).
9. **회오리 최대 지급 “per lap”** [확인: 영상 설명 “maximum of 3 per lap depending on your position”] — 지급은 바퀴당 1회, 결승선 통과 시에만. 스턴 중 통과는 불가능(속도 0)이므로 예외 없음.
10. **동률 해소**: 원작 미니게임 모드는 Q&A 라운드로 푼다(StrategyWiki 재확인). 셸에 퀴즈가 없으므로 4절 규칙(`s` 큰 쪽 → 슬롯 순) 확정. 2~4위는 승자 골인 프레임의 `prog` 내림차순, 완전 동률 시 슬롯 순.

### C. 구현 시 누락되기 쉬운 항목 (추가 규정)
11. **화면 4인 배치**: 4명이 같은 트랙을 달리므로 별도 분할 화면 없음(원작도 한 화면). 그리기 순서는 `y` 큰(아래쪽) 캐릭터를 나중에 그려 겹침을 자연스럽게, 동일 y면 슬롯 번호 순. 태그는 항상 캐릭터 위에.
12. **출발 정렬**: 결승선 30px 앞에서 트랙 폭 방향으로 4열(1P가 가장 안쪽 = 인코스) [추정]. 시작 직후 4명이 정확히 겹쳐 달리는 것을 피하려 y 간격 22px 유지.
13. **CPU의 ‘뒤에 처져 모으기’ 전략은 넣지 않는다**(GameFAQs 팁은 사람용). CPU는 8절 표대로 “뒤에 상대가 R px 내에 있을 때 설치”만 수행. Very Hard만 예외로 **마지막 바퀴 진입 시 보유 회오리를 코너 직후마다 1개씩 소진**(3개면 3코너).
14. **스턴 중 방향키 버퍼**: 마지막 입력 1개만 기억(큐 아님). 스턴 해제 시 그 방향으로 출발, 없으면 원래 `dir` 유지.
15. **구르기(9바퀴째) 조작**: 방향 전환·설치 모두 동일. 포즈 `ball` + `rot += 12 rad/s`. 스턴 시 회전 정지 후 `dizzy`.
16. **종료 직후 처리**: 승자 골인 프레임에 모든 회오리·파티클 갱신 정지, 경과시간 표시도 정지. 2.0s 뒤 `g.finish()`.
17. **안전장치 종료(180s)**: `text:'시간 종료!'`, 순위는 `prog` 순. 실제 발생 가능성은 벽에 박힌 채 방치된 사람 플레이어뿐이며, CPU는 최대 반응 지연으로도 ≈90s 내 완주.

### D. 여전히 불명(기본값 유지)
