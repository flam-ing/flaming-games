# stampede — Streaming Stampede (ピィとププリンのカウントゲーム / 포켓몬 스타디움 2, N64) 디자인 스펙

> 이 문서만으로 게임을 재구현할 수 있도록 작성. 원작 자료에 없는 값은 `불명 — 추정:` 으로 표시하고 리뷰어가 유튜브 영상과 비교할 수 있게 근거를 적었다.
> 좌표/시간 값은 셸 캔버스 960×540 기준(`g.W`, `g.H`). 게임 id: `stampede`.

## 1. 한 줄 요약 · 등장 캐릭터와 플라밍고 대체안

**한 줄 요약**: 화면을 가로질러 우르르 지나가는 포켓몬 무리 속에서 **문제로 지정된 포켓몬만** 골라 **A 버튼을 한 마리당 한 번씩** 눌러 세고(카운트), 정답에 가까울수록 점수를 받는 **관찰·카운팅 게임**. 5문제(라운드) 합계 점수로 승부. 원작 일본판 제목이 "피이와 푸푸린의 카운트 게임"이며 영어판은 "Streaming Stampede"(흘러가는 대이동).

| 원작 요소 | 원작 | 플라밍고 대체안 |
|---|---|---|
| 플레이어 캐릭터 | 삐(Cleffa) / 푸푸린(Igglybuff) **무작위 배정**(플레이어가 고르지 않음, 4명 모두 같은 종일 수도 있음). 화면 아래쪽 자기 자리(카운터 앞)에 앉아 A를 누를 때마다 깡총 뛰며 센다 | 플라밍고 4마리(슬롯 색 `palette.players[i]`), scale 0.55. 대기 = `idle`, A 입력 순간 = `jump` 0.18s(카운트 1회당), 라운드 정답 발표 시 정답 = `jump` 1.0s 반복, 1~2 차이 = `idle`, 3 이상 틀림 = `dizzy` 1.2s, 0점 최하위 = `sleep` |
| 세어야 할 포켓몬(타깃) | 라운드마다 바뀌는 소형 포켓몬 무리(예: 꼬리선·나옹·뽀뽀라 등 2세대 소형 포켓몬 — 정확한 종 목록은 불명). 타깃 이름은 라운드 시작 전 문제 문장으로 제시 | 플라밍고 **소품 종(species)** 6종을 색·포즈로 구분한다. 종 = `{name, color, pose}`: ① 빨강 `run` ② 파랑 `run` ③ 노랑 `fly`(낮게 날아감) ④ 초록 `ball`(굴러감) ⑤ 보라 `hit`(성큼성큼) ⑥ 주황 `dig`(땅에 반쯤 묻혀 지나감). 각 종은 **머리 위 한글 이름표 없음** — 색과 포즈만으로 구분(원작도 실루엣·색으로 구분). 문제 문장에는 "빨간 플라밍고는 몇 마리?"처럼 색+포즈 명칭을 쓴다 |
| 방해(decoy) 포켓몬 | 3~4문제에서 타깃과 비슷한 **다른 종** 또는 **닮은 사물**이 섞인다. 원작 확인 사례: 찌리리공 문제에 몬스터볼이 함께 굴러오고, 토게피 문제에 토게피 알이 함께 굴러온다(일본 플레이 기록·아니오타위키 요약, §10). 즉 방해물은 포켓몬만이 아니라 **비슷한 모양의 물체**도 포함 | 타깃과 **같은 포즈 다른 색** 또는 **같은 색 다른 포즈**의 플라밍고(§5 표)에 더해, **닮은 사물**을 섞는다: 초록 `ball` 종 문제엔 초록 공(원, r=18), 노랑 `fly` 종 문제엔 노란 알(타원 26×34). 사물은 캔버스 도형으로 그리며 같은 레인·같은 속도로 굴러간다(회전 애니메이션) |
| 무리의 이동 | 화면을 가로질러 줄지어 **뒤뚱뒤뚱 걸어**("waddle past the camera" — GameFAQs 가이드) 지나감. 진행 방향(오른쪽→왼쪽)은 불명 — 추정. 여러 열(레인)에 겹쳐서 지나가며 앞뒤로 살짝 가려짐 | 동일. 레인 3개(y = 250 / 300 / 350), 오른쪽 밖(x=1010)에서 왼쪽 밖(x=-60)으로 |
| 무대 | 게임쇼 스튜디오풍(카운트 게임쇼). 뒤쪽은 초원/언덕 통로, 앞쪽에 플레이어 4명이 나란히 앉은 카운터 | `bg()` 위에 연녹색 언덕 통로(y 220~380) + 앞쪽 나무 카운터 4칸(y 400~470) |
| 카운터 숫자판 | 각 플레이어 앞(머리 위)에 자기가 지금까지 센 숫자가 크게 표시 | 각 자리 위 `rr` 흰 패널(90×44)에 숫자 32px 굵게. CPU도 실시간 숫자 표시(원작과 동일하게 보여 심리전 발생) |

## 2. 인원 · 시간 · 라운드 구조

- **4인 동시 플레이**(사람 1~4, 나머지 CPU). 전원 같은 무리를 보고 각자 센다. 서로 간섭 없음.
- **제한 시간 없음. 종료 조건 = 5라운드(문제) 완료.** (`duration: 0`, 게임이 `g.finish()` 호출) — 원작 확정(Bulbapedia "five rounds", Serebii/GameFAQs "first two questions… third and fourth… final question").
- 라운드 1회 흐름(시간은 불명 — 추정, 유튜브 영상 리듬 기준):
  1. **문제 제시(question)** 2.2s — 화면 중앙 상단에 문제 문장 팝업("Q1. 빨간 플라밍고는 몇 마리?") + `sfx.pop`. 이 동안 입력 불가, 카운터 0으로 리셋.
  2. **카운트다운** 0.8s — "시작!" 텍스트 + `sfx.go`. (원작은 라운드마다 별도 Ready/Go 없이 무리가 바로 들어옴 — 추정. 우리 구현은 짧은 "시작!"만 표시)
  3. **스탬피드(stream)** 라운드별 8~14s(§5 표) — 무리가 지나간다. A 입력 유효.
  3b. **답 입력 유예(answer)** 마지막 개체가 왼쪽 밖으로 나간 뒤 **`ANSWER_GRACE` = R1~R4 4.0s / R5 6.0s**(2차 보강 2번) — 여전히 A(·B) 입력 유효. 화면 중앙에 "답을 정하세요!" + 줄어드는 노란 바(폭 400→0). 원작 공략 팁 "마지막 문제는 먼저 눈으로 세고 지나간 뒤에 숫자를 입력하는 게 쉽다"(cheatcodes 가이드)가 이 유예 구간의 존재를 확정한다 — 즉 원작에서 카운터는 개체가 지나가는 순간에 잠기지 않는다. 유예 종료 시 `sfx.tick` + 패널 잠금. (길이는 추정)
  4. **정답 발표(reveal)** 3.0s — 화면 중앙에 "정답: 7마리!" 큰 글자 + 각 플레이어 카운터 옆에 `+10` / `+5` / `+1` / `0` 팝업. 정답자는 `jump`, 오답자는 `dizzy`. `sfx.good`/`sfx.bad`.
  5. 라운드 사이 텀 0.5s.
- 총 플레이 시간 ≈ 5문제 × (2.2+0.8+11+4.4+3.0+0.5) ≈ **105~110초** + 시작/종료 연출. 원작 플레이 영상 길이(타이틀·결과 포함) 114s / 117s / 132s / 145s, 퍼펙트 영상 214s(캐릭터 선택 포함) → 순수 플레이 약 100~130초. 첫 초안의 70~80초는 너무 짧아 수정.
- 최종 라운드(5)는 원작에서 "**지나가는 포켓몬 전부**를 세라"는 문제("count all of the Pokémon that appear" — Bulbapedia).

## 3. 조작

| N64 | 원작 기능 | 우리 액션 |
|---|---|---|
| **A** | Count. 한 번 누르면 카운터 +1 | `a` |
| B | 없음(불명 — 추정: 원작에 카운트 취소는 없음) | `b` = **카운터 −1**(우리 편의 기능). 플래그 `ALLOW_UNDO` **기본값 false**(원작 충실). true일 때만 안내 문구에 "B: 하나 빼기" 표시 |
| 스틱 / C / Z / R / L | 없음 | 무시 |

- **연타형**이 아니라 **한 마리당 한 번**. `hit('a')`(프레임 hit)만 사용, `down('a')` 홀드로는 증가하지 않음.
- **입력 억제**: 같은 키 연속 입력에 **최소 간격 90ms**를 둔다(원작도 한 프레임 연타로 숫자가 튀지 않게 디바운스가 있는 것으로 보임 — 추정). 90ms보다 빠른 재입력은 무시.
- 카운터 상한 **99**, 하한 0.
- 입력 가능 구간은 §2의 stream + 답 입력 유예(3b) 구간. 문제 제시·발표 중의 입력은 무시(카운터 리셋에 영향 없음).
- 한 마리를 센 순간 플레이어 플라밍고가 `jump` 0.18s + `sfx.tap`(플레이어별 `beep` 주파수 다르게: 1P 660, 2P 740, 3P 830, 4P 920Hz, 40ms).

## 4. 규칙과 점수

원작 확정 사항(Serebii · GameFAQs · Bulbapedia 일치):
- 라운드별 **만점**: R1·R2 = **10점**, R3·R4 = **20점**, R5 = **40점**. 합계 만점 **100점**.
- 정답과 **1~2 차이**면 **최소 1점** 이상 부분 점수("If you are 1-2 points off, you will still earn at least one point"). 3 이상 차이 = 0점.
- 감점 없음(음수 없음).
- **5라운드 합계 최다 득점 승.**
- 문제가 **속임수**를 쓴다: 후반엔 타깃 종이 **2종**이 되거나(둘 다 세야 함), 비슷한 다른 종이 섞여 나옴("Be sure to read the question carefully, because they may try to deceive you by throwing in extra Pokemon!").

부분 점수 수치(불명 — 추정):

| 오차 `|count − answer|` | R1·R2 (만점 10) | R3·R4 (만점 20) | R5 (만점 40) |
|---|---|---|---|
| 0 | 10 | 20 | 40 |
| 1 | 5 | 10 | 20 |
| 2 | 1 | 2 | 4 |
| ≥3 | 0 | 0 | 0 |

- 즉 `score = exact ? full : d==1 ? full/2 : d==2 ? full/10 : 0`.
- **원작 점수 예시**: 10+5+20+2+40 = 77점. CPU Hard는 70~90점대, 사람 초보는 20~45점대가 자연스럽다.
- **동점 처리(원작 확정)**: 스타디움 2 미니게임 공통 규칙으로 **1위 동점이면 퀴즈 문답 1문제로 승자를 가린다**(StrategyWiki "Ties will be broken by a question-and-answer round", PKMN.NET "face-off quiz question determines the ultimate winner rather than awarding each tied player a star"). 챔피언 모드 한정이 아니라 일반 미니게임에도 적용. 우리 구현은 포켓몬 퀴즈를 재현할 수 없으므로 **타이브레이크 = 추가 카운트 문제**(만점 10, 1종, R2 난이도 파라미터, 동점자만 채점·나머지는 관전)로 대체하고 최대 2회까지, 그래도 동점이면 셸의 동순위 표시로 마감. 플래그 `TIEBREAK=true`.
- 결과 `result()`: `{ scores: 합계 4개, text: '최고 ${max}점 / 정답 ${n}문제' }`, `lowerIsBetter` 없음.

## 5. 난이도 곡선 · CPU 난이도

원작 자료엔 "후반 라운드에 2종 세기·방해 포켓몬"만 기록됨. 라운드 설계(불명 — 추정, 영상 관찰 기준):

| 라운드 | 만점 | 타깃 | 타깃 수(정답) | 총 개체 수 | 방해 종 | 이동 속도 (px/s) | 등장 간격 | 특수 |
|---|---|---|---|---|---|---|---|---|
| 1 | 10 | 1종 | 5~8 | 12~16 | 없음(타깃과 색·포즈 모두 다른 종 1개만 섞임) | 220 | 0.55~0.9s | 스트림 ≈ 8~9s |
| 2 | 10 | 1종 | 7~11 | 16~22 | 다른 색 같은 포즈 1종 | 260 | 0.4~0.75s | 2개 동시 등장 확률 0.2 |
| 3 | 20 | 1종 | 9~14 | 22~30 | 같은 색 다른 포즈 1종 + **닮은 사물**(공/알, §1) 3~5개 | 300 | 0.3~0.6s | 동시 등장 0.35, 잠깐 멈췄다 되돌아가는 개체 1~2(왼쪽 밖으로 나가기 전 U턴 → 한 번만 세야 함) |
| 4 | 20 | **2종**("빨강 run + 파랑 run 합쳐서 몇 마리?") | 12~18 | 28~36 | 각 타깃의 유사종 각 1 + 닮은 사물 2~4개 | 340 | 0.25~0.5s | 동시 등장 0.5, 겹침(레인 교차) 허용 |
| 5 | 40 | **전부**("지나간 플라밍고 전부 몇 마리?") | 24~34 | = 정답(사물은 정답에 포함하지 않음, 사물 0~3개 섞임) | — (모든 종 등장) | 380 | 0.2~0.4s | 동시 등장 0.6, 3개 동시 등장 0.2, 속도 개체별 ±25% 편차 |

- 개체 속도는 표값 × `rand(0.85,1.15)` (R5는 ±25%). 레인은 등장 시 무작위, 뒤 레인(y 작음)이 먼저 그려져 앞 레인이 가린다.
- 정답이 "0"이 되는 라운드는 만들지 않는다. 정답은 라운드마다 `rand` 정수(위 범위).
- **U턴 개체(R3~)**: 화면 중앙 x∈[300,600]에서 0.4s 정지 → 오른쪽으로 되돌아가 사라짐. 정답에는 **1마리로 포함**(화면에 "지나간" 것으로 간주 — 불명 — 추정. 리뷰어 참고: 원작에서 되돌아가는 개체가 있는지 확실치 않으므로 `UTURN` 플래그로 제어, **기본값 false** — 비평가: 어떤 출처에도 되돌아가는 개체 언급이 없음).

**CPU 난이도**(원작 확정: 자유 대전(미니게임 단독 플레이)은 **Easy / Normal / Hard 3단계**(Serebii·StrategyWiki). **Very Hard는 미니게임 챔피언십(연속전) 해금 모드**에서만 존재 — StrategyWiki "Mini-Game Championship › Very Hard Mode". "Hyper"는 스타디움 2에 없음. 우리 구현은 4단계 모델을 그대로 두되 기본 배분은 3단계 안에서만 고른다). CPU는 무리를 "관찰"하는 게 아니라 **정답을 알고 오차를 주입**하는 모델(§8). 라운드가 어려울수록(총 개체 수·방해종) 오차 폭이 커진다. 정답률 수치는 추정.

| 난이도 | 정답 확률(R1) | 정답 확률(R5) | 오차 분포 |
|---|---|---|---|
| Easy | 0.35 | 0.10 | ±1: 0.35, ±2: 0.2, ±3~5: 나머지 |
| Normal | 0.55 | 0.25 | ±1: 0.3, ±2: 0.12, 그 외 |
| Hard | 0.75 | 0.45 | ±1: 0.2, ±2: 0.05 |
| Very Hard | 0.90 | 0.70 | ±1: 0.08, ±2: 0.02 |

- 셸에 난이도 선택이 없으면 **Normal**을 기본으로 하고, 슬롯 index별로 살짝 다르게(2P Normal, 3P Hard, 4P Easy — Very Hard는 기본 배분에서 제외, 상수 `CPU_LEVELS`로 교체 가능) 배분해 순위가 매번 같지 않게 한다. CPU도 답 입력 유예(§2 3b) 동안 마지막 1~2회를 누르는 경우가 있어야 자연스럽다(§8 6).

## 6. 화면 구성

- **카메라**: 정면 고정(횡스크롤 없음). 무리가 오른쪽→왼쪽으로 지나가는 **횡단 뷰**.

## 8. AI 행동 모델 제안

CPU는 실제로 화면 개체를 감지하지 않고, 라운드 시작 시 **자기 '최종 답' `target`을 미리 정한 뒤** 무리가 지나가는 동안 그럴듯한 타이밍으로 A를 "누른다"(숫자 패널이 실시간으로 오르게).

1. 라운드 시작 시 난이도별 `pCorrect(round)`(§5 표, R1→R5 선형 보간)로 정답 여부 결정. 오답이면 오차 분포에서 `±k` 뽑아 `target = clamp(answer ± k, 0, 99)`.
2. 무리의 각 타깃 개체가 **화면 x=480(중앙)을 지나는 순간** + 반응 지연 후 A를 1회 누른다. 반응 지연: Easy 420±140ms, Normal 300±100, Hard 220±70, Very Hard 150±40 (정규분포, 하한 60ms).
3. `target > answer`면 초과분만큼 **방해 개체**가 중앙을 지날 때도 누른다(방해 개체가 부족하면 임의 시점에 추가). `target < answer`면 타깃 개체 중 무작위 `answer − target`마리를 건너뛴다(빠른 동시 등장 개체를 우선 건너뛰어 자연스럽게).
4. 실수 확률(두 번 누르기·헛누름) `pSlip`: Easy 0.06 / Normal 0.03 / Hard 0.015 / Very Hard 0.004 — 개체 1마리당. 슬립이 나면 그 라운드는 `target` 대신 실제 누른 수가 답이 된다.
5. Easy는 `ALLOW_UNDO` 시에도 B를 쓰지 않음. Hard 이상은 슬립 발생 후 0.5s 내 확률 0.6으로 B로 정정.
6. **답 입력 유예 활용**: 스트림 종료 시점에 CPU 카운터가 `target`에 못 미치면(건너뛴 개체·지연으로) 유예(`ANSWER_GRACE`) 안에 남은 횟수를 0.25~0.45s 간격으로 눌러 `target`에 맞춘다(R5에서 Hard 이상이 눈으로 세고 나중에 입력하는 원작 공략을 흉내). Easy/Normal은 확률 0.5로만 보정.

2. **[확정] 답 입력 유예의 존재(재확인, 원문 인용)**: GameFAQs Mini-Game FAQ 원문 — "For the final grouping, it is easier to count the Pokemon first, then enter the number in after they pass." → 개체가 지나간 **뒤에** 숫자를 입력할 수 있다는 것이 확정. §2 3b(유예 3.0s)는 유지. 단 원문 뉘앙스상 유예가 "잠깐"이 아니라 답을 다 입력할 만큼 넉넉하므로, **유예 길이를 3.0s → `ANSWER_GRACE = 4.0s`** 로 늘리고 R5(정답 24~34, 0.25s 간격으로 30회 입력 ≈ 7.5s 필요)에서는 **6.0s**로 둔다. 유예 중 A 연타 간격 하한은 §3의 90ms 그대로.
3. **[확정] 무대·연출 문구**: GameFAQs "count the Pokemon visiting the studio", 닌텐도 JP "スタジオにかけつけたポケモン達" → 포켓몬이 **스튜디오로 달려 들어온다**. 1차 보강 7번(스튜디오 조명·관객석)을 유지하고, 각 라운드 첫 개체 등장 직전 0.3s 동안 오른쪽 가장자리에 흙먼지 원 3개(`rr` 대신 원, 알파 0.5)를 그려 "달려 들어오는" 예고를 준다.
4. **[확정] 마지막 라운드의 밀도 = '스트림'**: GameFAQs "the last round is crazy, as you'll have to tally the **streams** of Pokemon that waddle past" → R5는 낱개가 아니라 **줄(스트림)이 여러 가닥** 지나가는 밀도. §5 R5 값(정답 24~34, 동시 등장 0.6, 3개 동시 0.2, 레인 3개 전부 사용)은 이 서술과 부합하므로 유지. R1~R2는 "simply picking Pokemon out of the crowd" → 낱개가 드문드문 지나가는 느낌(§5 R1 등장 간격 0.55~0.9s 유지).
5. **[수정] 이동 모션의 손맛**: 원문 동사가 "walks across"(Serebii) · "waddle past"(GameFAQs)이므로 **달리기(run)가 아니라 뒤뚱걸음**. 플라밍고 종 ①②의 포즈 `run`은 유지하되(구분용), **이동 중 상하 바운스 진폭 4px·주기 0.35s**의 뒤뚱 오프셋을 모든 종에 공통으로 준다. 속도는 §5 표 유지(960px 횡단에 2.5~4.4s = 뒤뚱거리며 지나가는 체감).
6. **[확정] 게임 종료 조건·승패 문구**: "Get the highest score to win"(GameFAQs), "players who have the most points after five rounds wins"(Bulbapedia). 종료 = 5문제 완료, 시간 제한 없음. §2와 일치.
7. **[확정] 부분 점수 문구 재검증**: "Even if you don't get the right answer, you could still earn points for getting close"(GameFAQs) + "points will decrease the further you are away"(StrategyWiki) + "1-2 off → at least one point"(cheatcodes/Psypokes). 세 문구 모두 §4 표(만점/½/만점의 1/10/0)로 만족. **오차 3 이상 = 0점**은 "1-2 off"가 한계선으로 명시돼 있어 타당. 유지.
8. **[확정] 조작은 A 하나뿐**: Serebii·StrategyWiki 조작표 모두 "A: Count"만. `ALLOW_UNDO=false` 기본 재확인. howto의 B 문구 없음.
9. **[추가] 문제 유형 순서 고정**: 확인된 유형(단일 종 / 유사종·사물 혼입 / 2종 합산 / 전부)을 §5 표대로 R1·R2 단일, R3 단일+혼입, R4 2종, R5 전부로 **고정**(무작위 순서 금지). 원문 "first couple rounds are easy… last round is crazy"의 난이도 곡선과 일치.
10. **[추가] 종 목록(원작 확인분)**: 피카츄, 찌리리공(+몬스터볼 페인트), 토게피(+알 페인트) 3종만 확인. 나머지는 불명. 플라밍고 6종 대체안 유지. 페인트 사물은 **반드시 타깃 종과 같은 색**이어야 원작의 "本気のフェイント"가 재현된다(§1 표: 초록 ball↔초록 공, 노랑 fly↔노란 알).
11. **[추가] 4인 화면 배치의 근거**: 원작 자료 어디에도 분할 화면 언급 없음 + "walks across the screen" 단수 화면 → **단일 공유 화면**에 4명이 하단에 나란히 앉는 §6 배치 확정. 각 플레이어 숫자 패널은 라운드 내내 항상 보이며(계약 "각 플레이어 상태 상시 표시"), 누적 점수도 패널 옆에 상시.
12. **[추가] 라운드 사이 점수 누적 표시**: 정답 발표 시 누적 점수가 0.6s 동안 이전 값→새 값으로 카운트업(`sfx.count`를 5회 이내로 분할 재생). 원작의 점수판 갱신 리듬을 흉내.
13. **[보강] 효과음 매핑**: 카운트 1회 = `sfx.tap`(플레이어별 beep 주파수 §3), 유예 종료 = `sfx.tick`, 정답 발표 드럼롤 = `sfx.beep(200,…)`×4, 정답 = `sfx.good`, 0점 = `sfx.bad`, 최종 = `sfx.win`. 신규 셸 사운드 불필요.
14. **[확정] 동점**: StrategyWiki 원문 "Ties will be broken by a question-and-answer round"(미니게임 전체 공통). §4 대체안(추가 카운트 문제, 최대 2회) 유지.

**여전히 불명(추정 유지)**: 진행 방향(우→좌), 레인 수(3), 라운드별 개체 수·속도 수치, 각 구간 정확한 초 수, 입력 디바운스, CPU 실제 정답률. 모두 상수/플래그(`ANSWER_GRACE`, `UTURN`, `ALLOW_UNDO`, `TIEBREAK`, `CPU_LEVELS`)로 노출해 리뷰어가 영상과 대조해 조정할 수 있게 한다.

**빌드 가능 판단(2차)**: 규칙·조작·점수·종료 조건·난이도 곡선·화면 배치·연출 타이밍·CPU 모델이 모두 수치로 채워져 있고, 원문과 모순되는 서술은 위 1·2·5번에서 수정됨. 이 문서만으로 구현 가능.
