# barrier — 배리어 볼 (원작: Barrier Ball / バリヤードのバリアーテニス, Pokémon Stadium 2 · N64)

> 이 문서만으로 게임을 재구현할 수 있도록 작성. **[확인]** = 복수 출처 일치, **[출처 1개]** = 단일 출처, **불명 — 추정:** = 출처가 침묵하여 원작 영상 기억·4인 퐁(Pong) 관례로 정한 값. 구현자는 추정 값을 상수로 빼 두고, 리뷰어는 §10 유튜브 영상과 비교한다.
> 좌표/시간은 셸 캔버스 960×540 기준(`g.W`, `g.H`). 게임 id `barrier`, 파일 `games/barrier.html`.

## 1. 한 줄 요약 · 등장 포켓몬 · 플라밍고 대체안

**한 줄 요약 [확인]**: 정사각형 코트의 네 변에 마임맨(Mr. Mime) 4마리가 한 마리씩 서서, 자기 앞의 **배리어(Barrier, 반투명 판)** 를 좌우로 움직여 몬스터볼을 튕겨낸다. 볼을 **남의 변(골)** 에 넣으면 +1, 내 변에 들어오면 −1. **60초** 안에 **먼저 5점**을 내거나, 시간 종료 시 최다 득점자가 승리. "마임맨 4인 퐁(Pong)".

원작 명칭: 영문 *Barrier Ball*, 일문 *バリヤードのバリアーテニス*(마임맨의 배리어 테니스) [확인]. 스타디움 2 미니게임 12종 중 5번째 슬롯(StrategyWiki 순서) [확인]. 코트는 대각선으로 4진영 분할(§6).

**등장 포켓몬 [확인]**: 마임맨(Mr. Mime) ×4 (트랜스퍼팩으로 자기 마임맨 참가 가능, 외형·성능 동일). 소품: 몬스터볼(빨강/흰), 배리어(반투명 판), 중앙 볼 발사 장치.

| 원작 요소 | 역할 | 플라밍고 대체안 (셸 포즈) |
|---|---|---|
| 마임맨 ×4 | 플레이어. 자기 변을 따라 좌우 이동, 앞에 배리어를 띄움 | 플라밍고 ×4, `palette.players[i]` 색. 정지 `idle`, 이동 중 `run`(이동 방향으로 `flip`), 스매시(A) 순간 `hit` 0.25s, 득점 시 `jump` 0.6s, 실점 시 `dizzy` 0.8s, 종료 1위 `fly`, 꼴찌 `sleep`. 플라밍고는 코트 변 **바깥쪽**에 정면 스프라이트로 서고 회전하지 않는다(§6 배치 참고) |
| 배리어(Barrier) | 패들. 마임맨 앞 반투명 판, 마임맨과 함께 이동 | 플레이어 색을 alpha 0.45로 칠한 둥근 사각형(`rr`) + 흰 테두리 1.5px. 스매시 순간 0.12s 동안 alpha 0.9·두께 1.5배로 번쩍임(`harden` 느낌의 색 `#9C8AA5`를 테두리에 덧칠) |
| 몬스터볼 | 공. 마지막으로 친 플레이어 색의 링(aura)이 둘러싼다 | 흰 공(반지름 9px)에 분홍 띠(플라밍고 알처럼 보이게) + **마지막 타자 색 링**(반지름 14px, 두께 3px). 갓 발사된 공은 **흰 링** |
| 중앙 발사 장치 | 코트 중앙에서 공을 튀겨 올려 내보냄 | 코트 중앙의 회색 원판(반지름 22px), 발사 시 0.2s 동안 확대(1.0→1.3→1.0)와 `sfx.pop` |
| 골(각 변 전체) | 공이 변을 완전히 넘어가면 골 | 각 변 뒤 폭 18px 띠를 해당 플레이어 색(alpha 0.35)으로 칠함 |

## 2. 인원 · 시간 · 라운드

- **4인 동시** 플레이, 빈 슬롯은 CPU [확인]. 셸 규칙대로 항상 4명 생성.
- **제한 시간 60초** [확인: StrategyWiki]. **구현은 `duration: 0`** 으로 두고 게임이 자체 60초 타이머를 돌린 뒤 `g.finish()`를 부른다(셸 `duration`을 쓰면 시간 종료 순간 셸이 즉시 순위 화면으로 넘어가 "끝!" 연출을 못 넣고, 셸 타이머 HUD와 §6 타이머가 이중으로 그려지므로 — §12-1 참고).
- **조기 종료**: 누군가 **5점** 도달 즉시 정지 [확인]. 5점 달성 프레임에 공·입력을 멈추고 1.2s 승리 연출 후 `g.finish()` 호출(`finish()`는 즉시 순위 화면으로 전환되므로 연출은 그 전에 게임 안에서 끝낸다).
- 라운드 구조: 단판 1라운드. 세트/리셋 없음. 골이 나도 코트는 멈추지 않고 나머지 공은 계속 굴러간다 [확인: TheGamer "There are no breaks in the action"]. 코트에 공이 하나도 없어지면 **즉시** 새 공이 발사된다 [확인: TASVideos].
- 동점: 원작은 미니게임 모드 공통 규칙으로 "퀴즈 라운드"가 동점을 깬다 [확인: StrategyWiki]. 우리 구현은 공동 순위(셸이 같은 점수를 같은 순위로 표시).

## 3. 조작

**원작 N64 입력**
| 버튼 | 동작 | 출처 |
|---|---|---|
| 컨트롤 스틱 좌/우 (또는 십자키) | 자기 변을 따라 좌우 이동. 아날로그 기울기만큼 속도 | [확인: StrategyWiki·Serebii·GameFAQs] |
| **A** | 배리어를 **앞으로 밀기(push) = 스매시**. 배리어에 공이 닿아 있을 때 누르면 더 세고 빠르게, 이동 중이면 **커브**가 걸려 날아간다 | [확인: Serebii "put more force and curve if you're in motion", GameFAQs "hit a smash"] |
| B, C버튼, L/R, Z | 사용 안 함 | [확인 — 어느 출처도 언급 없음] |
| 스틱 상/하 | 사용 안 함(변에서 벗어나지 못함) | **불명 — 추정** |

**우리 액션 매핑**
| 우리 액션 | 동작 |
|---|---|
| `left` / `right` / `up` / `down` (down, 홀드) | 자기 변을 따라 이동. 홀드형. **화면 기준** 방향으로 매핑한다: 상·하 변 플레이어(1P·2P)는 `left/right`가 x축 이동, 좌·우 변 플레이어(3P·4P)는 `up/down`이 y축 이동. 쓰지 않는 축의 입력은 무시(원작은 스틱 기울기 하나로 "자기 변 방향"만 움직임) |
| `a` (hit) | 스매시. 누른 프레임부터 0.12s 동안 "스매시 판정 창" 활성. 창 안에서 공이 배리어에 닿으면 강타. 창이 지나도 공이 닿지 않으면 그냥 소모(헛스윙 페널티 없음) |
| `b` | 미사용(A와 동일 동작으로 받아줘도 무방 — **추정**) |
| `axis().x / .y` | 아날로그 속도(키보드는 ±1) |

**입력 규칙**
- 이동은 홀드. 반대 방향 동시 입력 → 정지. 배리어(패들)는 항상 플레이어와 함께 움직인다.
- 스매시는 **연타 무효 아님, 그러나 쿨다운 0.25s** (**불명 — 추정**; 원작에서 A를 연타하면 배리어가 계속 앞뒤로 들썩이지만 매번 강타가 나오지는 않음). 쿨다운 중 `hit`은 무시.
- 스매시 애니메이션: 배리어가 코트 안쪽으로 10px 밀려 나갔다가(0.06s) 돌아온다(0.12s).
- 실점 후 `dizzy` 0.8s 동안 **이동 속도 50%**, 스매시 불가 (**불명 — 추정**; 원작 마임맨은 실점 시 뒤로 자빠지는 모션이 있고 그동안 조작이 둔하다).

## 4. 규칙과 점수

- **점수 단위: 골 수(정수)** [확인]. HUD는 각 플레이어 색으로 0~5.
- **득점 +1**: 공이 **남의 변**을 넘어가면, 그 공을 **마지막으로 친(배리어에 닿은) 플레이어**가 +1 [확인: StrategyWiki — "1P가 쳤지만 2P 배리어에 튕겨 3P 골에 들어가면 2P 득점"]. 공의 링 색 = 마지막 타자 = 득점자.
- **실점 −1**: 공이 **내 변**을 넘어가면 나는 −1. 단 **0점이면 감산 없음(0 클램프)** [확인: Bulbapedia "lose a point if … not at zero points"].
- **자책골**: 내가 마지막으로 친 공이 내 변으로 들어오면 → 나는 −1만 받고 +1은 없음 [확인: Bulbapedia "into their opponents' goal … to score", PKMN.NET "if you let one in, you lose a point"].
- **흰 공(아직 아무도 안 친 공)** 이 내 변에 들어오면 나 −1, 아무도 +1 없음 [확인: StrategyWiki].
- 공이 배리어에 닿는 순간 링 색이 바뀐다. 코트 **벽/모서리에 튕겨도 링 색은 유지**(**추정**).
- **승리 판정**: 5점 선착 즉시 승리, 아니면 60초 종료 시 최다 점수 [확인]. `result()` → `{ scores:[점수×4] }`, 높을수록 좋음. 동점은 공동 순위.
- **원작 점수 예시**: 5:2:1:0 같은 스코어가 전형. 종료 화면은 "1P Wins"처럼 승자 호명 [확인: TASVideos] → 우리는 "1P 승리!". 일본 플레이어 후기 "3점쯤은 넣지만 후반에 펑펑 먹혀서 지는 패턴이 많다" [출처 1개: note.com]. 60초를 다 쓰는 경기가 5점 조기 종료보다 흔하다(**추정**).

## 5. 난이도 곡선

**시간에 따른 변화(모든 난이도 공통)**
- **동시 공 개수가 시간에 따라 증가** [확인: StrategyWiki "There will be more Poké Balls on the field at one time as the game progresses", TheGamer]. 원작은 "최대 개수 타임라인"이 아니라 **무작위 간격으로 공이 추가 발사**되는 방식이며, 코트에 공이 0개가 되면 **즉시** 발사된다 [확인: TASVideos "Balls spawn at random intervals. Multiple balls can be in play. If no balls are in play … a new ball spawns immediately"]. 첫 두 공의 발사 위치·시점은 고정(시드) — 두 번째 공이 7초 안에 나올 수 있다 [확인: TASVideos]. → **구현 모델(§11 참고)**: 첫 공 t=0, 둘째 공 t=5s 고정, 이후 `interval = clamp(9 − 0.12·t, 4, 9)`s ± 1.5s마다 추가 발사, 동시 최대 4개(추정). 골로 공이 사라졌을 때 남은 공이 0개면 즉시, 아니면 다음 간격을 기다린다.
- **발사**: 중앙 발사 장치에서 **무작위 각도**(단, 어느 변에 정확히 수직으로 가지 않도록 각 축 ±12° 제외 — **추정**)로, 초속 **220 px/s**(**추정**; 코트 폭 420px를 약 2초에 횡단하는 원작의 느긋한 첫 공 속도 기준). 발사 후 0.5s 동안은 골 판정 없음(발사 직후 사고 방지 — **추정**).
- **공 속도**: 배리어에 튕길 때마다 **×1.06**, 스매시면 **×1.5** 후 상한 **620 px/s** (**추정**). 벽 반사에는 변화 없음. 공은 마찰 없이 등속(**추정**; 원작은 살짝 감속하는 듯 보이지만 무시 가능).
- **커브**: 스매시 시 플레이어 이동 속도의 **35%** 를 공의 접선 방향 속도로 더한다(Serebii "curve if you're in motion"을 단순화; 실제 곡선 궤적은 없고 각도가 꺾이는 방식으로 표현 — **추정**).
- 일반 반사(스매시 아님): 배리어 중심에서 맞은 위치에 따라 반사각을 ±40° 조정(퐁 관례 — **추정**).

**CPU 난이도(원작 등급: Easy / Normal / Hard, 언락 Very Hard) [확인: StrategyWiki]**. Hyper는 Stadium 1 계열 등급이며 Stadium 2에는 없다 — 요청에 따라 Very Hard 위 확장 등급으로 정의. 행동 차이는 §8 수치 참고. 요지: Easy는 공을 따라가다 늦고 스매시를 거의 안 씀, Hard 이상은 공 궤적을 예측해 미리 기다리고 스매시로 빈 변을 노린다.

## 6. 화면 구성

- **카메라**: 약간 기울어진 **탑다운**(원작은 코트를 위에서 비스듬히 내려다보는 3D 고정 카메라). 우리는 순수 탑다운 2D로 그리고, 코트 바닥에 원근 느낌의 타일 그라데이션만 준다. 스크롤 없음.
- **코트**: 정사각형. 중심 (480, 290), 한 변 **420px** → x 270~690, y 80~500. 코트는 **두 대각선으로 4개의 삼각형 진영**으로 나뉜다 [확인: PKMN.NET "a court split in diagonals"] — 각 삼각형을 그 변 플레이어 색(alpha 0.18)으로 칠하고 대각선을 흰 선(1px, alpha 0.5)으로 긋는다. 중앙 원(반지름 40px). 코트 바깥은 어두운 관중석 느낌(`#2e3a4f`)에 점 조명.
- **플레이어 배치 [불명 — 추정: 1P 하단(남) 확정, 나머지 배치는 영상 기억]**:
  - 1P: 하단 변(y=500), x 이동. 2P: 상단 변(y=80). 3P: 좌측 변(x=270), y 이동. 4P: 우측 변(x=690).
  - 플레이어(플라밍고 scale 1.3)는 변 **바깥쪽 24px** 위치, 배리어는 변 **안쪽 14px** 위치. 플라밍고는 회전하지 않고 항상 정면 스프라이트(`flip`으로 이동 방향만 표시) — 원작은 마임맨이 코트를 향하지만 셸 스프라이트 특성상 정면으로 둔다.
  - **배리어 크기**: 길이 **96px**(변의 약 23%), 두께 12px (**추정**). 이동 범위: 변 끝에서 끝까지(배리어가 코트 밖으로 나가지 않도록 클램프).
  - **이동 속도**: **300 px/s** (**추정**; 원작 마임맨이 변 하나를 약 1.4초에 횡단).
  - 코트 **모서리**(각 변 끝 30px 구간)는 골이 아니라 벽으로 반사(**불명 — 추정**; 원작에서 모서리 기둥이 있어 공이 튕김).
- **골 판정**: 공 중심이 변 좌표를 넘어가면(공 반지름 무시) 골. 배리어와의 충돌은 원-사각형 충돌.
- **HUD**:
  - 네 모서리에 플레이어 점수 박스: 1P 좌하(40, 500), 2P 좌상(40, 40)… **추정** → 우리는 배치와 맞게 **각 플레이어 변 옆**에 둔다: 1P 하단 중앙 아래(480, 528), 2P 상단 중앙 위(480, 30), 3P 좌측(120, 290), 4P 우측(840, 290). 각 박스: `drawPlayerTag` + 큰 숫자(32px, 플레이어 색), 5점 만점 표시 "3 / 5".
  - **타이머**: 셸 HUD와 같은 자리·서체(좌상단 x=16, y=32, bold 22px, `palette.ink`)에 `남은 시간 42.0s`. 화면 상단 중앙은 2P 점수 박스가 쓴다. 10초 이하 빨강 + `sfx.tick` 매초. (`duration: 0`이므로 셸은 타이머를 그리지 않는다 — §12-1)
  - 공이 골에 들어갈 때 해당 변 옆에 "+1"(득점자 색) / "−1"(빨강) 팝업 0.8s.
- **색감**: 원작은 밝은 파스텔 코트 + 마임맨의 분홍/파랑. 우리는 민트 코트, 플레이어 색 배리어, 흰/분홍 공. 채도 중간, 배경만 어둡게 해 공이 잘 보이게.
- 텍스트는 전부 한국어.

## 7. 연출

- **시작**: 원작 아나운서 "Ready… Go!". 우리: **셸이 3·2·1 카운트다운과 "GO!"(0.8s)를 그려 주므로 게임은 별도 "준비…/시작!" 텍스트를 만들지 않는다.** `update()` 첫 호출(=GO 시점)부터 60초 타이머를 시작하고 첫 공을 즉시 발사(`sfx.pop`). 카운트다운 중에는 `update()`가 불리지 않으므로 위치 선점은 없다(원작과의 차이는 무시 가능).
- **공 발사**: 중앙 원판이 0.2s 부풀며 `sfx.pop`, 공이 중앙에서 나타나 0.15s 동안 scale 0.4→1.0.
- **배리어 반사**: `sfx.tap`, 배리어가 플레이어 색으로 0.08s 번쩍, 공 링 색 변경.
- **스매시 성공**: `sfx.hit`, 플레이어 `hit` 포즈 0.25s, 공 뒤에 0.25s 잔상(3개, alpha 감소), 배리어 흰 섬광.
- **득점(남의 골)**: 득점자 `jump` 0.6s, `sfx.good`, 골 띠가 득점자 색으로 0.4s 깜빡, "+1" 팝업. 실점자는 동시에 `dizzy` 0.8s, `sfx.bad`, "−1" 팝업(0점이면 "0" 유지, 팝업 없음).
- **흰 공 실점**: 실점자만 `dizzy` + "−1", `sfx.bad`.
- **공 추가 발사(무작위 간격, §5·§11)**: 별도 텍스트 없이 공만 하나 더 발사(원작도 알림 없음 — **추정**).
- **5점 도달**: 즉시 정지, 중앙 "1P 승리!"(승자 색, 원작 "1P Wins") 1.2s, 승자 `fly`, 나머지 `idle`, 꼴찌 `sleep`. 그 뒤 `g.finish()` → 셸 순위 화면(승패 효과음은 셸이 낸다).
- **시간 종료**: 자체 타이머가 0이 되면 공·입력 정지, 중앙 "끝!" 1.0s(`sfx.win`은 셸 `finish()`가 울리므로 게임은 울리지 않음), 위와 같은 포즈. 그 뒤 `g.finish()`.
- **아나운서 대사 요지(원작)**: "Ready, Go!", 골마다 짧은 감탄사, 종료 시 "Finish!"와 승자 호명. 우리는 텍스트 "시작!", "끝!", "5점! 승리!" 만.

## 8. AI 행동 모델 제안

CPU는 매 프레임 "자기 변으로 다가오는 공"(속도 벡터가 자기 변을 향하는 공) 중 **도착 예정 시간이 가장 짧은 공**을 목표로 고른다. 목표 지점은 그 공이 자기 변에 닿을 때의 좌표(벽 반사 1회까지 예측, 등급에 따라 예측 여부 다름). 목표까지 이동하되 **반응 지연**만큼 늦게 갱신하고, **조준 오차**를 더한다. 공이 배리어 도달 **0.10s 전**이면 `smash` 확률로 A를 누른다. 다가오는 공이 없으면 변 중앙으로 천천히(속도 50%) 복귀.

| 난이도 | 반응 지연 (ms) | 조준 오차 σ(px) | 궤적 예측 | 스매시 확률 | 실수 확률(엉뚱한 방향 0.3s) | 예상 결과(60s) |
|---|---|---|---|---|---|---|
| Easy | 420 ± 120 | 34 | 없음(공 현재 x/y만 추적) | 0.10 | 0.10/s | 0~1점, 실점 많음 |
| Normal | 280 ± 80 | 22 | 벽 반사 0회(직선) | 0.35 | 0.05/s | 1~2점 |
| Hard | 180 ± 50 | 12 | 벽 반사 1회 | 0.65 | 0.02/s | 2~4점 |
| Very Hard | 110 ± 30 | 6 | 벽 반사 1회 + 빈 변 조준 | 0.85 | 0.005/s | 4~5점 |
| Hyper(확장) | 60 ± 15 | 3 | 완전 예측 + 빈 변 조준 | 1.00 | 0 | 5점 조기 종료 |

- **빈 변 조준**(Hard 이상): 스매시 시 배리어 접촉 위치를 살짝 이동시켜 반사각을 "배리어가 가장 멀리 떨어진 상대 변"으로 유도. 이동 속도 커브(§5)도 활용.
- 조준 오차는 목표 갱신 시마다 정규분포로 새로 뽑고, 공이 가까워질수록(도달 0.4s 이내) 오차를 절반으로 줄인다(마지막 순간 보정).
- **실수**: 확률 발생 시 0.3s 동안 반대 방향으로 이동(Easy CPU가 헛움직이는 원작 느낌).
- 여러 공이 동시에 올 때 Easy/Normal은 최근접 공만, Hard 이상은 두 번째 공 위치를 고려해 중간 지점에서 대기(간단히 두 목표의 가중 평균 0.7:0.3).
- 셸이 난이도를 노출하지 않으면 기본 **Normal**, 슬롯별로 Normal/Hard/Normal 처럼 섞어 CPU 간 격차를 만든다.

## 11. 비평가 보강

독립 확인 출처: Bulbapedia(Barrier Ball · Stadium series mini-games), Serebii, PKMN.NET, TASVideos #9382(Mini-Game Champion TAS 제출문), TheGamer, 楽天ブログ GAME FIELD, StrategyWiki·GameFAQs(검색 요약; 본문 403). 아래는 원 스펙과 다르거나 빠져 있어 **원작과 다르게 느껴질** 항목을 고친 것이다. 항목마다 원 스펙 §를 표기.

1. **공 추가 방식 정정(§2·§5)** — 원 스펙의 "15/30/45s에 최대 개수 증가" 모델은 근거 없음. 원작은 **무작위 간격으로 공이 계속 추가**되고, **코트에 공이 0개면 즉시 발사**된다 [TASVideos 확인]. 첫 두 공은 시드 고정이며 두 번째 공이 7초 이내에 나올 수 있다. 구현 상수: `SPAWN_FIRST=0`, `SPAWN_SECOND=5.0`, 이후 간격 `clamp(9 − 0.12·t, 4, 9) ± 1.5`s, `MAX_BALLS=4`(추정). 골 후 재발사 지연 1.2s 규칙은 삭제 → 공 0개면 **즉시**(0.3s 연출만), 아니면 간격 타이머대로.
2. **템포 가속(§5)** — "every point scored will accelerate the pace" [TheGamer]. 시간뿐 아니라 **총 득점 수**에 따라 빨라진다: 공 초속 `220 + 25·(전체 골 수) + 2·t` px/s(상한 420), 배리어 반사 ×1.06, 스매시 ×1.5, 절대 상한 620 px/s. 원작의 "후반에 펑펑 먹힌다"는 체감(note.com)과 일치.
3. **코트 대각선 진영(§6)** — 코트는 두 대각선으로 4개 삼각형 진영으로 나뉘어 각 플레이어 색으로 구분된다 [PKMN.NET "court split in diagonals"]. 스펙 §6에 반영. 삼각형 색 = 그 변의 골 소유자 → 플레이어가 어느 변을 지키는지 한눈에 보인다(4인 퐁에서 가장 중요한 가독성 요소).
4. **플레이어 색(§1·§6)** — 원작 기본 색: 1P 파랑(StrategyWiki 예시 "Player 1 … blue"), 2P 빨강, 3P 초록, 4P 노랑(Stadium 2 공통). 우리는 셸 `palette.players[i]`를 그대로 쓰되, 공 링·진영·HUD·"+1" 팝업 모두 **같은 색 변수** 하나만 참조해 색 일치를 보장한다.
5. **1P 위치·시점(§6)** — GameFAQs 요약 "Player 1 … the southern section" → 1P 하단 확정. 2P 상단·3P 좌·4P 우 배치는 여전히 추정이나, 원작이 3D 비스듬한 카메라라 1P가 화면 앞(아래)에 오는 것과 맞는다. 유지.
6. **A 버튼 정의 명확화(§3)** — 모든 출처가 A 하나만 언급(Serebii "A: Hit", PKMN.NET "Press A to shoot", StrategyWiki "push with the barrier"). B·C·Z·L·R 미사용 확정. A는 "배리어를 앞으로 미는 동작"이며 **공이 닿아 있을 때만** 힘·커브가 붙는다 [Serebii]. 헛스윙 페널티 없음(출처 침묵 → 추정 유지). 커브는 "좌우로 움직이며 치면 변화구"(楽천ブログ, Serebii 일치) → 이동 속도의 35%를 접선 성분으로 더하는 §5 모델 유지. 스틱과 십자키 호환 [Bulbapedia].
7. **운 요소 없음(§5)** — "ボールの飛び方に運要素は無い"(楽天) → 반사각은 결정적(맞은 위치·이동 속도·스매시 여부만으로 결정). 무작위는 **발사 각도·시점**에만 둔다. TAS가 "공이 나에게 오도록 운 조작"했다는 점에서 발사 방향은 무작위가 맞다.
8. **종료 처리(§7)** — 5점 즉시 종료 [Bulbapedia·StrategyWiki 일치], 종료 화면 "1P Wins" [TASVideos] → 중앙에 "1P 승리!"(승자 색) 1.2s 후 셸 순위 화면. 동점(시간 종료·최다 동률)은 원작이 퀴즈로 결정하므로 우리는 공동 순위(셸 규칙) 유지 — 변경 없음, 확인만.
9. **점수 0 클램프 재확인(§4)** — "lose a point if … not at zero points" [Bulbapedia], "if you let one in, you lose a point" [PKMN.NET]. −1 팝업은 0점일 때 표시하지 않음(§7 유지).
10. **특수 아이템·장애물 없음** — 어느 출처도 특수 볼, 보너스, 장애물을 언급하지 않음. 몬스터볼 1종만. 코트 모서리 처리(벽 반사 30px)는 여전히 추정.
11. **CPU 모델 보정(§8)** — 원작 CPU 수치는 어느 출처에도 없음(추정 유지). 단 TAS가 Hard CPU 3명을 상대로 5골을 ~20초에 넣었다는 점에서, Hard CPU도 **자기 쪽으로 오지 않는 공에는 반응하지 않고** 빠른 스매시 공은 놓친다 → §8 표의 Hard 반응 지연 180ms·조준 오차 12px는 적절. Very Hard는 Mini-Game Champion에서 Hard 3명을 7코인 매치로 이겨야 언락 [Bulbapedia] — 셸에 난이도 선택이 없으므로 기본 조합 **Normal/Hard/Normal**(슬롯 2·3·4) 유지.
12. **여전히 불명(추정 유지)**: 배리어 길이 96px·두께 12px, 이동 속도 300px/s, 공 반지름 9px, 스매시 창 0.12s·쿨다운 0.25s, 실점 경직 0.8s, 최대 동시 공 4개, 아나운서 원문. 모두 상수로 빼 두고 §10 영상과 비교해 조정.

## 12. 비평가 보강 (2차 · 독립 검증)

독립 재확인 출처: Bulbapedia *Barrier Ball* 및 *Pokémon Stadium series mini-games*(본문 직접 열람), Serebii Stadium 2 mini-games(직접 열람), TASVideos #9382 제출문(직접 열람), note.com 후기(직접 열람). StrategyWiki·GameFAQs·Fandom·PKMN.NET은 403/402/리다이렉트로 본문을 열지 못해 1차 요약을 그대로 신뢰한다. 직접 열람으로 **재확인된 사실**: 마임맨 4마리·배리어로 몬스터볼을 상대 골에 넣으면 +1·먹히면 −1(0점이면 감산 없음)·"시간 종료 시 최다 점수 또는 5점 선착" [Bulbapedia 원문], 조작은 "Control Stick: Move Left/Right, A Button: Hit"·A는 힘과 커브 [Serebii 원문], 공은 무작위 간격 추가·코트에 0개면 즉시 발사·첫 두 공은 고정 시드·종료 화면 "1P Wins" [TASVideos 원문], Very Hard는 Hard 3명 상대 7코인 매치 승리로 언락·동점은 퀴즈 [Bulbapedia 원문]. 아래는 그 위에서 **빌드 시 원작과 다르게 느껴지거나 아예 동작하지 않을** 항목을 고친 것.

1. **셸 계약과 충돌하던 시작·종료·타이머 처리 정정(§2·§6·§7 인라인 수정)** — `common/stadium.js`를 읽어 보면 셸이 이미 3·2·1 카운트다운 + "GO!" 0.8s를 그리고, `duration>0`이면 좌상단(16,32)에 `42.0s` 타이머를 그리며, 시간이 0이 되는 순간 `finish()`로 **즉시** 순위 화면으로 넘어간다. 또 `finish()`는 호출 즉시 상태를 `end`로 바꾼다. 따라서 1차 스펙의 "준비…/시작!" 텍스트는 셸 카운트다운과 이중이고, "끝!" 1.0s·"5점! 승리!" 1.2s 연출은 셸 `duration`으로는 표시할 수 없었다. 수정: `duration: 0`, 게임이 `elapsed`를 자체 누적(`g.time`은 페이지 로드부터 계속 흐르므로 쓰지 말 것), 60초 도달 또는 5점 도달 시 `phase='ending'`으로 1.0~1.2s 정지 연출 후 `g.finish()`. 재시작 시 `init()`이 다시 불리므로 모든 상태(공 배열·타이머·phase)를 `init()`에서 리셋한다.
2. **플레이어 색 실제 값(§1·§6·§11-4 정정)** — 셸 `palette.players = ['#FF7BAC'(1P 분홍), '#5AA9FF'(2P 파랑), '#FFD166'(3P 노랑), '#4FD37A'(4P 초록)]`. 11-4의 "원작 1P 파랑…"은 참고일 뿐 우리는 셸 색을 쓴다. 코트 삼각형·배리어·공 링·HUD 숫자·"+1" 팝업이 전부 이 배열 하나를 참조.
3. **배리어 충돌 규칙(§6 보강, 빠져 있던 항목)** — 배리어는 **한 방향 충돌**: 공이 그 변을 **향해** 이동 중(1P: `vy>0`, 2P: `vy<0`, 3P: `vx<0`, 4P: `vx>0`)일 때만 반사하고, 반사 직후 공을 배리어 안쪽 면 밖으로 밀어낸다(관통·연속 다중 히트로 링 색이 깜빡이는 버그 방지). 같은 배리어에 0.1s 안에 다시 맞지 않는다. 배리어 길이 96·두께 12는 유지하되, **배리어 옆면(끝)에 맞으면 접선 성분을 뒤집어 옆으로 튕긴다**(퐁 관례; 원작에서도 배리어 끝에 걸린 공이 옆으로 새는 장면이 잦다).
4. **코트 모서리·정체 방지(§6 보강)** — 각 변 양 끝 30px는 벽(추정 유지). 벽 반사 후 공 속도 벡터가 **어느 축 성분이 전체 속도의 18% 미만**이면 그 축 성분을 18%로 올려 부호를 유지한다(모서리에서 무한 왕복·변과 평행하게 미끄러지는 정체 방지 — 4인 퐁에서 원작과 가장 다르게 느껴지는 지점). 발사 각도의 ±12° 제외 규칙도 같은 이유.
5. **공끼리 충돌 없음(§5 보강)** — 출처가 침묵. 원작에서 공 여러 개가 겹쳐 지나가도 서로 튕기는 연출은 기억에 없고 TAS도 언급 없음 → **공은 서로 통과**(추정). 구현 단순화 겸 원작 체감과 일치.
6. **골 판정 세부(§4 보강)** — 공 중심이 변 좌표를 넘는 순간 골. 골 판정은 발사 후 0.5s 뒤부터(1차 유지). **골이 난 공은 즉시 제거**(원작은 골 뒤쪽으로 사라짐), 같은 프레임에 두 공이 골에 들어가도 각각 독립 처리. 마지막 타자 정보는 공 객체 `last`(−1=흰 공)에 저장.
7. **다중 공 시 CPU 목표 선택(§8 보강)** — "자기 변으로 다가오는 공 중 도착 예정 시간이 가장 짧은 공"에서 도착 시간은 `dist_to_side / |v_normal|`. 벽 반사 예측은 접선 좌표를 코트 폭으로 "접어 되돌리는(reflect fold)" 1차 함수로 계산하면 1회 반사까지 한 줄로 끝난다. Hard 이상만 사용.
8. **CPU 공정성 상한(§8 보강)** — CPU 이동 속도는 사람과 같은 300 px/s(가속 없음, 즉시 최대 속도)이고, CPU의 스매시도 사람과 같은 0.12s 창을 쓴다. Very Hard/Hyper의 강함은 반응 지연·오차만으로 만든다(치트 없음). 반응 지연은 "목표 좌표를 `delay`초 전 공 상태로 계산"하는 방식(링 버퍼나 `lastSeenAt` 타임스탬프)으로 구현.
9. **시간·득점에 따른 템포(§5·§11-2 정리)** — 1차 보강의 두 식이 겹쳐 혼란스러우므로 최종 하나로 고정: 발사 초속 `v0 = min(420, 220 + 25·totalGoals + 2·elapsed)`, 배리어 일반 반사 ×1.06, 스매시 ×1.5, 절대 상한 620 px/s, 벽 반사·자유 비행 중 속도 불변. 추가 발사 간격 `clamp(9 − 0.12·elapsed, 4, 9) ± 1.5`s, 둘째 공 5.0s 고정, 동시 최대 4개, 코트에 0개면 0.3s 후 발사.
10. **입력 매핑 최종(§3 보강)** — 1P(하)·2P(상): `left/right`·`axis().x`. 3P(좌)·4P(우): `up/down`·`axis().y`(`up`=화면 위쪽). 관용으로 3P·4P에게 `left/right`도 받아 `left`=위, `right`=아래로 매핑한다(키보드 사람이 어느 키든 움직일 수 있게; 원작엔 없는 편의 — 추정). `b`는 `a`와 동일 동작.
11. **HUD·가독성(§6 보강)** — 각 플레이어 점수 박스는 자기 변 옆(1차 좌표 유지)이며, 박스 배경을 플레이어 색 alpha 0.25로 칠해 "내 변이 어디인지"를 항상 보이게 한다(계약 "각 플레이어 상태 항상 표시" 충족). 우상단은 셸이 비워 두므로(`duration: 0`이면 BEST도 안 그림) 그 자리에 코트 위 공 개수 `공 ×2`를 작게 표시(원작엔 없음, 추정 — 생략 가능).
12. **아이템·장애물·특수 룰 재확인** — Bulbapedia·Serebii·TASVideos 어디에도 특수 볼·보너스·장애물·파워업 없음. 몬스터볼 1종, 규칙은 +1/−1/5점/시간뿐. 확정.
13. **여전히 불명(추정 유지, 상수화)** — 2P/3P/4P 변 배치, 배리어 96×12, 이동 300 px/s, 공 반지름 9, 초속 220, 스매시 창 0.12s·쿨다운 0.25s, 실점 경직 0.8s(이동 50%), 최대 동시 공 4, 발사 간격 분포, 모서리 벽 30px, 아나운서 원문, CPU 수치 전부. 파일 상단 `const C = {...}` 한 곳에 모아 두고 §10 영상과 비교해 조정.
