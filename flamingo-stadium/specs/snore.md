> 이 문서만 보고 게임을 다시 만들 수 있어야 한다. 원작 유튜브 영상과 비교 검수됨.

## 1. 한 줄 요약 · 등장 캐릭터와 플라밍고 대체안

**한 줄 요약**: 4마리가 가운데 시계추(pendulum)를 둘러싸고 서서, 추가 중앙의 **빨간 바늘(red needle)** 을 지나는 **정확한 순간에 A**를 눌러 최면(Hypnosis)을 걸어 상대를 재운다. 타이밍을 놓치면 **자기가 코를 골며 졸린다**. 추는 점점 빨라지고, **마지막까지 깨어 있는 1마리가 승리**. [확인]

| 원작 요소 | 원작 표현 | 플라밍고 대체 (셸 포즈/소품) |
|---|---|---|
| 슬리프(Drowzee) ×4 | 코끼리코 노란 포켓몬, 팔을 흔들며 최면 | `drawFlamingo` 플레이어 4색. 대기 `idle`(살짝 흔들림) |
| Hypnosis 성공 동작 | 슬리프가 양팔을 앞으로 내밀고 눈에서 파동 | `harden` 포즈 0.35s(몸을 곧추세우는 "집중" 느낌) + 몸 중심에서 **보라/분홍 동심원 링 3개**가 0.5s 동안 퍼져 나감 |
| 실패(헛누름) → 코골이 | 슬리프가 "쿠울~" 하며 몸이 앞뒤로 휘청, `Zzz` 글자 | `dizzy` 포즈 + 머리 위 `Z z Z` 텍스트 상승(0.8s), 몸이 좌우 ±6° 흔들림 |
| 졸림 누적 | 슬리프가 점점 눈을 감고 몸이 흔들리며 Z 개수 증가 | 졸림 게이지 비례로 `idle`→(0.5 이상) `dizzy` 블렌드, `alpha`는 유지, 머리 위 떠다니는 Z 개수 = floor(졸림×3) |
| 잠듦(탈락) | 슬리프가 벌렁 누워 코를 곤다 | `sleep` 포즈 고정, 위에 커다란 `Zzz…` 반복 팝업(1.5s 주기), `drawPlayerTag`에 "잠듦" 부기 |
| 시계추 | 화면 중앙에 매달린 추, 중앙 빨간 바늘 [확인, serebii/koopatv] (노란 눈금 호는 GameFAQs 요약 근거 [추정]) | 그대로 재현: 금색 원판 추(반지름 ≈ 26px), 길이 ≈ 200px 막대, 밑에 노란 호 + 빨간 바늘 |
| 배경 | 어둡고 사이키델릭한 최면 소용돌이(보라·핑크·남색) | `bg` 위에 느리게 회전하는 동심 소용돌이(보라 #4a2a7a ↔ 핑크 #c85aa0), 회전 속도 12°/s |
| 승리 슬리프 | 제자리 춤 | `jump` 포즈 반복(0.6s 주기) |

## 2. 인원 · 시간 · 라운드

- **4인 동시 플레이** (사람 1~4명 + 나머지 CPU). 원작 Kids Club 공통. [확인]
- **제한 시간 없음**: 종료 조건은 **3마리가 잠들어 1마리만 남을 때**. [확인, serebii/bulbapedia]
  - 아무도 누르지 않으면 영원히 끝나지 않고 추만 계속 빨라진다(koopatv 실험) → **졸림은 시간이 아니라 "최면 피격"과 "헛누름"으로만 누적**된다. [확인]
- 실측 길이: 4인 전원 플레이 시 **보통 20~40초, 최대 약 40초**. [확인, koopatv] `duration: 0`으로 두고 게임이 `g.finish()` 호출.
- **라운드 구조 없음**, 단일 라운드. 단 CPU 3마리 무입력 상태를 막기 위해 안전장치: **90초 경과 시 졸림 게이지 낮은 순으로 순위 확정 후 강제 종료** [추정, 원작엔 없음].
- 사람 플레이어가 먼저 잠들어도 게임은 **끝까지 진행**(원작은 남은 슬리프끼리 계속 겨룸). 관전 시간을 줄이기 위해 사람 전원 탈락 후엔 시뮬레이션 속도를 1.5배로 해도 됨 [추정].

## 3. 조작 (N64 → 우리 액션)

| N64 | 원작 기능 | 우리 액션 | 비고 |
|---|---|---|---|
| **A** | Hypnosis 시전 (타이밍 입력) | **`a`** | 단발. `hit('a')`만 사용, 홀드 무효 |
| B, 스틱, C, Z, L, R | 없음 | (`b`도 A와 동일하게 받아줌 — 편의) [추정] | — |

- **타이밍 판정**: 추 각도 θ(t) = A·sin(φ), φ는 위상. 중앙 통과 순간은 φ = kπ. 입력 시각의 `|sin φ|` 를 오차로 쓴다.
  - **판정 기준 시각**: 입력 시각에 가장 가까운 중앙 통과 시각(직전 통과 또는 현재 ω로 예측한 다음 통과) 과의 시간차 `e`를 쓴다. ω는 통과 사이에 일정하므로 예측이 정확하다. 판정 창은 아래 각도 기준을 시간으로 환산한 값 `asin(x)/ω`에 프레임 하한을 씌운 것.
  - **PERFECT**: 오차 ≤ 0.12 (추가 바늘 폭 안) → 최면 성공(강)
  - **GOOD**: 0.12 < 오차 ≤ 0.30 → 최면 성공(약) [확인-부분: pokemon.fandom 요약 "최면은 추가 정중앙일 때 가장 강하고, 옆으로 치우친 때 누르면 아예 안 걸린다" → 원작도 위치에 따른 강약이 있음. 정확한 단계 수는 불명, 2단계로 재현]
  - 판정은 **좌우 대칭**: 바늘에 닿기 *전에* 눌러도 헛누름(GameFAQs: "바늘에 닿기 전에 누르면 지쳐서 코를 곤다"). [확인]
  - **프레임 하한**: 후반엔 각도 기준 창이 1프레임(16.7ms)보다 좁아지므로 실제 시간 창은 `max(각도창, ±17ms)`(PERFECT), `max(각도창, ±34ms)`(MISS 경계)로 클램프한다. 원작(N64 30fps)도 판정 해상도가 ≈33ms였다. [추정, §비평가 보강 참조]
  - **MISS**: 오차 > 0.30 → 헛누름(코골이)
- **통과(crossing)당 입력 1회만 유효**: 각 중앙 통과에 번호 k를 붙이고 입력은 가장 가까운 통과 k에 귀속된다. 이미 소비된 k에 붙는 두 번째 이후 입력은 **무시**(코골이 페널티도 없음) — 연타 방지. (2차 비평가: "반주기당"을 "통과당"으로 정밀화 — 바늘 직전에 누른 조기 입력은 *다음* 통과에 귀속돼야 대칭 판정이 성립한다.) [추정; 원작에서 연타하면 "리듬 맞으면 괜찮고 틀리면 더 빨리 잔다"는 증언(koopatv)과 정합]
- **코골이 스턴 중** 입력은 전부 무시. (serebii: "실패하면 슬리프가 두어 번 흔들릴 동안 잠든다") [확인]
- 시작 카운트다운("준비… 시작!") 중 입력은 무시.

## 4. 규칙과 점수

### 4.1 졸림(sleep) 모델
각 플레이어에 **졸림 게이지 s ∈ [0, 1]** (원작은 화면에 게이지 없음 → HUD에 표시하는 것은 우리의 가독성 보강; koopatv가 "상대가 얼마나 졸린지 알기 어렵다"고 불평).

| 사건 | 대상 | 변화 | 부가 |
|---|---|---|---|
| 내가 PERFECT | **깨어 있는 다른 모든** 플레이어 | s += **0.34** | 링 이펙트, `sfx.good` |
| 내가 GOOD | 깨어 있는 다른 모든 플레이어 | s += **0.20** | 작은 링, `sfx.tap` |
| 내가 MISS | **나 자신** | s += **0.25** 그리고 **스턴 1.5 흔들림(반주기 ×1.5)** 동안 입력 불가 | `Zzz`, `sfx.bad` |
| 스턴 중 남이 PERFECT/GOOD | 나 | 정상 누적(스턴은 방어가 아님) | — |
| s ≥ 1.0 | 해당 플레이어 | **잠듦(탈락)** | `sfx.lose`(그 플레이어), 이후 최면 대상에서 제외 |

- 원작 기준: 슬리프는 대략 **최면 3번**(PERFECT 3회 = 1.02) 또는 **헛누름 4번**에 잠든다. [추정, 영상에서 3~4회 피격 후 쓰러짐]
- 여러 명이 같은 반주기에 PERFECT를 성공하면 **각각 별도로 가산**(2명 성공 시 나머지 2명은 0.68 누적) — 후반 동시 최면으로 순식간에 여러 명이 잠드는 원작의 "갑자기 다 쓰러진다" 느낌 재현.
- 같은 프레임에 2명 이상 s ≥ 1 → **동시 탈락**, 순위는 **s 초과량이 큰 쪽이 더 낮은 순위**, 같으면 슬롯 번호 큰 쪽이 낮은 순위 [추정].

### 4.2 승리·순위·점수
- 잠든 순서의 역순이 순위: 1번째 잠든 = 4위, … 마지막 생존 = 1위.
- `result()` 점수: **생존 시간(초, 소수 1자리)** 을 점수로. 생존자는 `게임 종료 시각 + 10` 보너스로 1위 확정. `lowerIsBetter` 없음.
  - 예: 3P 8.4s 잠듦, 2P 15.1s, 4P 22.7s, 1P 생존 → 점수 [32.7, 15.1, 8.4, 22.7].
- 원작 점수 표기는 없음(승/패만). Stadium 1 Kids Club의 토너먼트 모드 이름은 **"Who's the Best?"**(Serebii 표기; Bulbapedia 미니게임 총람은 Stadium 1에도 "Who's the Champion?"을 쓴다 — 출처 상충, 게임 구현과 무관)이며 1위만 1승 획득, 목표 승수는 설정 가능, 첫 게임은 무작위·이후는 점수가 가장 낮은 플레이어가 게임 선택. [확인, cheatcodes/serebii]
- 동점(마지막 2명 동시 잠듦): 4.1 규칙으로 순위 결정, 원작에서는 화면상 둘 다 4위/… 구분이 어려움 [추정].

## 5. 난이도 곡선

### 5.1 추 속도 (시간 곡선)
- 추 각도 θ = 55° · sin(φ), **φ' = ω(t)** (rad/s). 반주기 = π/ω.
- **ω(0) = 2.6 rad/s** (반주기 ≈ 1.2s, 처음엔 "쉽게 맞출 수 있음") → **기준 곡선은 연속식 ω(t)=2.6·1.05^t**. 원작은 "매 흔들림마다 빨라짐"(StrategyWiki [확인])이므로 구현은 **중앙 통과 순간마다 ω ← 2.6·1.05^t 로 갱신**(통과 사이엔 일정)한다. ~~통과마다 ×1.045~~ 는 폐기: 그 식이면 26초 만에 상한에 닿아 아래 표와 맞지 않는다(비평가 수정).
  - t=10s: ω≈4.2(반주기 0.75s), t=20s: ω≈6.9(0.46s), t=30s: ω≈11(0.28s), t=40s: ω≈18(0.17s, 사실상 연타 구간).
  - **상한 ω_max = 16 rad/s**(반주기 0.196s ≈ 초당 5회 연타, t≈37s에 도달) [추정, 비평가 수정: 22는 초당 7회로 사람이 리듬 유지 불가능. 실측 최대 40초와 정합하도록 16으로 낮춤].
- **누군가 잠들어도 속도는 리셋되지 않는다**(입력 무관하게 계속 가속). [확인, koopatv]
- 판정 폭은 각도 기준 고정(§3) → 속도가 오르면 시간 창이 자동으로 좁아짐. PERFECT 창(초) = asin(0.12)/ω ≈ 0.12/ω → t=0 ±46ms, t=20s ±17ms, t=30s ±11ms; MISS 경계(0.30)는 t=0 ±117ms, t=20s ±44ms, t=30s ±28ms. 이 급격한 좁힘이 원작의 "후반은 리듬 연타" 느낌의 핵심.
- **바늘 통과 시 추가 흰색으로 0.08s 플래시** — 초반에만 유용한 힌트. [추정, GameFAQs 검색 요약만 근거·직접 열람 불가(2차 비평가 격하)]

### 5.2 CPU 난이도 (원작 Easy/Normal/Hard/Hyper; Very Hard는 Stadium 2 명칭)
셸에는 난이도 선택이 없으므로 **CPU 3마리를 Normal / Hard / Hyper 계열로 섞어** 배치(2P=Normal, 3P=Hard, 4P=Hyper 성향; 매 판 무작위 셔플). 수치는 §8.

| 난이도 | 원작 체감 | 행동 |
|---|---|---|
| Easy | 초반부터 자주 헛누르고 금방 잔다 | 반주기당 시도율 낮음, 오차 큼 |
| Normal | 20초 전후까지 버팀 | 초반 정확, 15s 이후 오차 급증 |
| Hard | 사람 숙련자와 비슷 | 25s까지 정확 |
| Hyper | 거의 실수 없음, 리듬 예측 | 오차 최소, 늦게까지 정확. 사람은 "리듬 암기"로만 이김 |

## 6. 화면 구성

- **카메라**: 정면 약간 위(3/4 하이앵글)에서 보는 고정 시점. 원근 없이 2D로 표현하되 뒤쪽 2마리를 **scale 0.85**, 앞쪽 2마리를 **scale 1.0**으로 깊이감. [확인, 스크린샷]
- **배치 (960×540)**: 시계추 축 (480, 120), 추 길이 200 → 추 원판 중심이 (480, 320) 근처를 지나며 좌우로 ±55° 흔들림. 노란 호는 축 기준 반지름 230, 각도 -60°~+60°, 폭 10px; 빨간 바늘은 호 중앙(480, 350)에서 위로 30px 삼각형.
  - 1P: (300, 430) 정면(앞줄 왼쪽) · 2P: (660, 430) 앞줄 오른쪽(flip) · 3P: (200, 250) 뒷줄 왼쪽 · 4P: (760, 250) 뒷줄 오른쪽(flip). 4마리 모두 시계추(중앙)를 향해 몸을 돌림.
  - 각 캐릭터 머리 위 `drawPlayerTag`, 그 아래 **졸림 게이지** 60×8px (보라 채움, 1.0 근처 빨강 점멸).
- **HUD**: 상단 중앙 **경과 시간** (`mm:ss` 아님, `12.3초`), 상단 좌측 "남은 인원 N/4". 타이머는 원작에 없으나(무제한) 정보용. 하단에는 `common/style.css` 바(조작 안내).
- **색감**: 배경 보라-남색 소용돌이, 추 금색(#e6b422)/플래시 흰색, 바늘 빨강(#e0302a), 호 노랑(#f2d34c), 최면 링 분홍(#ff7ad9)→보라(#8a4bd6) 그라데이션, Z 글자 하늘색(#9ad0ff). 전체적으로 **어둡고 나른한** 분위기. [확인, 다수 리뷰가 "creepy/최면적 분위기" 언급]

## 7. 연출

1. **시작**: 셸 타이틀 → `init()` 후 화면 중앙 "준비…" (1.0s, `sfx.count`) → "시작!" (0.6s, `sfx.go`). 이 동안 추는 정지 상태(θ = +55° 끝점)에서 대기, "시작!"과 함께 흔들리기 시작. 원작 인트로 텍스트: "Press the A Button when the pendulum gets to the center red needle to cast HYPNOSIS. The last one awake wins." [확인] → 한국어 howto 3줄로 전달.
2. **추 중앙 통과**: 추 원판 흰색 플래시 0.08s + `sfx.tick`(작은 째깍, 후반에는 속도 상승으로 자연스럽게 빠른 틱).

## 8. AI 행동 모델 제안

CPU는 **매 반주기마다** "이번 통과에 누를지"를 결정하고, 누르면 목표 시각(중앙 통과) + **반응 지연 + 가우시안 오차**에 입력한다. 후반(ω 상승)일수록 오차의 시간 폭이 판정 창보다 커져 자연스럽게 실패가 는다.

| 난이도 | 시도율(반주기당) | 반응 지연 평균 (ms) | 시간 오차 σ (ms) | 초당 σ 증가 (ms/s) | 무작위 대실수 확률 | 스턴 후 복귀 지연 |
|---|---|---|---|---|---|---|
| Easy | 0.55 | +40 | 70 | +2.0 | 12% | 1 반주기 추가 쉼 |
| Normal | 0.75 | +25 | 45 | +1.4 | 6% | 0 |
| Hard | 0.90 | +10 | 28 | +0.9 | 3% | 0 |
| Very Hard | 0.95 | +5 | 20 | +0.6 | 1.5% | 0 |
| Hyper | 1.00 | 0 | 12 | +0.35 | 0.5% | 0 |

- 입력 시각 = 중앙 통과 시각 + 지연 + N(0, σ(t)), σ(t) = σ₀ + 증가율·t. "대실수"는 σ 대신 ±(반주기의 30~50%) 만큼 어긋나게 누름(초반에도 코골이 발생시켜 리듬감 부여).
- **연타 구간 처리**: 반주기가 σ(t)의 2배보다 짧아지면(ω가 큰 후반) CPU는 "리듬 연타" 모드 — 매 반주기마다 시도하되 σ를 반주기의 25%로 캡. 즉 Hyper는 끝까지 대부분 성공, Easy는 절반 실패.
- 사람에게 유리한 보정 없음. 다만 사람 플레이어가 유일한 사람이고 8초 내에 잠들면 다음 판 CPU σ에 +5ms(옵션, 필요시).
- 셸에 난이도 선택이 없으므로 기본은 **Normal / Hard / Hyper 1마리씩**(슬롯 셔플). 사람이 2명 이상이면 남는 CPU는 Hard→Normal 순으로 채움.

검수자가 Bulbapedia(Snore War 항목·워크스루 Part 5), Serebii Kids' Club, KoopaTV 티어리스트, cheatcodes 미러(GameFAQs 전략 가이드), DualShockers/ScreenRant/CBR/Mic/Twinfinite 기사, TASVideos 포럼을 직접 열람해 대조했다(StrategyWiki·GameFAQs·pokecommunity·fandom은 여전히 403/402, 검색 요약만 사용). 원작 정확 수치(피격 횟수·가속률·판정 폭)를 적어 둔 출처는 **어디에도 없다** — 아래는 원작 증언과 정합하도록 수치를 확정·수정한 것이다.

### A. 인라인 수정한 것
1. **가속 곡선 불일치 수정(§5.1)**: "통과마다 ×1.045"와 "ω=2.6·1.05^t"는 다른 곡선이었다(전자는 26초에 상한 도달, 후자는 표의 값). **연속식을 기준**으로 확정하고, 원작의 "매 흔들림마다 빨라짐"[확인]을 살리기 위해 중앙 통과 순간에만 ω를 갱신한다.
2. **상한 22 → 16 rad/s**: 반주기 0.196s(초당 5회). 초당 7회(22)는 리듬 유지 불가능해 "맞는 리듬으로 연타하면 이긴다"(KoopaTV)는 원작 체감과 어긋난다. t≈37s에 상한 도달 → 실측 "최대 40초"[확인]와 일치.
3. **판정 창 프레임 하한 추가(§3)**: 각도창 asin(0.12)/ω는 ω=16에서 ±7.5ms로 1프레임보다 좁다. 60fps 입력은 프레임 단위이므로 `PERFECT = max(각도창, ±17ms)`, `MISS 경계 = max(각도창, ±34ms)`로 클램프. 이렇게 해야 후반이 "운"이 아니라 "리듬"이 된다. 원작(30fps)의 판정 해상도 ≈33ms를 참고했다. ScreenRant가 지적한 "반응 없는 조작감"은 이 거친 해상도에서 온 것이므로 **인위적 입력 지연은 넣지 않는다**.
4. **모드 명칭 수정(§4.2)**: Stadium 1은 "Who's the Best?", Stadium 2가 "Who's the Champion?". 첫 게임 무작위·이후 최하위가 선택 규칙 추가[확인].
5. **강약 판정 근거 격상(§3)**: fandom 요약이 "정중앙일 때 최면이 가장 강하고 옆이면 아예 안 걸린다"고 명시 → PERFECT/GOOD 2단계는 [추정]이 아니라 [확인-부분].
6. **좌우 대칭 판정 명시(§3)**: 바늘에 닿기 전 조기 입력도 헛누름[확인, GameFAQs].

## 구현 노트 (games/snore.html 재구축, 2026-09-10)

§B18의 옛 프로토타입은 폐기하고 `_template.html` 기준으로 다시 썼다(CONTRACT v2: 슬롯 4개, 사람은 `g.p(i)`, CPU는 §8 모델, `result()` → `{scores:[4]}`). 아래는 스펙과 다르게 구현한 것과 이유. 수치는 게임 로직을 그대로 옮긴 시뮬레이션(2,000판, 사람 1명 + CPU 3, dt=1/60)으로 확인했다.

1. **같은 통과의 최면은 하나의 파동으로 합친다(§4.1 "각각 별도로 가산" 미적용)**: 성공(PERFECT/GOOD)한 쪽끼리는 서로 면역이고, 그 통과에 성공하지 못한 깨어 있는 전원이 **가장 강한 최면 하나**를 맞는다. 스펙 그대로(성공자끼리도 피격·누적)면 정확한 4마리가 매 통과 3×0.34씩 주고받아 평균 **8초**에 끝나고 첫 탈락이 3초에 나와, [확인] 항목인 "20~40초·조용한 초반·후반 연쇄 탈락"(§2, §B17)과 맞지 않는다.
2. **코 고는 동안은 파동을 스턴당 한 번만 맞는다(§4.1 "스턴은 방어가 아님" 완화)**: 합친 파동 모델에서 헛누름 1회는 자기 0.25 + 스턴 2반주기 동안 파동 2~3회(0.68~1.02) = 0.93~1.27 이라 **실수 한 번이 곧 탈락**이었다(시뮬: σ 28ms 사람 승률 12%, 첫 탈락 11초, 사람은 평균 헛누름 1.1회에 잠듦). 헛누름 후 첫 파동만 맞고 나머지는 "이미 코 고는 중"으로 흘려보내면 헛누름 1회 = 0.59, 두 번째 헛누름(또는 안 누르고 한 번 더 맞기)에 잠든다 — "가만히 있으면 PERFECT 3회에 잔다"와 "헛누르면 더 빨리 잔다"(2회)가 모두 살아 있다. 스턴은 여전히 방어가 아니라 한 번은 반드시 맞는다.
3. **파동 확정 시점**: 통과 k의 입력은 다음 반주기 중간(통과 + π/2ω)까지 들어올 수 있으므로 그 시점에 한 번에 확정한다(먼저 누른 쪽만 면역이 되는 순서 문제 방지). 시전 연출(harden·링·팝업)은 입력 즉시, 피격 흔들림·게이지 증가는 확정 시점.
4. **CPU 수치 재조정(§8 표 대체)**: 보통 `delay 15ms, σ 25+0.55t ms, 대실수 0.8%`, 어려움 `8ms, 18+0.4t ms, 0.5%`, 초고수(Hyper) `0ms, 12+0.2t ms, 0.3%`; 판당 σ배수 U(0.8,1.5)·대실수 배수 U(0.7,1.8)(§B11), 후반 σ ≤ 반주기×25% 캡(§8) 유지. 시도율은 1.0 고정이고, §C14의 조용한 초반은 **t<8s 동안 CPU 대실수율을 최소 3.5%로 올리는 방식**으로 구현했다(시도율을 낮추면 합친 파동 모델에서 곧 피격이 되므로). MISS 는 자기 +0.10 + 2반주기 스턴이며 **스턴은 방어가 아니다**(코 고는 중에도 파동을 모두 맞음) → 헛누름 비용 0.10+0.44 > 가만히 있기 0.44 (시뮬: 사람이 가만히 있으면 5.4초, 중앙 직후 헛누름은 4.5초에 잠듦 — §B10 충족). 최면량 PERFECT 0.22 / GOOD 0.14(4~5번 맞아야 잠듦), 판정창 하한 PERFECT 28ms · GOOD 75ms.
5. **CPU 조합과 길이**: 사람 1명 → 보통·어려움·초고수(Fisher–Yates 셔플), 2명 → 어려움·보통, 3명 → 어려움. 시뮬 2,000판(사람 σ 28+0.5t ms 모델): 사람 4명 길이 P10/50/90 = 25/30/34초, 첫 탈락 중앙값 21.5초; 사람 1명 판 길이 26/33/45초, CPU 잠드는 시각 평균 보통 21초·어려움 31초·초고수 33초(§C13 대역). 이 사람 모델의 승률은 약 3%로 §C13의 숙련 50–60%보다 훨씬 낮다 — 사람 σ 증가율(0.5ms/s)이 CPU보다 커서 후반에 불리하다. ω 곡선은 바꾸지 않았다(길이는 판정창 하한과 최면량으로 조정).
6. **시작 직후 0.25초는 입력 무시**: '시작!' 반사 연타가 첫 통과(0.6s) 기준 MISS로 잡혀 스턴+파동으로 크게 손해 보는 것을 막는 유예. 추가 바늘에서 멀리 있는 구간이라 판정 손실 없음.
7. **점수·동점 처리**: 잠든 시각(0.1초 단위)을 점수로 쓰되 직전 탈락자보다 항상 ≥0.01 크게 보정해 셸 순위에 동점이 생기지 않게 했다(같은 프레임 동시 탈락은 초과량 큰 쪽이 먼저 → 낮은 점수, §B13). 생존자 = 종료 시각 + 10. 90초 안전장치 종료 시 생존자끼리는 게이지 낮을수록 높은 점수(`+10 − s×5`).
8. **연출 축약·추가**: 셸 카운트다운(3초)이 §7-1 "준비…" 역할을 하고 추는 그동안 +55° 끝점에 정지, 셸 "GO!"와 함께 흔들리기 시작. 효과음은 사람 플레이어의 성공·실패만 크게(`good/tap/bad`), 사람이 파동에 맞으면 낮은 사인음, CPU 실패는 작은 비프, 통과 째깍은 전원 공통 — 후반 초당 5통과 × 4마리 소리 과밀 방지. PERFECT 시 금색 불꽃 파티클 8개 추가, 자막은 반투명 필 위에 표시. 사람 전원 탈락 후 1.5배속(§2 옵션) 적용. 승리 팡파르는 셸 종료 화면의 `sfx.win/lose`에 맡겨 중복 재생하지 않는다.
