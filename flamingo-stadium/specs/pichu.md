# pichu — 피츄 발전소 (원작: Pichu's Power Plant / ピチューのはつでんきょうそう, Pokémon Stadium 2 · N64)

> 표기: **[확정]** = 복수 출처 일치 / **[추정]** = 출처 침묵 → 원작 영상 리듬·전작(Thundering Dynamo, `specs/dynamo.md`)·장르 관행으로 추정. 구현자는 [추정] 수치를 튜닝 가능한 상수로 뺀다. 좌표는 셸 캔버스 960×540(`g.W`,`g.H`) 기준.
> 이 게임은 **전작 "Thundering Dynamo"(dynamo)의 정식 후속작**이다 [확정: Bulbapedia·StrategyWiki·Serebii·PKMN.NET 전부 "similar to Thundering Dynamo"]. 차이점은 딱 하나 — **방향 선택(D-pad)이 추가**되어 "어느 전극이 켜졌는지 방향을 잡은 뒤" 색에 맞는 버튼을 연타한다.

---

## 1. 한 줄 요약 · 등장 포켓몬 · 플라밍고 대체안

**한 줄 요약 [확정]**: 각 플레이어(피츄)를 둘러싼 **4방향(상·하·좌·우) 전극(electrode/발전 단자)** 중 하나가 튀어나와 **파랑 또는 초록**으로 켜진다. 플레이어는 **D-pad를 그 방향으로 기울인 채**, **파랑이면 A 연타 / 초록이면 B 연타**로 전기를 쏘아 자기 파워 미터를 채운다. **먼저 100% 채운 사람이 승리**, 패자는 감전.

원작 설명 원문 [확정]:
- Bulbapedia: "As Pichu, players must face the electrodes that pop out in their corner and rapidly charge (them). The players who do so (first) win."
- StrategyWiki: "Use (D-pad) to select an electrode. … The surrounding electrodes will light up with either a green or blue color. If it is blue, use the A button to charge. If it is green, then use the B button to charge."
- Serebii 컨트롤표: "D-Pad: Angle / A Button: Zap / B Button: Zap"
- PKMN.NET: "Just like Thundering Dynamo but with an added twist. … use the d-pad to press the direction of the thing you have to shock. The thing you shock displays what button you need to tap. First one to power all the way up wins."
- TASVideos(#9382): "I press A or B 15 times per second while holding the appropriate direction button." → **방향은 홀드, 버튼은 연타**임을 확정.

**등장 포켓몬 [확정]**: 기본 **피츄(Pichu) ×4**. 트랜스퍼팩(옐로 세이브의 오박사 피카츄)으로 **피카츄(Pikachu)** 대체 가능. 성능 차이 없음. (SuperCheats는 Elekid도 나열하나 Bulbapedia·Serebii·다른 팁은 "Elekid는 안 됨" → 피츄/피카츄만 확정.)

**플라밍고 대체안** (셸 포즈 `idle jump run sleep dig eat dizzy harden fly ball hit`):

| 원작 요소 | 원작 표현 | 플라밍고 대체 |
|---|---|---|
| 피츄(플레이어) | 발판 중앙에 서서 켜진 전극을 향해 몸을 돌리고, 연타 시 볼에서 스파크를 튀김 | 플라밍고 `palette.players[i]` 색. 대기 `idle`. 방향 입력 시 그 방향으로 `flip`(좌/우) 또는 살짝 `rot`(상 = −0.25rad, 하 = +0.25rad)로 "바라보기". 정답 연타 중 `run` 포즈(제자리 발구르기)로 부리 끝에서 전극 방향으로 램프색 스파크 파티클. 25/50/75% 통과 시 `jump` 1회 |
| 전극(electrode) 4개 | 각 플레이어 발판 사방에 묻혀 있다가 **튀어 올라오며(pop up)** 파랑/초록으로 점등하는 원통형 단자(전구 달린 피뢰침 느낌) | 발판 사방 4개의 회색 원기둥(`#6f7a8c`, 폭 34px 높이 22px). 활성 시 0.15s 동안 높이 22→48px로 튀어오르고 꼭대기 전구가 램프색(파랑 `#3A7BFF` / 초록 `#3FD35A`)으로 켜지며 글로우. 비활성은 회색 소등 |
| 파워 미터 | 각 플레이어 옆 세로 게이지(노란 충전) | 플레이어 발판 옆 세로 바(폭 18px, 높이 120px) 노랑 `#FFD23F` 채움, 테두리 플레이어 색. 옆에 % 숫자 |
| 틀린 버튼 → 방전 | 피츄가 움찔, 게이지 감소 | `dizzy` 0.3s + 회색 스파크가 바닥으로 흩어짐 + 게이지 붉게 깜빡임 |
| 승자 | 만충 → 발전소 조명이 일제히 켜지고 피츄가 기뻐함 | `fly` 0.5s 후 `jump` 반복, 머리 위 노란 번개 아이콘 |
| 패자 | 감전 [확정: "The loser gets electrocuted"] | `hit` 0.6s → `dizzy` 유지, 흑백 8Hz 깜빡임 2s |
| 발전소 바닥·기계 | 금속 바닥, 중앙에 큰 발전기/변압기 | 어두운 남색 실내, 중앙 상단에 원통형 발전기 소품(진행에 따라 창이 노랗게 밝아짐) |

## 2. 인원 · 시간 · 종료 조건

- **4인 동시 플레이 [확정]**. 사람 1~4명 + CPU. 항상 4슬롯 생성. 서로 간섭 없음(각자 자기 전극만 상대).
- **제한 시간 없음, 선착 레이스 [확정]**: 누군가 100% 도달 즉시 종료. `duration: 0`, `g.finish()` 직접 호출.
- **한 판 길이 [확정(개략)]**: 유튜브 3편 전체 길이 34s·37s·34s(인트로+"Ready Go"+플레이+결과 포함). 순수 플레이 기준점 [확정, 비평가 보강]: TAS(Hard, 15회/초) **약 7초**(TASVideos #9382 타임라인 0:38~0:45) / 사람 최속 기록 **6.60초**(Cyberscore 차트 547868, 2024-09-27 — 검색 요약만, 2차 비평가가 직접 열람 실패 → [미검증]) / **Very Hard CPU는 10초 이내 만충**(SuperCheats·PokeCommunity 팁). 캐주얼 사람은 **약 14~20초** [추정]. 목표: Normal에서 사람이 성실히 하면 **14초 ±3초**, 최선의 사람(13회/초)은 7초 안팎.
- **안전장치 [추정]**: 60초 안에 아무도 못 채우면 최대 충전자 승(CPU가 항상 연타하므로 실제로는 발동되지 않음).
- **라운드 구조**: 단판. 원작의 "Who's the Champion?"(정해진 승수 선착) 토너먼트와 동점 시 퀴즈 타이브레이커 [확정: StrategyWiki "Ties will be broken by a question-and-answer round"]는 셸 밖 문제이므로 미구현.

## 3. 조작

원작 N64 [확정]:

| N64 | 기능 |
|---|---|
| **D-pad(십자키) ↑↓←→** | 켜진 전극 방향을 **홀드**(Angle). 스틱도 동일하게 동작한다고 보는 것이 안전 [추정: Bulbapedia "Control Stick or Control Pad"] |
| **A** | 전극이 **파랑**일 때 연타 → 충전(Zap) |
| **B** | 전극이 **초록**일 때 연타 → 충전(Zap) |
| C·L·R·Z | 사용 안 함 |

우리 액션 매핑:

| 우리 액션 | 역할 |
|---|---|
| `up/down/left/right` | 전극 방향 선택. `down()` **홀드**로 읽는다(`axis()`도 허용: |x|,|y| 중 큰 축, 0.5 이상). 마지막으로 누른 방향을 `facing`으로 유지 — 즉 키를 떼어도 마지막 방향을 바라본 채 남는다 [추정: 원작 피츄도 몸 방향이 유지됨] |
| `a` | 파랑 전극 연타 |
| `b` | 초록 전극 연타 |

입력 규칙(정확히 이대로):
1. 연타는 `hit()`(눌린 프레임)만 카운트. 홀드 무효 [확정: "tap repeatedly"]. 같은 키 반복은 **유효**(연타 게임). **연타 상한 15회/초** [확정: TAS가 15회/초로 만충 → 그 이상은 무의미하다고 보고 초과분 무시].
2. 유효 충전 조건 = **(facing == 활성 전극 방향) AND (누른 버튼 색 == 전극 색)**. 둘 다 맞아야 +.
3. **방향이 틀린 채** 올바른 색 버튼 → **충전 0, 페널티 없음** [추정: 원작에서 허공에 스파크만 튀고 게이지 변화 없음. 빈 방향에 스파크 파티클만 출력].
4. **방향이 맞을 때 색이 틀리면** → **방전 페널티**(§4) (방향이 틀리면 §3-3 무페널티, §2차-9) [확정: 전작과 동일하게 "wrong button drains"].
5. A·B 같은 프레임 동시 → 틀린 것으로 처리 [추정, dynamo와 통일].
6. 전극 전환 직후 유예(grace) **0ms** [추정, dynamo와 통일]. 접근성 옵션으로 사람에게만 80ms 유예 가능하나 기본 0.
7. 전극이 없는 상태(전환 사이 공백)에서의 입력은 전부 무효·무페널티.

## 4. 규칙과 점수

- **점수 단위**: 충전량 0~100(%) [단위 추정; 원작은 게이지만].
- **가산 [추정, 비평가 보정]**: 올바른 방향+색 `hit` 1회 = **+1.25%** → **80회**로 만충. (근거: TAS가 15회/초로 약 7초, 사람 최속 6.60초. 전극 전환 공백·방향 전환 손실 약 15%를 빼면 유효 연타 ≈ 75~90회. 63회면 TAS가 4~5초에 끝나 원작보다 빨라진다.)
- **감산(방전) [존재 확정 / 수치 추정]**: 틀린 색 `hit` 1회 = **−2.5%**(정답 2회분). 0 미만 없음. 스턴 없음(누르는 동안 계속 깎임).
- **자연 감소 없음** [추정].
- **승리 판정 [확정]**: 최초 100% 1명 승. 나머지는 그 시점 충전량으로 2~4위.
- **동점 [확정(간접), 2차 비평가 수정]**: 같은 프레임에 둘 이상 100% → **동점자 전원 승자**(`scores` 모두 100, 배너 "1P·3P 만충전!"). 근거: Bulbapedia 원문이 "The **players** who do so win"(복수)이고, 같은 문서가 Rock Harden을 "동점 시 점수를 못 받는 유일한 미니게임"이라 명시 → 나머지 게임은 동점자 전원 승(`specs/dynamo.md` §12와 통일). 누적 연타 수·슬롯 번호 타이브레이크는 두지 않는다.
- `result()`: `scores = [충전량 정수 4개]`(승자 100), `text = '⚡ NP 만충전!'`.
- **원작 점수 예시**: 숫자 없음. 결과 화면은 순위(1st~4th)만 표시 [확정(영상)].

## 5. 난이도 곡선 · CPU 난이도

**전극 전환 스케줄 [추정 — 원작은 "무작위"라고만 서술]**:
- 활성 전극은 항상 **정확히 1개**. 방향 4개 중 **직전과 다른 방향**을 균등 랜덤, 색은 **50/50 독립**(같은 색 연속 가능 — 전작과 달리 방향이 바뀌므로 색은 독립 추첨).
- 유지 시간 `hold` [2차 비평가 수정 — 전작 프레임 계측값을 그대로 승계]: **{1.0, 1.5, 2.0}초 중 균등 랜덤**(전작 Thundering Dynamo에서 9회 전환 전부 0.5초 단위로 양자화된 값만 관측, `specs/dynamo.md` §11). 짧은 페인트(0.5~0.8초)는 전작에서 관측되지 않았으므로 **넣지 않는다**. 튜닝 상수 `HOLD_SET=[1.0,1.5,2.0]`.
- 전환 사이 **공백 0.2초**(구 전극 하강 0.1s + 새 전극 pop 0.15s가 겹침; 전작의 0.07초 소등 블링크에 해당) [추정]. 공백 중 입력 무효·무페널티.
- **시간 가속: 없음** [2차 비평가 수정]. 한 판이 7~15초라 곡선을 둘 여지가 없고, 전작에서도 가속 없음. 난이도는 CPU 설정이 대신한다.
- 시작 첫 전극은 "Go!" 0.3초 뒤 점등.
- 4명의 전극 스케줄은 **서로 독립**(각자 다른 방향·색) [확정(영상: 플레이어마다 다른 전극이 켜짐)].

**CPU 난이도** [확정, 비평가 보정: Stadium 2 미니게임은 **Easy / Normal / Hard / Very Hard 4단계**(Bulbapedia 미니게임 총론·SuperCheats·World-of-Nintendo 교차). **Very Hard 해금 = 1인 플레이로 미니게임 챔피언(7코인) 을 Hard CPU 3명 상대로 우승**. "Hyper"는 전작(Stadium 1) 용어이며 Stadium 2에는 없음 → 선택적 보너스 단계로만 둔다]:

| 난이도 | 방향 반응 지연 | 색 반응 지연(방향 이후) | 연타(회/초) | 전환당 오색 확률 | 오방향(허공 연타) 확률 |
|---|---|---|---|---|---|
| Easy | 500~800ms | +150~300ms | 4.5~6.0 | 40% (1~3회) | 20% (0.3~0.6s 동안 옛 방향에 연타) |
| Normal | 300~500ms | +80~180ms | 6.5~8.0 | 25% (1~2회) | 12% |
| Hard | 180~300ms | +40~100ms | 8.5~10 | 12% (1회) | 6% |
| Very Hard | 100~180ms | +20~60ms | 10.5~12 | 5% | 2% |
| Hyper(선택) | 50~100ms | +0~30ms | 13~15 | 2% | 1% |

기대 소요(80회 기준, 전환 손실 포함): Easy ≈ 22s / Normal ≈ 14s / Hard ≈ 11s / Very Hard ≈ 8~9s(원작 "10초 이내"와 일치) / Hyper ≈ 6.5s(TAS급).

셸에 난이도 UI가 없으면 **기본 Normal**, CPU 3명에게 표 범위 안 값을 개별 랜덤 배정.

## 6. 화면 구성

[영상 기반 확정 + 수치 추정]
- **카메라**: 위에서 비스듬히 내려다보는 **3/4 탑다운(살짝 기울인 사각 무대)**. 스크롤 없음. 원작은 4명의 피츄가 **화면 네 사분면에 한 명씩** 배치되어 각자 사방 전극에 둘러싸여 있다 [확정(영상)].
- **플레이어 배치**: 사분면 중심 `(W×0.27, H×0.36)`=1P, `(W×0.73, H×0.36)`=2P, `(W×0.27, H×0.78)`=3P, `(W×0.73, H×0.78)`=4P. 각 중심에 원형 금속 발판(반경 44px, `#4a5568`).
- **전극 4개**: 발판 중심에서 상·하·좌·우 **92px** 떨어진 위치. 활성 시 튀어올라 색 점등 + 발판까지 램프색 전기 선(지그재그, 8Hz 깜빡) 연결.
- **파워 미터**: 각 발판 좌측 하단(`중심 x−120, y−60`)에 세로 바 18×120px. 위에 `drawPlayerTag`("1P"/"2P CPU"). 바 옆 % 숫자(14px).
- **버튼 힌트**(원작엔 없으나 필요): 활성 전극 전구 안에 **"A"/"B" 글자(20px, 흰색)** 를 찍는다. 원작 "The thing you shock displays what button you need to tap" [확정: PKMN.NET] — 즉 원작도 전극에 버튼이 표시되므로 충실 재현.
- **HUD**: 타이머 없음. 상단 중앙 40px 높이 띠에 "켜진 전극 방향 + 파랑=A / 초록=B" 소형 안내. 상단 중앙에 발전기 소품(폭 140px), 4명 중 최대 충전량에 비례해 창이 밝아짐.
- **배경·색감**: 발전소 실내. 상단 `#151c33` → 하단 `#26304f` 그라데이션, 바닥 격자 타일(`#2f3a5a` 선), 뒤쪽 파이프·계기판 실루엣. 램프 글로우가 바닥에 반사.

## 7. 연출

- **시작**: 셸 "준비… 시작!"(Ready? Go!) → `sfx.go` → 0.3s 후 첫 전극 pop(`sfx.pop`). 이전 입력 무시.
- **전극 pop**: 0.15s 튀어오름 + 전구 점등 + `sfx.tick`. 내려갈 때 0.1s.
- **정답 연타**: 캐릭터 ±3px 진동, 부리→전극 스파크 4~6개(램프색), 전극↔발판 전기선, `sfx.tap`(사람만). 25/50/75% 통과 시 `sfx.pop` + 작은 `jump`.
- **허공 연타(방향 틀림)**: 바라보는 방향으로 작은 회색 스파크 2개만, 소리 없음, 게이지 변화 없음.
- **오색 입력**: `dizzy` 0.3s + 회색 스파크 낙하 + 게이지 붉게 0.2s 깜빡이며 감소 + `sfx.bad`(사람만) + "찌릿!" 팝업 0.5s.
- **종료 [확정: 승자 만충 / 패자 감전]**: 100% 도달 즉시 전 전극이 노랗게 점등, 승자 발판에서 상단 발전기로 굵은 번개 0.5s, `sfx.win`(승자가 사람) / `sfx.lose`. 0.3s 뒤 나머지 3명 `hit`→`dizzy` 흑백 깜빡임 2s. 1.8s 후 `g.finish()`.
- **아나운서 대사 요지**(원작은 텍스트·효과음 위주): 시작 "전극 방향을 보고! 파랑은 A, 초록은 B!", 종료 "NP 만충전!". 실수 잦을 때(선택) "방향을 먼저!".

## 8. AI 행동 모델 제안

상태: `facingSeen`(인지한 방향), `colorSeen`(인지한 색), `rate`, `dDelay`, `cDelay`, `pErr`, `pWrongDir`.

```
전극 전환 시:
  faceAt  = now + dDelay×(0.7~1.3)        // 방향을 인지해 몸을 돌리는 시각
  colorAt = faceAt + cDelay×(0.7~1.3)     // 색을 인지하는 시각
  with pWrongDir: faceAt += 0.3~0.6s       // 옛 방향에 계속 연타(허공)
매 프레임:
  if now>=faceAt: facingSeen = 활성 방향
  if now>=colorAt: colorSeen = 활성 색
  cd -= dt; if cd<=0: press(colorSeen 버튼, facingSeen 방향); cd = 1/rate×(0.85~1.15)
  colorAt 도달 첫 프레임에 확률 pErr 로 잘못된 색을 errK회 더 누른 뒤 정정
```

| 난이도 | dDelay(ms) | cDelay(ms) | rate | pErr / errK | pWrongDir | 정확도 |
|---|---|---|---|---|---|---|
| Easy | 500~800 | 150~300 | 4.5~6.0 | 0.40 / 1~3 | 0.20 | ≈78% |
| Normal | 300~500 | 80~180 | 6.5~8.0 | 0.25 / 1~2 | 0.12 | ≈87% |
| Hard | 180~300 | 40~100 | 8.5~10 | 0.12 / 1 | 0.06 | ≈94% |
| Very Hard | 100~180 | 20~60 | 10.5~12 | 0.05 / 1 | 0.02 | ≈97% |
| Hyper(선택) | 50~100 | 0~30 | 13~15 | 0.02 / 1 | 0.01 | ≈99% |

지연 구간 동안 CPU는 **옛 방향·옛 색으로 계속 연타**하므로 자연히 허공 연타와 방전이 발생한다. 기대 소요(Normal): 80회 ÷ 7.25회/초 ≈ 11초 + 전환 손실(전환 6~8회 × 0.5s) ≈ **14~15초**.

## 비평가 보강 (2026-09-09, 독립 교차 검증)

### 수정(inline 반영)
1. **난이도 단계**: "Easy/Normal/Hard 3단계 + Very Hard 추정"을 **4단계 [확정]** 으로 정정. Very Hard 해금 = **1인 플레이 미니게임 챔피언 7코인전을 Hard CPU 3명 상대로 우승**(Bulbapedia·SuperCheats·World-of-Nintendo 3곳 일치). "Hyper"는 Stadium 1 전용 용어라 Stadium 2에는 없음 → 선택 단계로 강등.
2. **만충 연타 수 63회 → 80회(+1.25%/회)**: 시간 기록으로 역산. TAS(Hard, 15회/초)의 실제 플레이 구간이 약 7초(0:38~0:45), 사람 최속 6.60초, Very Hard CPU가 10초 이내. 63회면 TAS가 4~5초에 끝나 원작보다 빠르고, 80회면 15회/초×7초×(1−전환 손실 15~20%) ≈ 80~90회와 맞는다.
3. **오색 페널티 −3.2% → −2.5%**: "정답 2회분" 원칙을 새 단가에 맞춤.
4. **CPU 연타 속도 표 상향**: 난이도별 기대 소요를 원작 기록에 맞춤 — Hard는 TAS(7초)보다 확실히 느리고, Very Hard는 10초 이내여야 함(위 표에 소요 시간 명시).
5. **등장 포켓몬**: Elekid 언급은 출처 간 충돌 → 피츄/피카츄만 확정으로 정리.

### 추가
6. **연타 상한의 구현 정의**: TAS의 "15회/초"는 60fps에서 **4프레임당 1회**(누름 2프레임+뗌 2프레임)에 해당. 구현은 `hit()` 사이 최소 간격 **66ms** 미만이면 무시. 사람 최속 6.60초는 이 상한에 거의 붙어 있음 → 상한이 너무 낮으면 "손이 빠른데 안 올라간다" 느낌이 나므로 66ms 이하로 내리지 말 것.

### 수정(inline 반영)
1. **전극 유지 시간**: 균등 1.2~2.6초 + 15% 페인트 → 전작 프레임 계측값 **{1.0, 1.5, 2.0}초 균등**으로 교체. 같은 개발사·같은 엔진의 후속작이므로 계측된 전작 값을 승계하는 편이 임의 분포보다 원작에 가깝다. 페인트 삭제.
2. **동점 규칙**: "누적 연타 수 → 슬롯 순"을 **동점자 전원 승**으로 정정(Bulbapedia 복수형 + Rock Harden 예외 조항, `dynamo.md` §12와 통일). `result()`는 동점자 전원 100.

### 추가
5. **전작과의 동일 리듬 [확정]**: TAS 7초·(미검증) 사람 6.6초는 전작 계측 7.4~8.2초와 같은 급 → 이 게임은 전작에 "방향 잡기 0.3~0.5초"가 전환마다 얹힌 것일 뿐, 템포는 같다. 체감 목표(2차 확정): **Normal CPU 만충 12~15초, Hard 9~11초, Very Hard 7~9초, 사람(키보드 8~9회/초) Normal 12~15초**. 이 목표 시간에 맞춰 `GAIN`(기본 1.25%)을 조정하고, 사람 만충이 16초를 넘기면 사람에게만 GAIN 1.4~1.5%를 주는 전작식 밸런스 상수를 허용(CPU는 고정).
6. **CPU 난이도의 본질 [전작 계측 승계]**: 전작에서 CPU 연타 속도는 난이도와 거의 무관(≈10회/초)하고 난이도 차이는 **전환 반응 지연**에서 났다. 이 게임은 반응이 **방향 인지 + 색 인지 두 단계**라 §8의 `dDelay`+`cDelay` 모델이 그 구조를 정확히 옮긴 것이다. 구현 시 §5 표의 `rate` 차이보다 **지연 차이를 먼저 튜닝**할 것(지연 동안 옛 방향·옛 색으로 계속 누르는 것이 원작의 "관성 페널티"를 CPU에도 똑같이 적용하는 핵심).
7. **Very Hard 승률 목표 재확인**: 원작 팁("Very Hard CPU는 10초 이내 만충")과 전작 Hyper 트리비아("LCD 지연 때문에 CPU만큼 빨리 못 누른다")를 합치면 Very Hard는 **사람이 무결점으로 연타해도 5번에 1번쯤 이기는** 수준. §5 Very Hard `rate` 10.5~12는 사람 상한(15)보다 낮으니 원작보다 관대한 편 — 원작 감각을 원하면 12~13으로 올린다.
8. **오방향 연타의 시각 피드백 [추정, 필요]**: 원작은 피츄가 바라보는 방향으로 스파크를 쏘므로 "허공에 쏘고 있다"는 것이 즉시 보인다. 우리 구현도 방향이 틀리면 **부리 앞 회색 스파크 + 게이지 정지**로 반드시 보여줄 것(무음·무페널티는 유지). 이것이 없으면 사람이 "버튼이 안 먹는다"고 느낀다.
9. **전극 전환 직후 관성 페널티 [전작 확정 승계]**: 새 전극이 pop 되는 0.15초 동안 사람이 옛 색을 계속 누르면 §3-7에 따라 무효(공백)로 처리되지만, pop이 끝나 점등된 첫 프레임부터는 유예 0ms로 오색 판정. 전작과 같은 "전환 순간 2~3회 헛방" 감각이 나야 한다. 단 방향이 아직 옛 방향이면 §3-3에 따라 페널티 없음 — 즉 이 게임은 전작보다 **오색 페널티를 맞을 확률이 낮고**(방향을 먼저 바꿔야 색이 판정됨), 대신 방향 전환 시간만큼 느리다. 이 트레이드오프가 두 게임의 차별점이므로 §3-3을 완화·강화하지 말 것.
10. **구현 힌트**: `games/dynamo.html`(89줄)의 구조(players 배열, `mash`/`stun` 타이머, bolts 파티클, `result()`의 승자 판정)를 그대로 가져와 (a) 램프 1개 → 플레이어별 전극 4개·활성 인덱스, (b) 판정에 `facing==active` 조건 추가, (c) 사분면 배치로 바꾸면 300줄 안에 들어간다. 동점 판정은 dynamo의 `filter(score===best).length===1` 대신 **best≥100인 전원을 승자**로.
11. **특수 아이템·해저드·타이머 없음 재확인 [확정]**: Bulbapedia·Serebii·PKMN.NET·TAS 노트 어디에도 아이템·장애물·제한 시간 언급 없음.

## 구현 메모 (games/pichu.html, 2026-09-11)

`[추정]` 수치는 파일 상단 상수로 뺐고, 실제 채택값이 스펙 기본값과 다른 곳만 적는다.

- **`GAIN = { human: 1.5, cpu: 1.6 }`** (스펙 기본 1.25 = 80회): §8 CPU 모델을 60fps로 400판씩 시뮬하면 1.25에서 Normal 중앙값 **26초**, Hard 14초라 §2차-5 목표(Normal 12~15 · Hard 9~11)에 못 미침. CPU 1.6 + 연타 9~10.5회/초(§2차-6)로 Normal ≈ 15s · Hard ≈ 10.5s. 사람은 처음 2.0이었으나 QA 시뮬(300판, vs Hard 1 + Normal 2)에서 7회/초 사람 승률 89%·만충 9.0s로 과해 §2차-5 허용 범위 1.5로 낮춤. QA 계측: 사람 1.6 → 7회/초 16%·9회/초 94%, 1.4 → 1%·62%. 재계측(자체 60fps 헤드리스 봇, 300판): 1.5에서 7회/초·반응 0.45s 승률 0%, 9회/초·반응 0.35s 7%, 경기 중앙값 ≈ 12.3s. 이 봇은 QA 봇보다 약하게 나옴(같은 봇으로 2.0 → 10%/88%, QA는 89%/100%) → QA 척도로 환산하면 1.5는 QA의 1.4(1%/62%)~1.6(16%/94%) 사이.
- **CPU 구성**: 셸에 난이도 UI가 없어 CPU 3명 = Hard 1 + Normal 2 를 Fisher–Yates로 균등 무작위 슬롯에 배정(§5 "기본 Normal" 대신 — 전원 Normal이면 성실한 사람이 거의 항상 이겨 §비평가-13 승률 목표에서 벗어남).
