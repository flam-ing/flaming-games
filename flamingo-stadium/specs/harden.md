# Rock Harden (딱딱하게!) — 설계 스펙

원작: Pokémon Stadium 1 (N64, 1998/2000) Kids Club 미니게임 "Rock Harden" (일본판 『ポケモンスタジアム2』 チビッコクラブ의 **「かたくなるがっせん」**(딱딱해지기 합전) — 일본판 넘버링이 하나 밀려 서양판 Stadium 1 = 일본판 2다). 게임 id: `harden`. 셸 계약은 `CONTRACT.md` 를 따른다.

---

## 1. 한 줄 요약 + 등장 포켓몬과 플라밍고 대체안

**한 줄 요약**: 하늘에서 떨어지는 바위(boulder)가 머리 위에 닿는 순간에만 A 버튼으로 "딱딱해지기(Harden)"를 써서 바위를 부수되, 딱딱해져 있는 동안에도 에너지가 새어나가므로 **최대한 짧게·늦게** 굳어야 하는 4인 동시 생존(last one standing) 게임.

| 원작 요소 | 원작 표현 | 플라밍고 대체안 |
|---|---|---|
| 플레이어 캐릭터 | 단데기(Metapod) 또는 딱충이(Kakuna), 4명에게 무작위 배정. 바닥에 서서 거의 움직이지 않음 | `drawFlamingo` **`idle`** 포즈(살짝 숨쉬는 흔들림). 플레이어 색은 `palette.players[i]` |
| 딱딱해지기(Harden) | 몸이 번쩍이며 은회색 금속광택으로 변하고 미세하게 진동 | **`harden`** 포즈 + 흰색 하이라이트 플래시(0.1초) + `alpha`로 은색 오버레이 |
| 바위에 맞음 | 납작하게 눌리며 "찌부" → 어지럼 | **`hit`** 포즈 0.25초 → **`dizzy`** 0.6초(별 회전) |
| 탈락(에너지 0) | 옆으로 픽 쓰러져 누움, 이후 반응 없음 | **`sleep`** 포즈(회색 톤, `alpha` 0.55) + 머리 위 "탈락" 배지 |
| 승리 | 남은 1명이 통통 튀며 기뻐함 | **`jump`** 포즈 반복(0.5초 주기) |
| 바위(boulder) | 갈색·회색 다각형 돌덩이, 대·중·소 3크기 | 캔버스 도형: 회갈색 불규칙 다각형(8각), 반지름 대 42px / 중 30px / 소 20px, 하이라이트 + 그림자 |
| 바위 그림자 | 바닥의 검은 타원, 바위가 내려올수록 커지고 진해짐 | 검은 타원 `alpha` 0.15→0.55, 반지름 6px→바위 반지름×1.1 |
| 바위 파괴 | 딱딱해진 몸에 맞으면 산산조각(파편 6~10개) + 먼지 | 파편 파티클 8개(회갈색 삼각형), 0.5초 |

## 2. 인원·시간·라운드 구조

- **4인 동시 플레이** (원작 1~4명 사람 + 나머지 CPU. 우리 셸도 4슬롯 고정, `humans` 이외는 CPU).
- **제한 시간 없음** — 종료 조건은 "1명만 남을 때"(last player standing). `duration: 0`, 게임이 `g.finish()` 호출.
- 실제 소요 시간: 원작 영상 기준 한 판 **약 45~90초** (플레이 영상 1개가 정확히 60초, 다른 영상은 인트로 제외 약 2분 20초 = 결과 화면 포함). 우리 구현은 **안전 상한 120초**를 두고, 120초가 지나면 남은 에너지 순으로 순위를 매겨 강제 종료(원작에는 없음 — 추정 안전장치).
- **라운드 없음**: 바위가 끊임없이(endless waves) 날아온다. 내부적으로는 "웨이브"(0.9~2.4초 간격의 투척 묶음)로 관리한다(§5).
- 시작 후 **1.5초 유예**(첫 바위는 Go! 후 1.5초 뒤 착지).
- **사람 전원 탈락 후**: 원작은 남은 CPU끼리 마지막 1명이 남을 때까지 그대로 진행된다(관전). 우리도 동일 — 강제 종료하지 않고 CPU 끼리 끝까지 돌린다(비평가 보강 §11-3).
- **동점 처리**: 마지막 두 명 이상이 같은 웨이브(착지 시각 차 ≤ 0.2초) 안에서 함께 탈락하면 원작은 "무승부(tie)"로 처리하고 챔피언전에서 아무도 점수를 받지 못한다(Rock Harden만의 특례, Bulbapedia). 우리 구현: 동시 탈락자는 **동일 순위**로 처리(result 점수 동일).

## 3. 조작 매핑

| N64 | 원작 동작 | 우리 액션 |
|---|---|---|
| **A** | 누르고 있는 동안 Harden(딱딱해짐). 떼면 즉시 풀림 | **`a` 홀드** — `g.p(i).down('a')` 가 true인 동안 굳음 |
| B | 없음 (게임 내 설명문도 A만 언급) | `b` — **무시**. A와 동일 취급하지 않는다(비평가 수정: 원작 설명문 "HARDEN only works while the A Button is pressed") |
| 스틱 / C / L / R | 없음 (이동 불가) | 없음 |

- **홀드형**이다. 연타 아님. 단, 원작 공략(GameFAQs)이 강조하듯 **"누르지 말고 톡(tap)"** — 아주 짧게 눌러도 그 프레임에 굳어 있으면 바위가 부서진다.
- 입력 반응 규칙:
  - 버튼을 누른 **즉시(0프레임 지연)** 굳는다. 떼면 즉시 풀린다(원작에서 해제 애니메이션 약 0.1초는 보이지만 판정은 즉시 — 추정).
  - 최소 유지 시간 없음. 1프레임 tap도 유효.
  - **에너지가 0이면 입력 무시**(탈락).
  - 맞은 직후 `hit`+`dizzy` 중(**0.7초**, §11-10-3)에는 입력을 받지 않는다 (불명 — 추정: 원작에서 눌린 직후 굳지 못하는 경직이 보임).
  - 탈락한 플레이어 입력은 완전 무시.

## 4. 규칙과 점수

### 에너지(HP) 게이지
- 각 플레이어 **에너지 100** (원작은 수치 표시 없이 막대만 보임 — 100 스케일은 추정).
- **바위에 맞음**: 크기별 큰 손실 — 대 **-30**, 중 **-22**, 소 **-15** (원작: "큰 덩어리가 깎임", Harden 비용보다 훨씬 큼. 수치는 추정: 대 3발이면 KO).
- **딱딱해져 있는 동안**: **-12 / 초** 지속 소모 (원작 "slowly deplete". 추정: 8초 계속 누르면 KO).
- 바위를 **정상 방어**(굳은 상태로 맞음): 에너지 손실 없음(홀드 시간만큼의 소모 외). 바위는 부서진다.
- 에너지는 **회복되지 않는다**(원작: stamina game, 회복 없음).
- 에너지 ≤ 0 → 즉시 탈락(`sleep` 포즈). 그 플레이어 자리로는 더 이상 바위가 안 떨어진다.

### 바위 판정
- 바위마다 `impact` 시각이 있고, 그 순간 대상 플레이어가 `harden` 상태면 **방어 성공**, 아니면 **피격**.
- 판정 창은 **한 순간(1프레임)** — "살짝 늦게 누르면 이미 맞음"이 원작 긴장감의 핵심. 단, 초보 배려로 impact ±0.05초(약 3프레임) 내에 눌린 것도 성공 처리(추정 관용값).
- 바위는 플레이어 머리 위에 **정확히** 떨어진다(빗나가지 않음). 각 바위는 특정 플레이어 1명을 노린다.

### 승패
- 마지막 1명 → 승자. 나머지는 **탈락 순서의 역순**으로 2·3·4위.
- `result()` 점수: **생존자 = 남은 에너지 + 10000**, 탈락자 = **round(탈락 시각 초×10)** (§11-12 가 대체) (늦게 탈락할수록 높음). `text` 에 승자 이름 + "남은 에너지 N". 동시 탈락 → 같은 점수.
- 원작 점수 예시(추정): 승자가 에너지 60% 남기고 승리 / 하드 CPU 3명 상대로 50% 이상 남기고 이기는 것이 RetroAchievements 도전과제("Tough It Out")일 만큼 어려운 편.

## 5. 난이도 곡선

### 시간에 따른 바위 투척 (모든 난이도 공통)
- 웨이브 간격(같은 플레이어에게 다음 바위가 오는 간격): 시작 **2.4초 → 60초 시점 1.0초**까지 선형 감소, 이후 1.0초 고정(원작 "patterned intervals" + 후반에 빨라지는 체감 — 수치 추정).
- 낙하 시간(그림자 출현 → 착지): 대 **1.6초**, 중 **1.2초**, 소 **0.9초**. 시간이 지나면 ×(1 − 0.25·min(t,60)/60) 까지 빨라짐(60초에 25% 빨라짐).
- 크기 확률: 0~20초 대 60/중 30/소 10 → 40초 이후 대 30/중 40/소 30.
- **패턴** (원작 "patterned intervals"): 웨이브 하나는 아래 중 하나
  1. 4명 동시 동일 크기 (40%)
  2. 왼→오 0.15초 간격 순차 (25%)
  3. 오→왼 순차 (15%)
  4. 무작위 2명만 (20%)
- **페인트(fake)**: 원작에서는 확인 안 됨. 그림자만 크고 실제로는 작은 돌(소)이 빨리 떨어지는 조합이 심리적 페이크 역할. **가짜 바위(맞아도 무해)는 만들지 않는다.** (기존 harden.html의 fake 돌은 원작과 다름 → 제거 권장.)
- ~~연속 두 바위가 같은 플레이어에게 0.5초 안에 오는 "더블"~~ → **폐기**(2차 비평가 §11-10-2: 원작은 한 플레이어에게 바위가 한 번에 하나만 날아온다). 대신 후반에는 착지 직후 곧바로 다음 그림자가 뜨는 방식으로 압박한다.

### CPU 난이도(원작 Easy/Normal/Hard/Hyper; 셸에는 단일 CPU이므로 **Normal~Hard 중간**을 기본으로)
- Easy: 자주 너무 일찍 굳어 에너지 낭비, 가끔 못 눌러 맞음.
- Normal: 대체로 방어하지만 홀드가 길어 에너지가 빨리 준다.
- Hard: 거의 마지막 순간에 짧게 tap. 실수 드묾.
- Hyper: 거의 완벽. 플레이어가 느긋하면 무조건 진다(GameFAQs: "aggressive해야 한다").
- 수치는 §8.

## 6. 화면 구성

- **카메라**: 정면 약간 위(15° 내려다봄)의 3/4 뷰. 사각 바위 절벽 앞 평평한 돌바닥.
- **플레이어 배치**: 4명이 화면 가로로 한 줄, 등간격. 960×540 기준 x = **165, 375, 585, 795**, 발 y = **395**. 왼쪽부터 1P→4P.
- **HUD**:
  - 화면 **하단** 각 플레이어 밑에 이름 배지(`drawPlayerTag`) + **에너지 막대**(폭 150, 높이 14, y=470). 색: 60% 초록 / 30~60% 노랑 / <30% 빨강, 뒤 배경 어두운 회색. 원작도 하단에 4개의 막대가 나란히 있음.
  - 상단 중앙: 경과 시간(mm:ss)은 원작에 없음 → **표시하지 않음**, 대신 남은 인원 "생존 3/4"를 작게.
  - 탈락자 막대 위 "탈락" 텍스트, 승자 위 "승리!".
- **배경 소재·색감**: 회갈색 암석 벽(#6b5a4a~#8a7663), 바닥 밝은 회색 돌(#b9b1a6), 하늘 연한 청회색 상단 그라데이션. 흙먼지 파티클. 전체적으로 채도 낮은 갈색·회색 톤에 플라밍고 분홍이 대비되게.
- **바위 낙하 표현**: 화면 상단 밖(y=-60)에서 플레이어 머리(y≈300) 로 수직 낙하, 낙하 중 회전(2 rad/s). 바닥엔 그림자 타원이 먼저 나타나 커짐(그림자가 곧 유일한 타이밍 단서 — 원작 공략의 핵심).

## 7. 연출

- **시작**: 셸 카운트("준비… 시작!") 후 1.5초 조용한 대기, 첫 그림자 등장. 셸 `sfx.count/go` 사용.
- **굳기**: `sfx.tap()`(짧은 금속음), 몸 흰색 플래시. 원작에선 "카캉" 하는 금속 효과음.
- **방어 성공**: 바위가 파편으로 산산조각(`sfx.hit`) + 작은 먼지 링. 텍스트 없음(원작엔 팝업 없음). 우리 구현은 1P에게만 작게 "방어!"(선택).
- **피격**: `sfx.bad`, 화면 살짝 흔들림(4px, 0.2초), 캐릭터 `hit`→`dizzy`, 에너지 막대 빨간 플래시. 원작에선 납작해졌다 튕겨 올라옴.
- **탈락**: `sfx.lose` 짧게, 캐릭터가 옆으로 쓰러짐(`sleep`), 회색 처리. 배지 "탈락".
- **종료**: 마지막 1명 남는 순간 바위 낙하 정지, 승자 `jump` 반복 1.5초, `sfx.win`, 중앙 큰 텍스트 "○P 승리!" → `g.finish()`.
- **아나운서 대사 요지**(원작 영어 아나운서, 추정): 시작 "Rocks are falling! Use Harden at the last second!", 피격 시 "Ouch, that's gotta hurt!", 남은 1명 "And we have a winner!" — 우리는 텍스트 자막으로 한국어 한 줄만: "바위가 닿는 순간에만 딱딱해지세요!".

## 8. AI 행동 모델 제안

CPU는 각 바위의 `impact` 시각을 알고, 그 시각에서 **오프셋 `d` 만큼 앞서 누르기 시작**해 **`hold` 초 동안** 유지한다. 오프셋과 홀드에 난이도별 정규분포 잡음을 준다. 결과적으로 `d<0`(늦음) 이면 피격, `hold` 가 길수록 에너지 낭비.

| 난이도 | 반응 오프셋 d (impact 전, ms) | 오프셋 표준편차 (ms) | 홀드 길이 (ms) | 실수(아예 안 누름) 확률 | 조기 헛굳기(바위 없는데 누름) 확률/웨이브 |
|---|---|---|---|---|---|
| Easy | 350 | 200 | 600 ± 250 | 18% | 20% (300ms) |
| Normal | 180 | 110 | 320 ± 120 | 8% | 8% |
| Hard | 90 | 55 | 180 ± 60 | 3% | 2% |
| Very Hard(보간) | 60 | 40 | 130 ± 40 | 1.5% | 1% |
| Hyper | 35 | 20 | 90 ± 20 | 0.5% | 0% |

- 늦음 판정: 실제 누른 시각이 impact + 50ms 보다 늦으면 피격. Easy는 σ가 커서 약 4%가 추가로 늦어 맞는다.
- 에너지 30% 이하가 되면 Hard 이상 CPU는 홀드를 20% 더 짧게(절박 모드). Easy는 반대로 겁먹어 홀드 +30%.
- 셸 기본 CPU: **Normal 과 Hard 의 중간**(오프셋 130ms, σ 80, 홀드 250±90, 실수 5%). 사람 수가 많을수록(3~4명) CPU를 Hard로 올려도 됨.
- 탈락한 CPU는 아무 것도 하지 않는다.

## 9. 초보자 한 줄 설명 + 제목안

- 한 줄 설명: **"그림자가 발밑까지 커지는 순간 A를 톡! 오래 누르면 힘이 빠지고, 늦으면 바위에 깔려요. 끝까지 서 있으면 승리."**
- 제목 한국어안: **"딱딱하게!"** (기존 제목 유지 — 원작 Harden(かたくなる)의 뉘앙스에 맞고 8자 이내). 대안: "바위 버티기", "플라밍고 굳기".

### 11-1. 틀린/느슨한 서술 수정 (인라인 반영 완료)
1. 일본판 이름: 「いわおとし/かたくなる 계열」→ **「かたくなるがっせん」**(『ポケモンスタジアム2』(일본판) = 서양판 Stadium 1).
2. B 버튼: "A와 동일 취급해도 됨" 삭제. 게임 내 설명문이 **A 버튼 홀드만** 명시하므로 `b`는 완전히 무시한다.
3. HP 용어: 원작 게임 내 텍스트는 **HP**("HARDEN consumes HP")라고 부른다. 화면 HUD 라벨은 "HP"로 쓰고, 코드 변수명은 자유. (스펙 본문의 "에너지"는 HP와 같은 뜻.)
4. 사람 전원 탈락 시 처리 누락 → 원작처럼 **CPU끼리 끝까지 진행**(§2에 추가). 1인 플레이에서 1P가 먼저 죽으면 관전 상태로 순위가 확정될 때까지 기다린다. 이때 안전 상한 120초는 그대로 유효.

### 11-2. 게임 내 설명문(원문 확정)과 howto 문구
- 원문: "Press the A Button to HARDEN and avoid being squashed by the boulders. HARDEN only works while the A Button is pressed. Beware, HARDEN consumes HP. Watch for the boulder shadows."
- `howto` 확정(한국어, 액션 이름만 사용):
  1. "A 버튼을 누르는 동안만 딱딱해져서 바위를 막아요."
  2. "딱딱한 동안에도 HP가 줄어요. 바위에 깔리면 훨씬 많이 줄어요."
  3. "바닥의 그림자를 보고 닿기 직전에 톡! 마지막 1명이 남으면 승리."

### 11-3. 종료 조건·동점·순위 (확정)
- 종료: 생존자 1명이 되는 순간(또는 마지막 생존자들이 같은 웨이브(≤0.2초) 안에 함께 탈락 → 무승부, §11-10-4). 제한 시간 없음(원작 확인). 우리만의 안전 상한 120초는 유지하되, KoopaTV "1분 넘게 살아남기 어렵다"에 맞춰 **60초 이후 난이도가 사실상 생존 불가 수준**이 되도록 §11-5 곡선을 강화했으므로 상한에 걸리는 일은 거의 없어야 한다.
- 동시 탈락(같은 프레임에 마지막 2명 이상이 HP≤0): 원작은 "tie"로 챔피언 점수를 아무도 못 받는다(Bulbapedia 특례 확인). 우리는 `result().scores`를 동일값으로 주고 `text`는 "무승부!".
- 순위: 탈락 시각 오름차순이 4위→2위, 생존자 1위. 동시 탈락자는 같은 점수(탈락 시각 초 단위 동일).
- `result()` 확정: 생존자 `10000 + 남은 HP(0~100 정수)`, 탈락자 `round(탈락 시각 초×10)` (§11-11·§11-12 로 갱신). `lowerIsBetter` 없음.

### 11-4. HP 수치 확정 (원작 체감 기준, 추정 → 확정값)
- 최대 HP **100**. 표시는 막대만(숫자 없음 — 원작과 동일). 막대 색은 §6 그대로.
- 피격 손실: 대 **-30** / 중 **-22** / 소 **-15** (§4 유지). 근거: 공략 "large chunk", RetroAchievements 도전과제가 "50% 이상 남기고 승리"를 어려운 목표로 삼는 것과 정합(대 2발 = 60% 손실).
- Harden 유지 소모: **-12/초, 홀드 시간에 순수 비례**. ~~누른 첫 프레임에 즉시 -1~~ 은 **삭제**(2차 비평가 §11-10-1: KoopaTV "A frame-perfect Rock Harden won't consume your HP, but if you hold down A much beyond that, it will" — 정확한 순간의 짧은 tap은 사실상 손실 0이어야 원작 체감). 1프레임 tap ≈ -0.2, 60번 완벽 tap ≈ -12 → 사람이 완벽하면 CPU보다 훨씬 오래 버티는 원작 구조.
- 피격 중(`hit`+`dizzy` **0.7초**로 단축, §11-10-3)에는 Harden 불가. 한 명당 바위가 하나뿐이므로(§11-10-2) 경직 중 착지하는 바위는 원래 없다. 경직이 끝나기 전에는 다음 바위의 그림자를 띄우지 않는다.
- HP는 회복되지 않는다(전 출처 일치).

### 11-5. 투척·난이도 곡선 확정 (§5를 이 값으로 덮어씀)
- 첫 바위 착지: Go! 후 **1.5초**.
- 같은 플레이어 기준 바위 간격 `gap(t)`: **0~15초 2.2초 → 45초 1.1초 → 60초 이후 0.8초** (구간 선형). 실제 간격 = gap × U(0.85, 1.15) (RetroAchievements 코멘트 "RNG 의존" 반영 — 완전 고정 간격이 아님).
- 낙하 시간(그림자 출현→착지): 대 1.6 / 중 1.2 / 소 0.9초, `× (1 − 0.3·min(t,60)/60)` (60초에 30% 단축; 최소 대 1.12 / 중 0.84 / 소 0.63초).
- 크기 확률: 0~20초 대60/중30/소10 → 20~40초 대45/중35/소20 → 40초 이후 대30/중40/소30.
- 패턴 비율(§5 유지): 4명 동시 40% / 왼→오 순차(0.15초 간격) 25% / 오→왼 15% / 무작위 2명 20%. 탈락자·경직 중인 플레이어는 대상에서 제외하고 나머지에게만 배정.
- ~~더블(같은 사람에게 0.5초 안에 두 발)~~ **폐기** — 한 플레이어에게 공중에 떠 있는 바위는 항상 **최대 1개**(§11-10-2). 다음 바위의 그림자는 이전 바위 착지(또는 피격 경직 종료) 이후에만 등장한다. 후반 압박은 `gap` 단축으로만 낸다.
- 페인트/가짜 바위·아이템·보너스는 **없음**(어떤 출처도 언급 안 함, 원작 영상 기억과도 일치). 기존 harden.html의 fake 돌·8웨이브 승리·HP 3 구조는 폐기.

### 11-6. 바위의 등장 방식과 "느낌" (연출 보강)
- 출처들은 "thrown at"(StrategyWiki), "come flying towards it"(geocities), "falling rocks / crashing down on their heads"(Bulbapedia·screenrant)를 섞어 쓴다. 즉 **화면 안쪽(절벽 위·뒤쪽)에서 던져져 포물선으로 날아와 머리 위에 떨어지는** 표현이 원작 체감이다. 구현: 바위 스프라이트를 대상 x 기준 뒤쪽 위(y=−60, 크기 0.4배)에서 출발해 착지점(y≈300, 크기 1.0배)으로 **곡선(뒤→앞으로 커지며)** 낙하시킨다. 수직 직선 낙하만 해도 규칙은 같지만, 이 "커지면서 다가옴"이 없으면 원작 느낌이 빠진다. 던지는 캐릭터는 원작에 보이지 않으므로 그리지 않는다.
- 그림자가 유일한 정확한 단서: 바위 자체는 원근 때문에 착지 타이밍을 읽기 어렵게(약간 빠른 이징 `easeInQuad`) 하고, 그림자는 선형으로 커지게 해서 "그림자를 보라"는 원작 공략이 실제로 유효하도록 만든다.
- 리듬: 웨이브가 "4명 동시" 일 때 4개 그림자가 동시에 나타나 "쿵" 하고 동시에 착지 → 파편이 동시에 튀는 것이 원작 특유의 장면. 순차 패턴은 0.15초 간격이라 "두두두둥" 느낌.
- 판정: 착지 프레임에 `hardened`이면 방어. 관용은 착지 50ms 안에 시작한 단발 tap 만(연타 제외) — §11-12 가 ±50ms 를 대체. 착지 후 누르는 것은 무조건 늦음(입력 버퍼 없음).
- 굳기 해제: 떼면 즉시 판정 해제, 시각 효과만 0.1초 페이드.

### 11-7. CPU 확정 (§8 보정)
- 셸 기본 CPU는 **Hard 수치(오프셋 90ms, σ 55, 홀드 180±60ms, 실수 3%, 헛굳기 2%)** 를 쓴다. 근거: RetroAchievements "Hard COM 3명 상대 50% 남기고 승리"가 '어렵지만 가능'하려면 사람이 완벽 tap 시 CPU 3명이 60~75초 안에 자연 탈락해야 하고, Hard 수치로 계산하면(홀드 180ms×12/s + 첫프레임 1 ≈ 3.2/발, 60초 동안 약 35발 ≈ 110 + 실수 1회) 정확히 그 범위에서 죽는다. Normal 수치는 40초 전후로 죽어 너무 싱겁다.
- CPU마다 **개별 편향**을 게임 시작 시 한 번 뽑는다: 오프셋 ±30ms, 홀드 ±40ms(정규). 세 CPU가 똑같은 프레임에 굳고 똑같이 죽는 것을 막는다.
- HP 30% 이하 절박 모드(홀드 −20%)는 유지. 헛굳기(바위 없는데 누름)는 200~350ms 홀드로 실행.
- 탈락한 CPU는 아무것도 하지 않는다. 사람 전원 탈락 후에도 CPU 모델은 동일하게 동작.

### 11-8. 화면 배치 보강
- 4명 가로 한 줄 x=165/375/585/795, 발 y=395(§6 유지). 원작의 HP 막대 위치는 출처로 확정하지 못했다(하단 배치는 추정). 셸 요구("각 플레이어 상태 항상 표시")를 만족하는 하단 막대 + 배지 유지.
- 각 막대 위에 작은 "HP" 라벨, 탈락 시 막대 회색 + "탈락", 생존자 1명 시 "승리!".
- 상단 중앙 "생존 N/4"만. 시간 표시 없음(원작에 없음 확인).

### 11-9. 여전히 불명(구현에 영향 없는 수준)
- 원작 HP 정확 수치·초당 감소율(막대만 표시, 공개 데이터 없음 — §11-4 값을 확정값으로 사용).
- 아나운서 정확 대사(자막 없음이므로 한국어 한 줄 "그림자를 보고 닿는 순간에만 딱딱하게!"로 대체).

- 난이도 선택 UI는 원작에 있으나 우리 셸에는 없음 → Hard 고정(§11-7).

### 11-10. 2차 비평가 보강 (완전성 검토, 2026-09)
2차 비평가가 Bulbapedia(Rock_Harden·시리즈 미니게임·Walkthrough Part 5), Serebii kidsclub, StrategyWiki(curl 본문), geocities pokemontours(본문), KoopaTV(게임 내 설명문 + 저자 플레이 분석)를 직접 다시 열어 대조했다. GameFAQs·RetroAchievements·TCRF·니코니코·IGN은 403/차단으로 원문 확인 불가. 새 출처 발견은 없었고, 규칙 서술(A 홀드, HP 소모, 바위 피격이 훨씬 큰 손실, 마지막 생존자 승리, 동점 시 챔피언 점수 없음, Easy/Normal/Hard/Hyper, Hyper = Hard 챔피언전 5연승)은 전 출처가 일치한다. 아래는 본문에 인라인 반영한 수정과 새로 확정한 항목이다.

1. **tap 비용 바닥값(-1) 삭제 [수정]** — KoopaTV: "A frame-perfect (and long) Rock Harden won't consume your HP, but if you hold down A much beyond that, it will." 따라서 소모는 홀드 시간에 순수 비례(-12/초)하고 정확한 순간의 tap은 손실이 거의 0이다. 이것이 "완벽한 사람은 이길 수 있고, 여유 있게 미리 누르는 사람은 진다"는 원작 리스크·리워드의 핵심이다(같은 출처: "뒤처지면 미리 눌러 버퍼를 두는 대신 정확한 프레임에 누르는 위험을 감수하게 된다").
2. **플레이어당 공중 바위 최대 1개 [수정]** — KoopaTV: "Rock Harden … having only one object flying at you". §5·§11-5의 "더블" 패턴을 폐기했다. 같은 플레이어의 다음 바위 그림자는 `이전 착지 시각 + max(0, gap(t) − 낙하시간)` 이후, 그리고 피격 경직 종료 이후에만 등장한다. 후반(60초+)에는 gap 0.8초 < 낙하시간이므로 사실상 "착지 즉시 다음 그림자"가 되어 쉼 없이 tap해야 하는 압박이 생긴다.
3. **피격 경직 0.85초 → 0.7초 [수정]** — 후반 gap 0.8초보다 경직이 길면 피격 후 다음 바위가 밀려 오히려 쉬는 시간이 생긴다. `hit` 0.2초 + `dizzy` 0.5초 = 0.7초로 두어 경직이 리듬을 끊지 않게 한다.
4. **동점(무승부) 판정 창 [보강]** — "같은 프레임" 은 실제로 거의 발생하지 않는다. 원작에서 동점은 "4명 동시" 패턴으로 마지막 2명이 같은 웨이브에 함께 깔릴 때 생긴다. 확정: 마지막 생존자들이 **같은 웨이브(착지 시각 차 ≤ 0.2초) 안에서 모두 HP ≤ 0** 이면 무승부. 그 외에는 나중에 죽은 쪽이 승자.
5. **투척 패턴은 반무작위 [확인]** — KoopaTV "rock patterns … at least semi-random", RetroAchievements 코멘트 "RNG 의존". §11-5의 gap × U(0.85,1.15)와 패턴 비율 추첨이 이를 재현한다. 완전 고정 리듬으로 만들지 말 것.
6. **한 판 길이 목표 [확인]** — KoopaTV "You probably won't survive for over one minute"(Hard CPU 기준). §11-5 곡선에서 완벽 tap이 아닌 보통 플레이어는 45~75초 사이에 탈락하고, Hard CPU 3명은 60~75초 안에 자연 탈락하도록 튜닝되어 있다. 120초 안전 상한은 유지(원작엔 없음, 도달 시 남은 HP 순).
7. **아이템·페이크·보너스 없음 [확인]** — 전 출처 어디에도 없다. 바위 크기 3종 자체도 추정이며, 크기별 HP 손실 차이는 "느낌" 목적(큰 그림자=큰 위협). 구현 부담이 크면 크기 1종(대, -30)으로 줄여도 원작 규칙에는 어긋나지 않는다.
8. **B 버튼 [확인]** — 게임 내 설명문이 A만 말한다. `b` 무시 유지.
9. **HUD 라벨** — 원작 텍스트 용어는 HP. 막대 옆 라벨 "HP", 수치 숫자 표시 없음(막대만).
10. **여전히 불명** — 원작 HP 정확 수치·초당 감소율, HP 막대 화면 위치(하단은 추정), 카메라 각도, 아나운서 대사. 모두 규칙에 영향 없는 수준이며 §11-4~11-8 확정값으로 구현 가능.

### 11-11. 구현 체크리스트(빌드 전 최종)
- `duration: 0`, `howto` 3줄(§11-2), 승자 `10000+HP` / 탈락자 `round(탈락초×10)`, 무승부 시 동일 점수 + "무승부!".
- 입력은 `g.p(i).down('a')`만. `b`·축 입력 무시. 키 코드 직접 참조 금지.
- 바위: 플레이어당 동시 1개, 그림자 선형 확대, 착지 50ms 안 단발 tap 관용(연타 제외, §11-12), 착지 후 입력은 늦음.
- HP: 100, 대/중/소 -30/-22/-15, 홀드 -12/초(바닥값 없음), 회복 없음, 피격 경직 0.7초.
- CPU: Hard 수치 + 개별 편향(§11-7). 사람 전원 탈락 후에도 CPU끼리 끝까지.
- 화면: x=165/375/585/795, 발 y=395, 하단 HP 막대+배지, 상단 "생존 N/4", 시간 표시 없음.

### 11-12. 구현 노트 (games/harden.html, 2026-09 v4) — §4·§11-3·§11-6 과 충돌 시 이 절이 우선
- CPU 홀드는 `max(press+hold, impact+0.04)` 까지 유지한다. §8 수치를 그대로 쓰면 hold < d 인 경우(Hard 약 4%, Normal~Hard 중간 약 8%) 착지 전에 손을 떼어 "조기 해제 피격"이 생겨 CPU가 38~49초에 전멸했다. 사람처럼 "누른 뒤엔 바위가 닿을 때까지 유지"로 바꾸자 CPU끼리 45~70초에 끝나 §11-3 목표(45~90초)에 들어온다. 실패 원인은 miss(3%)와 늦게 누름만 남는다.
- CPU 늦음 판정은 사람과 같은 규칙(§11-6 "착지 후 누르는 것은 무조건 늦음"): 뽑힌 오프셋 d < 0 이면 착지 뒤에 누른 것이라 피격. §8 의 "+50ms 까지 인정" 은 CPU 에게만 유리한 관용이라 쓰지 않는다 — 시뮬에서 이 관용 하나가 보통 사람 승률을 12%→4% 로 떨어뜨렸다.
- CPU 는 전원 Hard(§11-7) + 개별 편향(오프셋 ±30ms, 홀드 ±40ms), HP 30% 이하 홀드 −20% 절박 모드. Normal/중간 슬롯 배정(v2)은 §11-7 위반이라 폐기.
- 판정 관용(v3, §4·§11-11 최종): 착지 프레임에 굳어 있으면 방어. 추가로 착지 50ms 안에 시작한 **단발 tap**(최근 300ms 안 누름 1회)은 착지 직전에 뗐어도 방어. 떼기 기준 관용(v2의 "50ms 전 뗀 것까지")은 10Hz 연타가 65~69% 이기는 버그라 폐기. 착지 후 누름은 무조건 늦음. 규칙은 사람·CPU 동일하되 CPU 는 착지+40ms 까지 유지.
- 경직 중 플레이어도 웨이브 대상에 포함하고 남은 경직만큼 늦게 그림자를 띄운다(§11-4·§11-10-3, 피격 뒤 한 웨이브 통째로 쉬는 문제 해결).
- 점수: 생존자 10000+HP, 탈락자 round(탈락초×10). 같은 웨이브(≤0.2s) 묶음만 같은 점수.
  - 근거(v4, 헤드리스 시뮬 200~400판, 60fps, 실제 게임 스크립트, 2026-09 QA 반영 후 재측정): 1인 vs Hard 3명. Hard 와 같은 파라미터의 사람(90±55 / 180±60 / miss 3%) 승률 약 31%, 보통 사람(150±70 / 200±80 / miss 6%) 약 16%, 착지 즉시 떼는 보통 사람 약 28%. CPU 끼리만 한 판 길이 중앙값 56초, p90 65초, 최대 75초, 120초 상한 도달 0회. 연타·항상 유지·방치는 v3 와 같이 이득 없음(관용 규칙 불변).
- 웨이브 타이머는 §11-10-2 공식으로 잡는다: 다음 웨이브 시각 = max(이번 웨이브에서 경직 지연을 뺀 마지막 착지 + 0.02초, 지금 + gap(t)×U(0.85,1.15)). 경직 중인 사람의 늦춘 바위는 나머지 사람의 다음 웨이브를 늦추지 않는다(v4). 60초 이후엔 gap 0.8 < 낙하 1.12 라서 착지 직후 다음 그림자가 뜬다. 공중 바위 보유·탈락인 플레이어는 대상에서 빠진다. 착지 판정을 먼저 처리한 뒤 웨이브를 뽑는다.
- CPU 는 착지 뒤에도 남는 자기 바위 참조(`p.cr`)로 홀드를 계산한다. v3 는 착지 프레임에 `p.rock=null` 이 되어 CPU 가 늘 착지 순간 손을 떼(홀드·절박 모드가 죽은 코드) 사람보다 HP 소모가 적었다.
- 사람 전원 탈락 뒤(사람 1명 이상 판)는 관전 2배속으로 진행한다. 마지막 CPU 1명까지 겨루는 §2 규칙은 그대로다. 제목·카운트다운 화면에는 아나운서 자막을 그리지 않는다(play 상태에서만).
- 승자 확정 순간에는 `sfx.good` 만 울리고 `sfx.win` 은 1.5초 뒤 `g.finish()` 시 셸이 울린다(같은 팡파르가 두 번 겹치지 않게).
- 하단 HUD에 HP 막대 외에 "방어 N"(막은 바위 수)을 작게 표시한다 — HP 숫자는 여전히 표시하지 않는다. "방어!" 팝업은 사람 슬롯 전원에게 띄운다. 120초 상한 도달 시 HP가 가장 많은 생존자를 승자로 표시하고 결과 문구에 "120초 경과"를 붙인다.
- 탈락 포즈는 §1 대로 `sleep`(회색 #B9B0BA, alpha 0.55)을 살짝 기울여(rot 0.35) 바닥에 주저앉은 모습으로 그린다. 이전 버전의 옆으로 눕힌 `dizzy` 는 폐기.
