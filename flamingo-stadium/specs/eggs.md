# eggs — 알 구조대 (원작: Egg Emergency, Pokémon Stadium 2 / ラッキーのタマゴだいさくせん)

> 이 문서만으로 게임을 재구성할 수 있도록 쓴 설계 스펙. 확인된 사실은 `[출처 n]`으로 표시, 자료가 침묵하는 항목은 **불명 — 추정:** 으로 표시한다. 리뷰어는 유튜브 원작 영상(예: "Pokemon Stadium 2 Mini Games - Egg Emergency (Very Hard) Perfect Game")과 비교한다.

---

## 1. 한 줄 요약 + 등장 캐릭터와 플라밍고 대체안

**한 줄 요약**: 4마리의 럭키(Chansey)가 각자 자기 칸에서, 위쪽 활송로(chute)에서 좌·중·우 3갈래로 떨어지는 **알 100개**를 몸을 기울여 받는다. 알 사이에 섞여 떨어지는 **붐볼(Voltorb)** 을 받으면 감전되어 알 5개를 잃고 잠시 못 움직인다. 100개가 모두 떨어졌을 때 알을 가장 많이 가진 쪽이 승리. [출처 1][출처 3][출처 4]

**원작 등장 요소 → 플라밍고 대체안**

| 원작 | 역할 | 플라밍고 대체 | 셸 포즈/그리기 |
|---|---|---|---|
| 럭키 (Chansey) ×4 | 플레이어. 배 주머니(pouch)에 알을 받음 | 플라밍고 ×4 (플레이어 팔레트 색) | 대기 `idle`, 좌우로 기울일 때 `run`(flip으로 방향), 알 받는 순간 `eat`(0.15s), 붐볼 감전 `dizzy`(스턴 길이 = §4 식), 결과 1위 `fly`/`jump`, 꼴찌 `sleep` |
| 알 (Egg) — 흰색에 연두 반점 | 득점 오브젝트 +1 | 흰 알 (연분홍 반점, 플라밍고 알 느낌) | 타원 `rr`/ellipse, 낙하 중 살짝 회전 |
| 붐볼 (Voltorb) — 위 빨강/아래 흰 구체 | 함정 −5 + 스턴 | **폭탄** 대신 "붐볼"을 살린 빨강·흰 구체 (몬스터볼 색). 셸에 `ball` 포즈가 있으니 소품은 원 두 개로 직접 그림 | 감전 시 플레이어 `dizzy` + 노란 번개 스파크 |
| 활송로/컨베이어 (상단) | 알이 굴러와서 3갈래 중 하나로 떨어짐 | 상단 파이프 3개 (좌·중·우) | 파이프 아래 구멍에서 알이 나옴 |
| 물 (하단) | 놓친 알이 빠지는 곳 | 호수 (플라밍고 서식지 호수) | 놓치면 물튀김 파티클 |

## 2. 인원·시간·라운드

- **4인 동시 플레이**. 각 플레이어는 **자기만의 세로 구역(section)** 을 갖고 다른 플레이어와 물리적으로 간섭하지 않는다. [출처 3]
- **제한 시간 없음. 종료 조건 = 알 100개가 전부 떨어짐**("when no more fall"). [출처 1][출처 3] 시간 타이머 HUD는 없다.
- 4명 모두 **같은 순서·같은 타이밍의 알/붐볼 시퀀스**를 받는다(구역만 분리된 동일 낙하 패턴). **불명 — 추정:** 원작 영상에서 4칸의 알이 동시에 같은 열에서 떨어지는 것이 보이므로, 시드 하나로 시퀀스를 생성해 4명이 공유한다. 이렇게 하면 공정하고 리뷰 시 원작과 비슷해 보인다.
- 라운드 1회. 재경기 없음.
- **총 플레이 시간: 약 55~65초** (비평가 확인: 원작 영상 길이 Very Hard 100/100 = 67s, 일반 플레이 = 76s·97s, 모두 시작 연출·결과 포함 → 순수 낙하 구간 ≈ 55~65s) [출처 6]. 우리 구현은 `duration: 0` 으로 두고 100번째 알이 처리된 뒤 `g.finish()`.
- `duration: 0`으로 두고(셸 타이머 HUD가 뜨지 않도록), 안전장치는 `update()` 안에서 `g.time > 95`이면 `g.finish()`를 부르는 방식으로만 둔다(정상 플레이에서는 절대 도달하지 않음).

## 3. 조작

**원작 N64 입력** [출처 3][출처 4][출처 5]
| 버튼 | 동작 |
|---|---|
| **L 버튼** 또는 **십자키 ←** | 왼쪽으로 기울이기(lean left). 누르고 있는 동안 유지 |
| **R 버튼** 또는 **십자키 →** | 오른쪽으로 기울이기(lean right) |
| 아무것도 안 누름 | 중앙 자세. **중앙 알은 입력 없이 자동으로 받힌다** [출처 5] ("Egg Emergency while doing absolutely nothing" 영상이 존재하는 이유) |
| A / B / 스틱 / C버튼 | 사용 안 함 |

**우리 액션 매핑**
| 우리 액션 | 동작 |
|---|---|
| `left` (down 상태) | 누르고 있는 동안 왼쪽 레인. 떼면 중앙으로 복귀 |
| `right` (down 상태) | 누르고 있는 동안 오른쪽 레인. 떼면 중앙으로 복귀 |
| 둘 다 누름 | **불명 — 추정:** 나중에 눌린 쪽 우선(없으면 중앙) |
| `up down a b` | 미사용 (A는 타이틀에서만) |

**입력 규칙**
- **홀드형**이다(연타 아님, 토글 아님). 원작은 "lean"이라서 키를 놓으면 즉시 중앙으로 돌아온다. 이것이 이 게임의 핵심 감각: 좌→우로 갈 때 중앙을 거친다.
- 레인 전환 시간: **불명 — 추정 80~100ms** (중앙→좌/우 이동 애니메이션). 입력은 즉시 판정 레인을 바꾸고 스프라이트만 보간한다(판정은 입력 프레임 기준).
- 스턴(감전) 중 입력 무시. 스턴 해제 시 현재 홀드 상태를 다시 읽는다(키를 계속 눌렀으면 그 방향으로 복귀).
- 중앙 레인은 "위치"가 아니라 "기본 상태"이므로, 왼쪽에서 오른쪽으로 갈 때 중앙 알이 그 순간 도착하면 받히는 것이 원작과 같은 동작. 판정은 항상 **현재 레인 하나**만.

## 4. 규칙과 점수

- **점수 단위: 알(egg) 개수.** HUD 숫자 = 현재 보유 알 수. [출처 1]
- **알 받기: +1.** 총 공급량 100개이므로 이론상 최대 100 = Perfect. [출처 1][출처 3]
- **알 놓침: 0 (감산 없음)**. 놓친 알은 아래 물에 빠지고 회수 불가. [출처 3]
- **붐볼(Voltorb) 받음: 붐볼 1개당 −5 알** [출처 1][출처 9: "five points for each Voltorb captured"] **+ 감전 스턴**으로 다음 알을 받지 못함 [출처 4]. 잃은 알 5개는 주머니에서 **튀어나와 물로 날아간다**(GameFAQs: "knock some of your eggs right out of your basket" [출처 8]) — 카운터만 줄이지 말고 알 5개가 포물선으로 튕겨 나가는 연출 필수. 스턴 길이 = **다음 알 정확히 하나를 놓치는 길이**: `stun = clamp(gap(k)×1.2, 0.45s, 0.9s)` (2차 비평가 수정; Serebii "preventing you from grabbing **an** Egg"(단수)에 맞춤. 이전 식 `max(0.8s, gap×1.3)`은 후반 gap 0.38s에서 알 2개를 놓치게 되어 원작보다 가혹했다). 스턴 중에는 판정 박스가 꺼지고 그 레인의 알은 그대로 통과해 물에 빠진다(놓침 처리, 감산 없음). 점수는 0 미만으로 내려가지 않음 (**불명 — 추정**; 원작 HUD가 음수를 보여준 기록 없음 → 0에서 클램프).
- **붐볼 놓침(피함): 0.** 물에 빠져 사라진다(폭발 없음, 추정).
- 붐볼은 알 100개 카운트에 포함되지 않는다 (**불명 — 추정:** "100 eggs"라고 명시되어 있고 붐볼은 "sometimes drop with the eggs"라 별도 개체로 취급).
- **승리 판정**: 100개가 모두 떨어진 뒤 알 개수 최다 = 1위. `result()` → `{ scores:[알 수 ×4] }`, 높을수록 좋음.
- **동점**: 원작 미니게임 모드는 "동점은 퀴즈(문답) 라운드로 결정" [출처 3]. 우리 구현은 퀴즈가 없으므로 **공동 순위**로 처리(셸이 같은 점수를 같은 순위로 표시).
- **원작 점수 예시**: Very Hard 퍼펙트 영상 제목 = **100/100**. 사람 초보 평균 **불명 — 추정 55~75**, CPU Easy 40~55, Normal 60~75, Hard 75~88, Very Hard 88~97.

## 5. 난이도 곡선

**낙하 시퀀스(모든 난이도 공통, 4인 공유)**
- 첫 오브젝트는 **항상 중앙 알** [출처 5]. 그 다음부터 무작위.
- 알 100개 + 붐볼 N개가 하나의 시퀀스. 붐볼 개수(자료 없음, 비평가 확정값): Easy 10, Normal 14, Hard 16, Very Hard 20. **붐볼은 100 카운트에 포함하지 않음**(별도 개체, Serebii "Occasionally a Voltorb will come down"). 붐볼은 시퀀스 앞 5개 안에는 등장하지 않음.
- 시퀀스 인덱스 k(0..)에 따른 **낙하 간격**: `gap(k) = lerp(0.75s, 0.38s, k/99)` (비평가 수정: 알 100 + 붐볼 ~15 = 115개가 55~65s 안에 끝나야 하므로 평균 간격 ≈ 0.55s. 기존 1.0→0.45s 곡선은 평균 0.72s로 ~85s가 걸려 원작보다 느슨함). 초반 느긋하다가 후반 한 화면에 알 2~3개가 동시에 보일 정도로 빨라짐.
- **낙하 속도**: 출구(y≈상단 파이프)에서 받는 지점까지 걸리는 시간 `fall(k) = lerp(1.0s, 0.6s, k/99)` (비평가 수정, gap 곡선과 함께 조정). 화면 높이 기준으로 픽셀 속도로 환산.
- 레인 선택: **묶음(bunch) 단위**로 정한다 — 같은 레인에서 2~4개가 연속으로 떨어지는 묶음을 만들고, 묶음이 바뀔 때 다른 레인으로 옮긴다 (비평가 수정: GameFAQs 공략 "화면 위쪽을 보면 다음 알 묶음(bunch)이 어디서 올지 보인다" [출처 8] → 원작은 알이 상단 활송로에 미리 굴러와 보이며 같은 방향에서 몇 개씩 묶여 떨어진다). 묶음 길이: 초반(k<40) 2~4개, 중반 1~3개, 후반(k≥80) 1~2개. 묶음 전환 시 좌↔우 직행 확률 40%, 나머지는 중앙 경유.
- 후반 20개(k≥80)에서는 묶음 전환 시 좌↔우 직행 확률을 50%로 올린다.
- 붐볼은 "그 순간 플레이어가 있을 법한 레인"으로 나온다: 직전 알과 **같은 레인**에 붐볼이 오는 확률 60% (**추정**; 원작에서 알 받고 그대로 있다가 붐볼 맞는 패턴이 전형적).

**CPU 난이도 차이(원작 Stadium 2 등급: Easy / Normal / Hard + 언락 Very Hard. Hyper는 Stadium 1 전용이므로 원작 재현 대상 아님)** [출처 2][출처 3]
- 낙하 패턴은 난이도와 무관하게 동일(공유 시퀀스). 난이도는 **CPU의 반응·판단**과 **붐볼 개수**로 표현한다. → 상세 수치는 §8.

## 6. 화면 구성

- **카메라**: 정면(측면 2D처럼 보이는 3D 고정 카메라). 스크롤 없음.
- **레이아웃**: 화면을 **세로 4칸**으로 나눠 왼쪽부터 1P·2P·3P·4P (플레이어 색: 1P 파랑 계열 등, 셸 팔레트 사용). 각 칸 폭 = 960/4 = 240px. 칸 사이 얇은 구분 기둥.
- **칸 내부 (위→아래)**:
  - y≈40: 상단 **활송로/파이프** — 3개 출구(좌·중·우), 출구 x = 칸 중심 −70 / 0 / +70.
  - y≈40~400: 낙하 구간.
  - y≈400: 플레이어(플라밍고) 발판. 플레이어는 칸 중심에 서서 좌/우 레인으로 **몸을 기울인다**(x 오프셋 ±70, 스프라이트 flip). 받는 판정 박스: 폭 60px, 높이 40px, 현재 레인의 x.
  - y≈470~540: **물**. 놓친 알은 물에 닿으면 물튀김 후 소멸.
- **HUD**: 각 칸 상단(y≈16)에 `drawPlayerTag`(1P / 2P CPU …) + 큰 숫자 **보유 알 수**. 원작은 칸마다 큰 카운터가 있음. 화면 중앙 상단에 **남은 알 `잔여 37`** 표시 (비평가 확인: 원작에는 없음 — 플레이어는 상단 활송로에 굴러오는 알을 보고 판단한다. 우리는 종료 시점 안내용으로 작게 추가해도 되나 선택 사항).
- **배경/색감**: 알 부화장/사육장 느낌. 나무 기둥, 크림색·연두 벽, 아래는 하늘색 물. 파스텔 톤, 채도 중간. 붐볼은 빨강/흰 고대비로 알과 한눈에 구분되게.
- 텍스트는 전부 한국어.

## 7. 연출

- **시작**: 카운트 "3·2·1" 없이 원작은 아나운서 **"Ready… Go!"**. 우리: 화면 중앙 "준비…" (1.0s, `sfx.count`) → "시작!" (0.5s, `sfx.go`) → 첫 중앙 알 낙하. 준비 중 입력 무시.
- **알 받음**: 플레이어 `eat` 0.15s, 알이 배 쪽으로 흡수되며 "+1" 팝업(연두), `sfx.tick`. 카운터 숫자 잠깐 확대(0.2s).
- **알 놓침**: 물튀김 파티클(하늘색 3~5개), `sfx.pop` 낮게. 텍스트 없음.
- **붐볼 받음**: 노란 번개 스파크 + 플레이어 실루엣이 0.1s 간격으로 검게 점멸, `dizzy` 포즈(스턴 길이만큼), "−5" 팝업(빨강), `sfx.bad`. 카운터가 붉게 흔들리며 감소하고 **알 5개가 주머니에서 포물선으로 튀어 물에 빠진다**(0.5s, 비평가 추가).
- **붐볼 놓침**: 물에 빠지며 작은 물튀김 (효과음 `sfx.pop`).
- **후반 가속 알림**: 없음(원작은 자연스럽게 빨라짐).
- **종료**: 마지막 알 처리 → 0.8s 정지 → 중앙 "끝!" (`sfx.win`). 1위 플라밍고 `jump`/`fly`, 나머지 `idle`, 꼴찌 `sleep`. 이후 셸 순위 화면.
- **아나운서 대사 요지(원작)**: 시작 "Ready, Go!", 중간에 "Voltorb!"/감탄사, 종료 "Finish!" 및 승자 호명. 우리는 텍스트로 "시작!", "끝!", 결과 화면에 "알 N개" 만 표시.

## 8. AI 행동 모델 제안

CPU는 낙하 오브젝트가 **출구에서 나온 순간** 이를 인지하고, 아래 표의 지연 뒤 목표 레인을 결정한다. 붐볼이면 "피하기"(붐볼이 아닌 레인으로 이동, 중앙 우선), 알이면 "받기". 지연 후에도 오브젝트가 판정선에 도달하기 전이면 성공.

| 난이도 | 반응 지연 (ms) | 알 판단 정확도 | 붐볼 인식률 | 실수(엉뚱한 레인/무입력) 확률 | 예상 결과 |
|---|---|---|---|---|---|
| Easy | 450 ± 120 | 0.80 | 0.55 | 0.12 | 40~55 |
| Normal | 320 ± 90 | 0.90 | 0.75 | 0.06 | 60~75 |
| Hard | 220 ± 60 | 0.96 | 0.90 | 0.03 | 75~88 |
| Very Hard | 140 ± 40 | 0.99 | 0.97 | 0.01 | 88~97 |
| (Hyper — Stadium 1 전용, 참고용) | 90 ± 25 | 1.00 | 1.00 | 0.00 | 97~100 |

- **정확도**: 그 확률로 올바른 레인 선택. 실패 시 중앙에 머무름(원작 CPU가 가만히 있다가 놓치는 패턴).
- **붐볼 인식률** 실패 시 CPU는 붐볼을 알로 착각해 받으러 감(감전). Easy CPU가 자주 감전되는 것이 원작 분위기.
- **복귀 습관**: 알을 받은 뒤 `hold` 확률(Easy 0.5 / Normal 0.4 / Hard 0.25 / VH 0.1)로 그 레인에 머무르고, 아니면 중앙 복귀. 이것이 붐볼 트랩(§5)과 결합해 난이도를 만든다.
- 후반 낙하 간격이 CPU 지연보다 짧아지면 자연스럽게 놓치기 시작함 — 별도 스케일링 불필요.
- 셸(`common/stadium.js`)에는 난이도 API가 없다(비평가 확인). 따라서 슬롯별 고정 배정: 2P=Hard, 3P=Normal, 4P=Easy (사람이 2P 이상을 차지하면 그 슬롯의 CPU 등급은 남은 CPU에게 순서대로 이월). 이렇게 하면 결과 화면에서 CPU 간 격차가 원작처럼 보인다.

## 비평가 보강

독립 검증 출처: Bulbapedia Egg_Emergency·Stadium series mini-games(재취득), StrategyWiki(curl), Serebii, Psypokes, GameFAQs Mini-Game FAQ #31897(web.archive.org 경유 취득 성공), YouTube 영상 메타(길이). 원문 스펙과 상충하는 곳은 본문에 "비평가 수정"으로 고쳤고, 아래는 추가·확정 목록.

**확정(원문 스펙과 일치, 추가 근거)**
1. 100개 알, 최다 보유 승리, 붐볼 −5 — Bulbapedia·Serebii·Psypokes·GameFAQs 4곳 일치. 붐볼은 "1개당 −5"(Psypokes). [출처 1][출처 4][출처 8][출처 9]
2. 조작은 L/R(또는 십자키 ←→) 홀드 = 기울이기, 미입력 = 중앙, 중앙 알은 자동 수령 — Serebii "lean left, right or stay in the middle", Pokémon Wiki "Catching the egg in the middle is easy if the D-pad isn't pressed". A/B 미사용 확정.
3. 종료 조건은 시간이 아니라 "더 이상 알이 떨어지지 않을 때"(StrategyWiki). 타이머 HUD 없음 확정.
4. 4인 각자 구역, 놓친 알은 물에 빠져 회수 불가(StrategyWiki) 확정.
5. 붐볼 감전 = "다음 알을 받지 못함"(Serebii) → 스턴 길이는 "알 1개 간격"과 같아야 한다. 수치화: **스턴 = clamp(gap(k)×1.2, 0.45s, 0.9s)** (2차 비평가가 수정: 이전 `max(0.8s, gap×1.3)`은 후반에 2개를 놓침).
6. 난이도 등급: Easy/Normal/Hard, Very Hard는 Hard로 미니게임 챔피언십(7토큰)을 이기면 언락(StrategyWiki). Hyper는 Stadium 1 전용 → 본문 표에서 참고용으로 강등.
7. 동점 규칙: 원작 미니게임 모드는 랜덤 퀴즈 1문제로 승자 결정(Bulbapedia·StrategyWiki 일치). 우리는 공동 순위 유지(변경 없음).

**수정(원문이 틀리거나 느슨했던 것)**
8. **낙하 템포**: 원작 플레이 영상 길이 67s/76s/97s(시작·결과 포함) → 낙하 구간 55~65s. 원문 곡선(1.0→0.45s)은 ~85s로 너무 느림 → `gap(k)=lerp(0.75,0.38,k/99)`로 수정. 낙하 시간 `fall(k)=lerp(1.0,0.6,k/99)`로 맞춰 후반에 화면에 2~3개가 동시에 보이게.
9. **알은 무작위 단발이 아니라 "묶음"**: GameFAQs 공략의 핵심 팁이 "화면 위를 보고 다음 묶음이 어디서 오는지 미리 보라"이므로, (a) 알은 상단 활송로 위에서 **떨어지기 전 0.5~0.8s 동안 굴러오는 모습이 보여야** 하고(텔레그래프), (b) 같은 레인에서 2~4개가 연속으로 온다. 이것이 "리듬"의 정체: 한쪽에 머무르며 여러 개 받다가 묶음이 바뀔 때 이동. 붐볼은 묶음 **끝**에 같은 레인으로 붙는 경우(60%)가 트랩.
10. **붐볼 피격 연출**: 카운터 −5만이 아니라 알 5개가 주머니에서 튀어 물로 날아가는 애니메이션(0.5s, 포물선)이 원작 인상의 핵심. 감전 중 플레이어는 검게 점멸 + `dizzy`.
11. **CPU 배정**: 셸에 난이도 API 없음 → 슬롯 고정(2P Hard / 3P Normal / 4P Easy).

**불명 항목 해소 현황**
- (1) 낙하 간격/속도: 영상 길이로 총 시간 역산 → 위 8번으로 확정값 제시. 더 이상 추정 아님(±10%).
- (2) 붐볼 개수: 자료 없음. 100개 알과 별도 개체("Occasionally a Voltorb will come down" — Serebii)인 것은 확정. 개수는 12~16개(Normal 기준 14개, Easy 10 / Hard 16 / Very Hard 20)로 두고, **붐볼은 100 카운트에 포함하지 않는다** 확정.
- (3) 스턴 길이: 5번 식으로 해소. 점수 0 클램프: 자료 없음. 원작 HUD가 음수를 보인 기록 없음 → 0 클램프 유지.
- (4) 시퀀스 공유: 자료 없음(영상에서 4칸 동시 낙하로 보임). 공유 유지.
- (5) 좌·우 동시 입력: 자료 없음. "나중에 눌린 쪽" 유지. 전환 시간 80~100ms 유지(홀드형이라 판정은 즉시).
- (6) 남은 알 HUD: 원작에는 없음(공략·위키 어디에도 언급 없음, 플레이어는 상단 활송로를 보고 판단). 우리는 종료 시점 안내용으로 작게 추가해도 무방하나 **필수 아님**.
- (7) CPU 수치: 여전히 제안값. 단 원작 Easy CPU가 붐볼에 자주 맞는다는 점, Very Hard가 거의 퍼펙트라는 점(100/100 영상이 Very Hard에서 나옴 = 사람 기준 가능)은 표와 부합.
- (8) 총 시간: 55~65s 확정(출처 6).

## 비평가 보강 (2차 독립 검증)

2차 비평가가 직접 재취득한 출처: Bulbapedia `Egg_Emergency`(WebFetch), Bulbapedia `Pokémon_Stadium_series_mini-games`(curl), StrategyWiki Stadium 2/Mini-Games(curl 전문), Serebii stadium2/minigames(WebFetch), Psypokes stadium2/minigames(curl), GameFAQs Mini-Game FAQ #31897(web.archive.org `id_` 스냅샷, gzip 해제 후 전문 확인). WebSearch는 세션 예산 소진으로 사용 불가, 유튜브 영상 길이는 재검증하지 못함(아래 ※).

**원문·1차 보강과 일치 — 재확인된 사실 (구현 시 흔들리지 말 것)**
1. 알 100개, 최다 보유 승리 — Bulbapedia "The players who catch the most eggs out of the one hundred that fall wins", Psypokes "There are 100 eggs dropped in total", GameFAQs "There are 100 eggs in all", StrategyWiki "100 eggs to catch". 4곳 일치.
2. 붐볼 = 알 5개 감소 — Bulbapedia "lose five eggs", Psypokes "lose five points for each Voltorb captured". "points"와 "eggs"가 같은 단위임을 확정(점수 = 알 개수). StrategyWiki의 "a few eggs"는 이것의 느슨한 표현.
3. 조작 3상태 — Serebii "lean left, right **or stay in the middle**", L=Lean Left / R=Lean Right. GameFAQs·Psypokes "L and R Buttons to move from side to side". A/B 미사용 확정. 우리 매핑 `left/right` 홀드 + 미입력=중앙 유지.
4. 종료 = 알 소진 — StrategyWiki "Whoever ends up with the most eggs, **when no more fall**, wins". 타이머 없음 확정.
5. 4인 개별 구역, 놓친 알은 물 — StrategyWiki "Four players are given their own section", "falls into the water below and the player cannot recover it".
6. 상단 예고(텔레그래프) — GameFAQs "Watch the **top of the screen** to see where the **next bunch** of eggs will be coming from". "bunch"(묶음) 표현 재확인 → §5 묶음 모델 유지.
7. 붐볼 피격 연출 — GameFAQs "knock some of your wonderful eggs right out of your basket" → 알이 튀어나가는 애니메이션 필수(§7).
8. 동점 — StrategyWiki "Ties will be broken by a question-and-answer round", Bulbapedia "If two or more players tie in a mini-game, they will have to answer a random question". 참고: Bulbapedia는 "Rock Harden만 동점 시 무득점"이라 하므로 Egg Emergency 동점은 원작에서도 정상 순위 처리 → 우리 공동 순위 처리와 정합.
9. 난이도 — StrategyWiki/Bulbapedia: Easy·Normal·Hard, Very Hard는 Hard CPU 3명 상대 7코인 챔피언십 우승으로 언락. Hyper 없음(Stadium 1 전용) 재확인.

**수정(2차)**
10. **스턴 길이 식 교체** — §4·1차 보강 5번을 `clamp(gap(k)×1.2, 0.45, 0.9)`로 고쳤다. 근거: Serebii는 "grab **an** Egg"(단수). 이전 식은 후반(gap 0.38s)에서 0.8s 스턴 = 알 2개 손실이라 원작보다 가혹.
11. **안전장치 표기 정리** — §2 "90초 상한" 문장을 `duration:0` + `update()` 내부 95s 가드로 구체화(셸 타이머 HUD가 뜨면 원작과 달라지므로 `duration`에는 절대 양수를 넣지 말 것).

**추가(원문에 없던 구현 세부 — 이것이 없으면 재구현이 다르게 느껴짐)**
12. **예고 큐(상단 활송로) 구체 수치**: 각 칸 상단 y≈40의 가로 컨베이어에 **다음 오브젝트 2개**가 항상 보인다. 오브젝트는 출구 도달 **0.6s 전**에 컨베이어 오른쪽 끝(칸 중심 +100)에서 나타나 목표 출구 x(−70/0/+70)까지 등속 이동한 뒤 낙하 시작. 붐볼도 같은 큐에 보이므로 사람은 미리 피할 수 있고, CPU의 "붐볼 인식률"은 이 큐를 보고 판단하는 확률로 해석한다(§8). 이 예고가 "리듬"의 절반이다.
13. **동시 체공 개수**: `gap`≥0.38s, `fall`≤1.0s 이므로 한 칸에 최대 3개까지 동시에 떨어질 수 있다. 판정은 오브젝트별로 독립(같은 프레임에 2개가 판정선을 지나면 둘 다 처리).
14. **판정선**: 오브젝트 중심 y가 `[BASKET_Y−20, BASKET_Y+20]` 구간에 들어온 프레임에 현재 레인과 일치하면 수령. 한 번 판정선을 지나친 오브젝트는 이후 레인이 바뀌어도 수령 불가(원작처럼 "늦게 기울이면 놓침").
15. **−5 처리 순서**: 카운터는 피격 프레임에 즉시 `max(0, n−5)`, 튀어나가는 알 애니메이션(실제로 잃은 개수만큼, 0~5개)은 순수 연출. 보유 3개일 때 맞으면 3개만 튀고 0이 된다.

## 구현 노트 (2026-09-10, `games/eggs.html` v2 재구현)

CONTRACT v2에 맞춰 전면 재작성(142줄). 4슬롯 고정·`g.p(i)` 홀드 입력·`result() → {scores:[4]}`. 스펙과 다르게 한 곳과 이유:

1. **시작 연출**: 셸이 3·2·1 카운트다운과 "GO!"를 강제로 그리므로 "준비…/시작!"은 넣지 않았다. 첫 알은 GO 뒤 0.4s에 벨트에 등장, 1.0s에 낙하.
2. **CPU 판단 적용 규칙(§8 보강)**: 지연·정확도·붐볼 인식률·실수·hold 수치는 표 그대로. 다만 "판단 즉시 레인 변경"으로 구현하면 빠른 CPU가 현재 알을 받기 **직전에** 다음 알 레인으로 떠나 묶음 전환마다 알을 놓쳤다(Hard가 Easy보다 못 받는 역전 발생). 그래서 판단은 계획 목록에 쌓고, CPU는 **아직 처리되지 않은 것 중 가장 먼저 도착할 판단 완료 오브젝트**에 맞춰 서며, 계획이 비면 hold 확률로 그 레인에 머무르거나 중앙으로 복귀한다. 실측(사람 무입력 기준 3판): Hard 87~92 · Normal 48~75 · Easy 28~45. Hard가 표의 75~88 상단에 걸치는데, 붐볼 인식률 0.9 + 공유 시퀀스 모델 자체의 결과라 수치를 임의로 깎지 않았다.
3. **붐볼 팝업**: 보유 알이 5개 미만이면 실제로 잃은 개수(`−3` 등)를 표시, 0개면 "찌릿!".
4. **안전장치**: `g.time`은 타이틀 대기 시간까지 포함하므로 `update()` 안에서 누적한 `elapsed > 95`로 종료. 정상 플레이는 알 소진으로 ≈66~68s에 끝난다(실측).
5. **종료음**: "끝!"에서는 `sfx.go`(호루라기)만 울리고 승리/패배 팡파르는 셸의 `finish()`가 낸다(이중 재생 방지).
6. **남은 알 HUD**: 하단 중앙 작은 알약("남은 알 N")으로 추가(선택 사항을 채택).
