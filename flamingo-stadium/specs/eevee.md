# eevee — 잽싼 밍고 (원작: Eager Eevee, Pokémon Stadium 2 / N64 Mini-Games)

> 이 문서만 보고 `games/eevee.html`을 다시 만들 수 있어야 한다. 확정 사실은 [확정], 출처가 침묵한 부분은 "불명 — 추정: …"으로 표기. 원작 영상(YouTube "Pokemon Stadium 2 Eager Eevee")과 비교 검수되므로 수치는 최대한 구체적으로 적었다.

## 1. 한 줄 요약 · 등장 캐릭터와 플라밍고 대체안

**한 줄 요약**: 이브이 4마리가 음악에 맞춰 원형으로 빙글빙글 도는 "의자 뺏기(musical chairs)" 변형 반응속도 게임. 원 중앙의 나무 뚜껑을 에이팜(Aipom)이 잡고 있다가 음악이 멈추면 뚜껑을 들어 올리고, 그 순간 **A를 가장 빨리 누른** 이브이가 안에 있는 과일을 먹어 점수를 얻는다. 뚜껑이 닫혀 있을 때 뛰어들면(플라잉/false start) 뚜껑에 얼굴을 박고 몇 초간 기절, 뚜껑 안에 **피콘(Pineco)**이 들어 있으면 폭발해 다음 라운드를 쉬어야 한다. 총 5라운드, 점수 합계 최다 승리. [확정: 규칙·점수·B 페이크·에이팜 페이크·5라운드] 원작 미니게임 랭킹에서 "반응 타이머가 N64치고 정밀해서 1/100초 차이로 승부가 갈린다"고 평가됨 [확정].

## 2. 인원 · 시간 · 라운드 구조

- **4인 동시** [확정]. 사람 1~4명 + 나머지 COM. 모두 같은 뚜껑을 노린다(공유 오브젝트 1개).
- **제한 시간 없음, 라운드제** [확정: 5 rounds]. `duration: 0`, 게임이 `g.finish()` 호출.
- **종료 조건**: 5라운드 완료. 조기 종료 없음(피콘 페널티는 라운드 스킵일 뿐 탈락 아님).
- 라운드 1개의 단계 (시간은 불명 — 추정, 원작 영상 체감 기준):
  1. `intro` 1.0s: "라운드 N / 5" 자막. 에이팜이 뚜껑에 앉음. 이번 라운드 쉬는 플레이어(피콘 페널티)는 원 밖으로 이동해 `sleep`.
  2. `circle` (돌기): 이브이들이 원을 따라 걷는다. 길이 = `2.5 + rand()*3.5` s (2.5~6.0s). 이 구간 중 **페이크 이벤트** 0~2회 발생(§5).
  3. `open` (뚜껑 열림): 음악 정지 → 0.12s 뒤 에이팜이 뚜껑을 들어 올림(lift 0→1, 0.15s). 이 시점부터 `hit('a')`가 유효. **입력 창(window) 1.2s**: 첫 도착자 확정 후에도 0.35s(딸기 2등용) 더 받고 닫음.
  4. `resolve` 1.6s: 도착 순서 판정, 과일 먹기 `eat`, 점수 팝업 "+500" 등. 피콘이면 폭발 연출 1.2s.
  5. `settle` 0.8s: 뚜껑 다시 덮임, 점수 HUD 갱신, 다음 라운드.
- 라운드 1개 ≈ 6~10s, 5라운드 총 40~55s + 결과.

## 3. 조작

| N64 | 원작 기능 | 우리 액션 |
|---|---|---|
| A 버튼 | 중앙으로 돌진해 과일 잡기(retrieve) [확정] | `a` (`g.p(i).hit('a')`, 눌린 프레임) |
| B 버튼 | **페이크 대시**(fake a retrieval): 돌진하는 척만 하고 제자리. 상대(특히 사람)가 낚여 플라잉하게 만든다 [확정] | `b` (`hit('b')`) |
| Control Stick / D패드 | 사용 안 함 — 이동은 자동(원을 따라 자동 회전) [확정: StrategyWiki는 A·B만 명시] | `up down left right` 무시. `axis()` 사용 안 함. |
| C 버튼 | 사용 안 함 | 무시 |

- **상태별 입력 표**는 §11(2차 비평가 보강 1번) 참조 — intro/settle 중 A는 무시(스턴 아님), circle·페이크 중 A = 플라잉, open 중 A = 돌진.
- **연타 무의미**: 라운드당 A는 **첫 1회만** 판정. 뚜껑이 닫힌 상태에서의 A = 플라잉(false start) → 그 플레이어는 `stun` **2.0s** 동안 모든 입력 무시 [확정: "lose a few seconds of activity", 초 수는 불명 — 비평가 조정 2.0s("a few seconds"의 하한, 1.5s는 너무 짧음)]. 스턴이 풀리기 전에 뚜껑이 열리면 그 라운드 사실상 포기.
- **홀드 무효**: `down('a')`를 계속 누르고 있어도 열리는 순간 자동 반응하지 않는다(반드시 열린 뒤 새로 눌러야 함 — 불명, 추정. 원작이 "false start"를 페널티로 두는 이상 홀드 자동 반응은 없어야 규칙이 성립).
- **B 페이크**: `jump` 0.3s 모션만. 점수 영향 없음, 쿨다운 0.5s. **뚜껑이 열린 뒤에도 B는 유효**(비평가 수정: 원작 공략 "피콘이면 B로 페인트해 상대가 대신 물게 하라" — PokeCommunity). 단 스턴 중·휴식 중에는 무효.
- **판정 정밀도**: 열린 시각 `tOpen`으로부터 각 플레이어의 `hit('a')` 시각 차이 `dt_i`(ms 단위, 프레임 시간 기반)로 순위. 같은 프레임 동시 입력 = **동시 도착** → 둘 다 득점 [확정].
- 라운드를 쉬는 플레이어(피콘 페널티) 입력은 전부 무시.

## 4. 규칙과 점수

- **점수 단위**: 포인트(pt). 시작 0. [확정]
- **과일 종류와 값** [확정: StrategyWiki/Fandom]:
  | 과일 | 값 | 비고 |
  |---|---|---|
  | 딸기(Strawberries) | **100 × 잡은 개수** | 접시에 여러 개(불명 — 추정: 라운드마다 **6~10개**, 원작 5,100pt 기록에 딸기 600이 필요하므로 1등이 6개까지 가능해야 함). **1등이 더 많이, 2등이 더 적게** 나눠 가짐. 추정 배분: 1등 = ceil(N×0.6), 2등 = N − 1등, 3등 이하 0. 동시 도착이면 절반씩(홀수는 둘 다 올림). |
  | 포도(Grapes) | **500** | 1등 독식. 동시 도착 시 둘 다 500. |
  | 멜론(Melon, 큰 초록 공) | **1000** | 1등 독식. 동시 도착 시 둘 다 1000. |
  | 피콘(Pineco) | **페널티** | 1등으로 문 플레이어: 폭발, 점수 가산 없음, **다음 라운드 참가 불가**(lose a turn / sit the next round out) [확정]. 2등 이하는 무사(불명 — 추정: 첫 도착자만 문다). 5라운드째 피콘을 물면 쉴 라운드가 없으므로 페널티 사실상 없음 → 대신 **−500pt**(불명 — 추정, 원작에는 근거 없음. 마지막 라운드 피콘의 무의미함을 막기 위한 우리 규칙; 최저 0 클램프). |
- **플라잉(false start)**: 감점 없음, 스턴 2.0s [확정: 감점 언급 없음].
- **아무도 A를 안 누름**: 입력 창 1.2s가 지나면 뚜껑이 닫히고 아무도 득점 못 함(불명 — 추정).
- **라운드별 과일 출현 확률** (불명 — 추정, GameFAQs 팁 "처음 3라운드는 즉시 A, 4라운드는 피콘 확인, 마지막 라운드가 항상 가장 점수 큼"을 반영):
  | 라운드 | 딸기 | 포도 | 멜론 | 피콘 |
  |---|---|---|---|---|
  | 1 | 50% | 35% | 15% | 0 |
  | 2 | 40% | 35% | 20% | 5% |
  | 3 | 30% | 30% | 25% | 15% |
  | 4 | 20% | 25% | 20% | **35%** |
  | 5 | 0 | 25% | **65%** | 10% |
  (비평가 수정: 원작 RetroAchievements 기록상 한 판 최고 5,100pt·Hard 4,000pt 도전과제가 존재 → 멜론이 1라운드부터 나올 수 있어야 한다. 기존 표는 상한이 2,500~3,500이라 너무 낮았음.)
- **승리 판정**: 5라운드 후 합계 최다 [확정]. 셸 `result()`: `scores = [pt×4]`, `lowerIsBetter` 없음.
- **동점 처리**: 원작은 퀴즈로 결정 [확정: "Ties will be broken by a question-and-answer round"]. 우리는 퀴즈 없이 **셸 공동 순위**에 맡김. 대안(선택): 동점자끼리 보너스 라운드 1회(멜론 고정).
- **원작 점수 예시** (추정 재구성): R1 딸기 5개 → 1P 300, COM2 200 / R2 포도 → COM1 500 / R3 멜론 → 1P 1000 / R4 피콘 → COM3 폭발(R5 불참) / R5 멜론 → 1P 1000. 최종 1P 2300, COM1 500, COM2 200, COM3 0. 1인당 한 판 최대 **5,000~5,600pt**(멜론 5개 = 5,000; 원작 최고 기록 5,100pt = 멜론 4 + 포도 1 + 딸기 6개 같은 조합). 잘한 판 = 4,000pt 이상(원작 Hard 도전과제 기준).

## 5. 난이도 곡선

- **돌기 시간(circle)**: 라운드마다 랜덤 2.5~6.0s. 라운드가 갈수록 상한을 늘려 긴장 유지: R1 2.5~4.0, R2 2.5~5.0, R3~R5 2.5~6.0s (불명 — 추정).
- **에이팜 페이크** [확정: 존재. 빈도는 불명 — 추정]: 돌기 구간 중 뚜껑을 `lift` 0→0.35→0 으로 0.25s 동안 들썩임(진짜 열기는 0→1). 회수: R1 0회, R2 0~1회, R3 1회, R4 1~2회, R5 1~2회. 페이크와 진짜 열기 사이 최소 0.8s 간격. 페이크 때 메트로놈은 멈추지 않는다(구분 단서: **음악 정지 + 완전 개방**만 진짜).
- **뚜껑 열리는 속도**: 전 라운드 동일 0.15s(반응 게임이므로 변화 없음).
- **과일 가치**: 라운드가 갈수록 커짐(§4 표). 마지막 라운드 = 최대 [확정: "the last round, which always gives the most points"].
- **피콘 비중**: R3부터 등장, R4 최다 [추정, GameFAQs 팁 기반].
- **COM 난이도** (원작 Easy/Normal/Hard + 해금 Very Hard [확정]; Hyper는 셸 호환용 추가): 핵심 변수는 **반응 지연**, **페이크에 낚일 확률**, **피콘 판별 여부**. Easy는 사람보다 느리고 페이크에 잘 낚이며 피콘도 문다. Very Hard/Hyper는 인간 한계(~180ms)보다 빠르며 피콘은 절대 안 문다 → "초인적 상대" [확정 어구: "super-human opponent"]. 수치는 §8.
- **Hard 이상 대응 가능성**: 사람이 이기려면 동시 도착(같은 프레임) 규칙을 노리거나, 딸기 2등 몫과 피콘 회피로 누적. 하드 이상 COM은 피콘 라운드에서 일부러 안 움직이도록(§8 `p_pinecoBite`) 설계해 사람이 뒤늦게 얻는 기회 제공.

## 6. 화면 구성

- **카메라**: 약간 위에서 내려다보는 3/4 정면(원작은 3D 링 위를 걷는 이브이를 비스듬히 봄). 횡스크롤/탑다운 아님. 원근은 y로만 표현(위쪽 캐릭터 scale 0.9, 아래쪽 1.1).
- **배치 (960×540 기준)**:
  - 원(트랙) 중심 `(480, 320)`, 반지름 rx 250 / ry 120(타원). 캐릭터는 각도 `θ_i = base + i·90°`로 배치, base가 시계 방향으로 **60°/s** 회전(돌기 구간). 정지 구간에서는 그 자리에 멈춰 중앙을 바라봄.
  - 뚜껑+접시+에이팜: 중심 `(480, 300)`. 에이팜은 뚜껑 뒤(y 240) scale 1.3.
  - 돌진 위치: 각 플레이어 각도 방향으로 중심에서 rx 120 / ry 55 떨어진 지점(뚜껑 가장자리).
  - 쉬는 플레이어 대기 위치: 좌하단 `(80, 470)`(sleep).
  - **HUD**: 상단에 4칸 가로 바(`y 12~60`), 각 칸 `x = 20 + i·235`, 폭 220: 플레이어 색 원 + "1P / 2P CPU" 배지(`drawPlayerTag`) + 점수 "1,300" 큰 숫자 우측 정렬. 쉬는 중이면 칸에 "휴식" 회색 오버레이. 캐릭터 머리 위에도 `drawPlayerTag`.
  - 중앙 상단 `y 90`: "라운드 3 / 5". 우상단 음표 아이콘(돌기 중 깜빡).
  - 라운드 결과 팝업: 획득 플레이어 머리 위 "+1000" 금색(`palette.gold`) 1.0s 위로 떠오름; 2등 딸기 "+200" 흰색.
- **배경/색감**: 원작은 밝은 초원/공원 원형 무대 + 파란 하늘. 우리는 `bg` 위에 초록 잔디 타원 무대(`#7cc257`, 테두리 `#5a9a3c`), 트랙은 연갈색 흙길 링(폭 40, `#d9b27a`), 뒤로 나무 3그루(간단 원+기둥). 전체 파스텔 야외. 피콘 폭발 시 화면 전체 0.1s 흰 플래시.

## 7. 연출

- **시작**: 셸 Ready?/Go! 뒤 에이팜이 뚜껑을 두 번 두드림(`sfx.tap`×2) + 자막 "음악이 멈추면 A!" 1.2s.
- **돌기 중**: 메트로놈 beep 0.5s 간격, 캐릭터 `run` 애니메이션, 발밑 작은 먼지 점. 에이팜 페이크: 뚜껑 살짝 들썩 + `sfx.pop` 짧게 + 에이팜 머리 위 "?"; 낚여 플라잉한 플레이어는 뚜껑에 얼굴 박기(`hit` 후 `dizzy`, 머리 위 별 3개 회전, `sfx.bad`), 자막 "플라잉!" 0.6s(그 플레이어 색).
- **B 페이크**: `jump` 0.3s + `sfx.tap`. 자막 없음.
- **열림**: beep 정지 → 0.12s 정적 → 뚜껑 위로 튕김(`sfx.pop` 강하게), 접시 내용물 등장(scale 0.6→1 팝 0.15s).
- **획득**: 1등 플라밍고 `fly`로 중앙 도착 → `eat` 0.8s, 과일이 사라지며 점수 팝업, `sfx.good`. 2등(딸기)은 살짝 늦게 도착해 남은 딸기 `eat`, `sfx.tap`. 3등 이하는 중간에 멈춰 `idle`. 동시 도착 시 둘 다 `eat`, 자막 "동시!".
- **피콘**: 1등이 물자마자 0.2s 뒤 플래시 + 파티클 + `sfx.hit` + 화면 흔들림(±6px, 0.3s). 물은 플레이어 `dizzy` 1.2s, 그을림. 자막 "펑! 다음 라운드 휴식" 1.2s(그 플레이어 색). 2등 이하는 놀라 뒤로 점프(`jump`).
- **아무도 안 잡음**: 뚜껑 닫힘 + 자막 "아무도 못 먹었다…" 0.8s.
- **라운드 전환**: 뚜껑 내려오며 `sfx.tick`, "라운드 N" 자막.
- **종료**: R5 결과 후 1.2s, 최고 득점자 `fly` 반복 + `sfx.win`, 나머지 `idle`(꼴찌 `sleep`). `g.finish()`.
- **아나운서 대사 요지**(원작 미니게임 아나운서, 자막으로 대체): "음악이 멈추는 순간을 노리세요!" / "앗, 너무 빨랐어요! 플라잉!" / "에이팜의 페이크! 속지 마세요!" / "멜론이다! 1000점!" / "피콘이었습니다… 다음 라운드는 쉬어야겠네요" / "마지막 라운드! 가장 큰 점수가 걸려 있습니다!" / "승자는 ○P!"

## 8. AI 행동 모델 (COM)

라운드마다 COM별로 다음을 굴린다. 반응 시간은 정규분포(평균±표준편차, 하한 60ms). 뚜껑이 열리면 `reaction` 뒤에 A 입력. 페이크 이벤트마다 `p_fooled` 확률로 페이크에 반응해 플라잉(스턴 2.0s). 피콘 라운드에서는 `p_pinecoBite` 확률로 그냥 문다(아니면 `reaction`을 무한대로, 즉 안 움직임 — "피콘 확인" 행동). 또한 돌기 중 `p_bFake`/초 확률로 B 페이크를 한다(사람 낚기용, 사람이 페이크에 낚이는지는 사람 몫).

| 난이도 | 반응 지연 reaction(ms) | 페이크에 낚임 p_fooled | 피콘 그냥 묾 p_pinecoBite | 자발적 플라잉(초당) | B 페이크 빈도(초당) | 남의 돌진 따라감 p_follow |
|---|---|---|---|---|---|---|
| Easy | 500±120 | 0.45 | 0.85 | 0.04 | 0.10 | 0.50 |
| Normal | 360±90 | 0.30 | 0.60 | 0.02 | 0.20 | 0.35 |
| Hard | 270±60 | 0.15 | 0.30 | 0.01 | 0.30 | 0.20 |
| Very Hard | 150±25 | 0.05 | 0.10 | 0 | 0.40 | 0.10 |
| Hyper | 110±20 | 0.02 | 0.00 | 0 | 0.50 | 0.05 |

(비평가 수정: 원작 Very Hard COM은 "0.15초 만에 도착"[Serebii 포럼 증언] → 150ms. Hard에서 사람이 4,000pt를 낼 수 있어야 하므로[RetroAchievements 도전과제] Hard는 숙련자 반응(~250ms)보다 느린 270ms. `p_follow`: 뚜껑이 열린 뒤 아직 안 움직인 COM이 다른 플레이어의 돌진/B 페이크를 보면 `reaction` 뒤에 따라서 A를 누를 확률 — 피콘 라운드에서 사람의 B 페이크에 낚여 대신 무는 원작 전략을 재현.)
- 인간 평균 반응 ~220~280ms(키보드 기준) → Normal과 대등, Hard부터 불리, Very Hard는 "초인적" [확정 어구 반영].
- 셸에 난이도 선택이 없으면 COM 3명을 **Normal / Normal / Hard**로 배정한다(2차 비평가 수정: 원작 기본 난이도는 Normal이고 Very Hard는 해금 요소이므로 기본 판에 150ms COM을 넣으면 사람이 한 라운드도 못 이긴다. Very Hard/Hyper 표는 난이도 선택 UI가 생길 때를 위해 남김). 사람이 2명 이상이면 남는 COM 슬롯은 Normal부터 채운다. 슬롯 순서: 사람이 1명이면 2P COM = Hard, 나머지 Normal. 사람이 2명 이상이면 COM은 전원 Normal(구현 확정 해석).
- 피콘을 "확인"하는 COM(안 무는 쪽)은 뚜껑이 열리고 0.4s 뒤 `idle`로 고개만 돌리는 모션(사람이 눈치챌 수 있게).
- 동시 도착 재현: 같은 프레임(≈16ms) 안에 사람과 COM 입력이 겹치면 둘 다 득점 — COM 반응 표준편차 덕에 자연 발생.

## 비평가 보강

독립 검증 출처: Bulbapedia(Eager_Eevee, Stadium_series_mini-games, Aipom) 직접 열람, Serebii 미니게임 페이지 직접 열람, 8bitpickle·TheGamer 직접 열람, RetroAchievements/PokeCommunity/Fandom/GameFAQs는 검색 스니펫(본문 403/402). StrategyWiki는 캡차로 미열람(기존 스펙의 인용은 스니펫과 일치해 유지).

1. **[확정 추가] 원작 점수 스케일**: RetroAchievements 도전과제 "Eager Eevee" = **Hard에서 4,000pt 이상**, 리더보드 최고 **5,100pt(Very Hard)**, 56명 등록. → 한 판 최대는 5,000pt대. §4 확률표를 멜론이 R1부터 나오도록 수정, 딸기 개수 6~10개로 상향, 점수 예시 수정. 결과 화면 감각도 "몇 백 점"이 아니라 "수천 점" 단위여야 원작과 같다.
2. **[확정 추가] Very Hard COM 반응 ≈ 0.15s**(Serebii 포럼 "computer always gets there in like 0.15 seconds"). §8 표를 150±25ms로 조정, Hard 270ms(사람이 4,000pt 낼 수 있는 수준), Normal 360, Easy 500.
3. **[수정] 뚜껑 열린 뒤 B 페이크 유효**: PokeCommunity 전략 "Cautious: 매번 내용물을 확인하고 과일이면 A, 피콘이면 **B로 페인트**해 상대가 대신 물게 한다" / "Ultra aggressive: 1~3라운드는 무조건 GO, 4라운드만 확인해 5라운드 상을 노린다". 따라서 B는 열림 구간에도 동작해야 하며, COM에 `p_follow`(남의 돌진을 보고 따라가는 확률)를 추가해 이 심리전이 성립하게 함. 기존 "열린 뒤 B 무효"는 삭제.
4. **[확정 추가] 열림 후 시간 제한 존재**: Bulbapedia "quickly grab the fruit **before time is up**" → 입력 창이 원작에도 있다. 길이는 여전히 불명, 1.2s 유지(사람이 내용물을 보고 판단할 수 있는 최소 길이이면서 긴장 유지).
5. **[확정 추가] 5라운드·도착 순서 배점**: 8bitpickle "After five rounds, whoever has gathered the most fruit wins" / "Points awarded based on how quickly Eevees reach the fruits, ensuring all players have winning opportunities" → 5라운드, 도착 순서 기반 배분(딸기 1등·2등) 재확인.
6. **[확정 추가] 에이팜 페이크**: Bulbapedia Aipom "lifts the crate, but may also lower it quickly to fake out players" → 페이크 = 들었다가 **빠르게 도로 내림**. §5의 lift 0→0.35→0(0.25s) 유지. 페이크 중 A를 누르면 뚜껑에 박음(플라잉 처리).

8. **[확정 추가] 동점 규칙**: Bulbapedia "if multiple players tie in a single mini-game, they will have to answer a random question to decide the winner" → 원작은 퀴즈. 우리는 셸 공동 순위(기존 결정 유지). Very Hard 해금 = Hard COM 3명 상대 7코인 매치 승리(게임 밖 정보, 참고만).

## 비평가 보강 (2차 · 독립 검증)

2차 비평가가 Bulbapedia(Eager_Eevee·Stadium_series_mini-games), Serebii, 8bitpickle, TheGamer를 직접 다시 열람해 §1~§10과 1차 보강을 대조했다. 확정 규칙(A 돌진/B 페인트, 에이팜 무작위 개방+페이크, 열린 뒤 시간 제한, 피콘 폭발→다음 라운드 휴식, 5라운드, 도착 순 배분, 1/100초 정밀 판정, COM 난이도 선택)은 모두 재확인됐고 **틀린 확정 진술은 없었다**. 아래는 "이 문서만 보고 만들면 원작과 달라질" 구멍을 메운 것이다. 번호는 §11.n으로 인용한다.

1. **[추가] 상태별 입력 규칙 표(구현 기준)** — 기존 §3은 circle/open만 다뤄 intro·resolve·settle 중 A가 플라잉인지 불명확했다.
   | 상태 | A | B | 비고 |
   |---|---|---|---|
   | intro(1.0s) | 무시 | 무시 | 원작도 걷기 시작 전 입력 없음 |
   | circle(돌기) | **플라잉** → 스턴 2.0s | 페이크 모션(쿨다운 0.5s) | 에이팜 페이크 중 A도 플라잉 |
   | open(열림 창 1.2s) | 돌진(라운드당 첫 1회만) | 페이크 모션 유효(피콘 심리전) | 스턴 중이면 둘 다 무시 |
   | resolve/settle | 무시(스턴 아님) | 무시 | 뚜껑이 닫힌 뒤 누른 A로 벌 받지 않음 |
   | 휴식(피콘 페널티) 플레이어 | 전부 무시 | 전부 무시 | 원 밖 sleep |
   - 스턴이 open 도중에 풀리면 그 즉시 A가 유효(늦게라도 돌진 가능, 딸기 2등 몫 노릴 수 있음).
2. **[수정] 기본 COM 난이도 배정**: Normal/Hard/Very Hard 혼합 → **Normal/Normal/Hard**(§8 인라인 수정). 근거: 원작 기본 난이도 Normal, Very Hard는 해금 전용. 사람 반응 ~250ms가 Hard 270ms COM과 접전을 벌이고 Normal은 이기는 구도가 원작 첫 플레이 감각이다. 난이도 선택 UI가 생기면 표 그대로 사용.
3. **[추가] 스턴 중 플레이어의 위치·연출**: 플라잉한 플레이어는 뚜껑 가장자리까지 `fly`로 갔다가 `hit`(0.3s) 때 자기 슬롯 각도 방향으로 40px 튕겨 나온 뒤, **원의 회전에 그대로 실려**(θ_i는 계속 base+i·90°) `dizzy`로 끌려간다. 다른 3명의 회전은 멈추지 않는다. 스턴 해제 시 `run`으로 복귀. 이렇게 해야 "한 명이 박아도 게임은 계속 도는" 원작 리듬이 유지된다.
4. **[추가] 돌진 방향·이동 규칙**: 돌진 시 `flip`은 중앙을 향하도록(x가 중심보다 크면 flip). 돌진 목표 = §6의 뚜껑 가장자리 지점(rx 120/ry 55). 1등·2등(딸기)만 접시까지 추가로 30px 들어가 `eat`. 3등 이하는 가장자리에서 `idle`로 정지 후 settle에 자기 슬롯으로 0.4s 복귀. 판정은 **누른 시각** 기준이며 이동 애니메이션 길이(0.25s)는 판정에 영향 없다.
5. **[추가] 피콘 라운드 COM 심리전 보강**: 피콘을 "확인"하기로 한 COM(안 무는 쪽)은 Hard 이상이면 `p_bFakeOnPineco = 0.5`(Normal 0.25, Easy 0) 확률로 열림 후 `reaction` 시점에 **B 페이크**를 한 번 한다(사람을 낚아 대신 물게 하려는 원작 전략의 COM판). 사람이 낚여 A를 누르면 사람이 1등으로 피콘을 물고 휴식.
6. **[추가] 접시 내용물 가독성 요건**: 사람이 뚜껑이 들리는 0.15s + 자기 반응 시간 안에 "과일인가 피콘인가"를 판단해야 하므로, 내용물은 뚜껑 lift 0.3 시점부터 이미 보이게 그리고(뚜껑 뒤에서 드러남), 피콘은 과일 3종과 색상군이 겹치지 않게(회청 `#7d8fa3` 본체 + 검은 눈) 그린다. 팝 스케일 0.6→1은 실루엣 판별을 늦추므로 **피콘·멜론처럼 큰 소품은 팝 없이 즉시 풀 사이즈**, 딸기·포도만 팝.
7. **[추가] 동시 도착의 정의와 3~4인 동시**: 같은 프레임(`dt` 차 ≤ 16ms)에 A를 누른 모두가 "1등". 포도/멜론이면 전원 만점, 딸기면 1등 몫을 N/동시인원(올림)씩. 동시 1등이 2명 이상이면 2등 딸기 몫은 없음. 피콘이면 동시 1등 **전원** 폭발·휴식(불명 — 추정, 규칙 대칭성 유지).
8. **[추가] 열림 창 종료 조건 정리**: (a) 포도/멜론: 첫 유효 A가 들어온 프레임에 즉시 닫힘(같은 프레임 동시만 허용). (b) 딸기: 첫 A 후 0.35s 유예 동안 두 번째 A 허용, 그 뒤 닫힘. (c) 피콘: 첫 A 즉시 폭발·닫힘. (d) 아무도 없음: 1.2s 경과 후 닫힘. 창이 닫힌 뒤 도착한 A는 무시(§11.1).
9. **[추가] 라운드 길이·전체 템포 목표**: 라운드 = intro 1.0 + circle 2.5~6.0 + open ≤1.2 + resolve 1.6(피콘 2.4) + settle 0.8 ≈ 7~11s → 5라운드 40~55s. 원작 한 판 체감(약 1분)과 맞는다. 60°/s 회전(한 바퀴 6s)은 유지하되 `run` 위상은 beep(0.5s)에 동기화(1차 보강 10번).
10. **[추가] HUD 확정안**: 1차 보강 9번의 "네 귀퉁이 패널"을 기본으로 확정한다. 패널 크기 200×48, 1P (16,12) / 2P (744,12) / 3P (16,480) / 4P (744,480). 내용: 플레이어 색 띠 + `drawPlayerTag` + 점수(우측 정렬, 천 단위 콤마) + 상태 아이콘(★ 현재 1위, 💤 대신 "휴식" 회색 텍스트, 별 3개 = 스턴). 라운드 표시 "라운드 3 / 5"는 상단 중앙 y 40. 이 배치는 원의 상하좌우 여백(트랙이 y 200~440)을 침범하지 않는다.
11. **[추가] 종료 후 result 텍스트**: `text`에 "멜론 N개 · 포도 N개 · 딸기 N개" 대신 간단히 "5라운드 합계"만. 동점은 셸 공동 순위(퀴즈 없음, 1차 보강 8번 유지).
12. **[확정 재확인] 일본명 イーブイのフルーツダッシュ**(Bulbapedia 직접 열람) — 시작 자막 "프루츠 대시!" 사용 가능.
