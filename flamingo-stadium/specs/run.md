## 1. 한 줄 요약 · 등장 요소와 플라밍고 대체안

**한 줄 요약**: 4마리 꼬렛(Rattata)이 나란히 놓인 4개의 러닝머신(treadmill) 위에서 A 버튼 연타로 달리고, 무작위로 튀어나오는 허들(hurdle)을 십자키 ↑로 뛰어넘어 **50 m 골인 지점에 먼저 닿는 쪽이 이기는** 연타 레이스.

| 원작 요소 | 원작 묘사 | 플라밍고 대체안 (`drawFlamingo` 포즈) |
|---|---|---|
| 꼬렛(Rattata) ×4, 플레이어 색으로 구분 | 보라색 쥐, 연타에 맞춰 다리 휘적임 | 플라밍고 ×4, `palette.players[i]` 색. 정지 시 `idle`, 달릴 때 `run` (애니 속도 = 현재 속도에 비례), 점프 `jump`, 허들 충돌 후 넘어짐 `hit` → 일어날 때까지 `dizzy`, 골인 후 `fly`(1위) / `idle`(그 외), 제한시간 내 미완주 `sleep` |
| 러닝머신 벨트 ×4 (레인) | 잔디 느낌의 초록 벨트, 검은 고무 롤러, 앞쪽에 레인 번호 | 4개의 가로 벨트, 벨트 무늬가 각 주자의 속도로 왼쪽으로 흐름(주자 위치는 화면에서 거의 고정) |
| 허들(hurdle) | **[영상 확인·정정]** 육상 허들이 아니라 **레인 폭의 체크무늬 판자(플레이어색+흰색 체크, 1P 파랑·2P 초록·3P 빨강·4P 노랑)** 가 벨트 앞쪽에서 솟아 다가온다. 뛰어넘으면 세워진 채 뒤로 흘러가고, 부딪히면 판자가 납작하게 접힌다 | 플레이어색+흰색 체크 판자(자체 드로잉). 충돌 시 접혀 눕는다 |
| 5 m 간격 거리 표시(5,10,…,45) | **[영상 확인·정정]** 표지판이 아니라 **벨트 바닥에 흰 가로선 + 숫자(5, 10, 15 …)가 페인트**로 찍혀 벨트와 함께 흐른다. 바닥 재질도 구간별로 바뀜(잔디→흙→모래→흙/잔디→`GOAL` 글자 반복 프린트 구간→노란 결승선) | 벨트 바닥에 흰 선+숫자 프린트, 45 m 이후 빨간 `GOAL` 글자 무늬, 50 m에 노란 선 |
| 골 라인 | **[영상 확인]** 테이프 없음. 50 m 지점 노란 선. 골인한 주자는 그 자리에 앉고 레인 끝에 **순위 숫자가 적힌 작은 흰 깃발(1·2·3·4)** 이 꽂힌다 | 노란 선 + 순위 흰 깃발 팝업 |
| 아나운서 | 영어 음성 | 화면 텍스트 + `sfx` (§7) |

## 2. 인원 · 시간 · 종료 조건

- **4인 동시 플레이** (사람 1~4 + CPU 나머지). 모든 Kids Club 미니게임은 항상 4명이 뛴다. [확인]
- **트랙 길이 50 m**, 5 m 간격 표지 (5, 10, 15, 20, 25, 30, 35, 40, 45 m). [확인 — GameFAQs 50319]
- **종료 조건**: 1위 골인 시점부터 나머지 주자에게 **잔여 제한시간(time limit)**이 부여되고, 그 안에 골인 못 하면 실격(DNF) 처리. [확인 — Bulbapedia: "Once a player reaches the goal, the rest have a time limit to finish their race"]
  - 제한시간 길이: **[영상 실측·정정] 매우 짧다.** 원작 영상 3편 프레임 계측: 1위 골인 → `WINS` 표시까지 **2.2초**(byK), **2.0초**(mi52 2차), **7.2초**(pe4; 1위가 25.7초로 느린 경기). 두 사례가 2초대이므로 **기본 2.5초**를 쓴다(pe4의 7초는 난이도(Easy) 의존 가능성 — 불명). 즉 "1위가 들어오면 거의 바로 끝난다"가 원작 감각이며, 10초 추정은 **폐기**.
  - **4명 전원 골인 시에는 즉시 종료**(mi52 1차: 4위 깃발과 `1P WINS`가 같은 프레임). 미완주자는 깃발 없이 레인에 남는다.
- **한 판 길이**: **[영상 실측]** `Go` → 1위 골인 **20.5 / 20.8 / 22 / 25.7초**(4경기). 즉 1위 기준 **20~22초**가 표준, 종료는 1위 골인 + 2.5초(또는 전원 골인). KoopaTV "about twenty seconds"와 일치.
- **라운드 구조**: 단판 레이스 1회. 재경기 없음. 셸 `duration`은 **0(무제한)** 으로 두고 게임이 `g.finish()`를 직접 부른다 (1위 골인 + 2.5초, 또는 4명 전원 골인 시 즉시).
- 시작 전 카운트다운: **[영상 확인] 분홍색 3D 숫자 `3` → `2` → `1` → `Go`**, 각 약 1초 (§7). 카운트다운 중 입력 무시(연타해도 속도 0).

## 3. 조작

원작 N64 조작 (Bulbapedia / Serebii / GameFAQs / 인게임 설명문 "Tap the A Button repeatedly to run. Press up on the Control Pad to jump over hurdles. The first one to the goal wins."):

| N64 | 원작 기능 | 우리 액션 매핑 |
|---|---|---|
| **A (연타)** | 달린다. 연타 속도가 빠를수록 빠르다 (Serebii: "the faster you press the button, the faster Rattata moves"). 홀드는 무효. | **`a` 연타** (`hit('a')`). `down`은 무시. |
| **십자키 ↑** | 허들 점프 (Serebii는 "D-Pad 아무 방향"이라고 하나 공식 설명문은 ↑). | **`up`** = 점프. 관대하게 `b`로도 점프 허용(초보 배려, 안내문에는 ↑만 표기). |
| B, C, 스틱, L/R, Z | 사용 안 함 | `left/right/down`은 무시 (기존 구현의 좌우 번갈아 달리기 방식은 원작과 다르므로 **폐기**). |

**입력 규칙 (재현 사양)**

- **연타 → 속도 모델** (원작 수치는 불명 — 추정, 목표: 초당 8~10회 연타 시 50 m를 약 17~19초에 완주):
  - `speed`(m/s)는 매 탭마다 `+0.55 m/s` 가산, 상한 `MAX = 3.3 m/s` (**비평가 조정**: 실측 1위 20.5~22초에 맞춤. 3.6이면 17초대가 나와 원작보다 빠르다).
  - 매 프레임 감쇠 `speed -= speed * 1.6 * dt` (탭을 멈추면 약 1초 안에 거의 정지 → "연타를 멈추면 러닝머신 위에서 제자리"라는 원작 인상).
  - 정상상태 속도 ≈ `0.55 * 연타율 / 1.6` → 5회/s = 1.7 m/s, 8회/s = 2.75 m/s, 10회/s = 3.4 m/s.
  - 같은 프레임의 중복 입력은 1회로 센다. 홀드 무효(키 반복 없음). **탭 간격 40 ms 미만은 무시**(터보 방지).
  - KoopaTV 주장("furious mashing과 moderate mashing의 차이가 없다")을 반영해 **연타율 6회/s 이상은 수확 체감**: 위 상한 **3.3 m/s**로 자연 처리(연타 9.6회/s 이상은 전부 상한에 걸림 → "더 미친 듯이 눌러도 안 빨라진다"는 KoopaTV 인상과 일치). [2차 정정: 3.6→3.3 통일]
- **점프**: 지면에 있을 때 `up` 누른 프레임에 즉시 도약. 공중에서는 재점프 불가. 체공 **약 0.55초**(추정), 점프 높이는 허들 높이의 ~1.6배. 공중에서도 수평 속도는 유지되고 연타 가산도 유지된다(원작에서 점프 중 감속 인상 없음).
- **점프 판정 창** [2차 정정: 거리 고정이 아니라 **속도 의존**]: 체공 0.55 s 동안 주자는 `0.55 × speed` m를 나아가므로, 허들이 주자 앞 **`0 < gap ≤ 0.55·speed − 0.35` m** 에 있을 때 점프하면 확실히 넘는다(3.3 m/s → 1.46 m, 2.5 m/s → 1.0 m, 1.5 m/s → 0.47 m). 그보다 앞에서(예: 3 m/s에서 2.2 m 앞) 점프하면 착지 후 부딪힌다. 속도 0.6 m/s 미만이면 어떤 타이밍에도 못 넘으므로 "연타를 멈추면 허들에 걸린다"는 자연 페널티가 생긴다. 허들 통과 판정은 `|hurdle.d - dist| < 0.35 m` 이면서 발 높이 < 허들 높이일 때 충돌.
- **충돌 시**: 속도 즉시 0, 넘어짐(`hit`) 후 일어나기(`dizzy`) **총 1.2초** 입력 불능(추정; StrategyWiki "come to a halt", Twinfinite "lose a lot of time as it recovers"). 뒤로 밀리지는 않는다(원작에 후퇴 묘사 없음). 허들은 넘어지며 사라지고 재판정 없음.

## 4. 규칙과 점수

- **점수 단위**: 순위(완주 순서). 내부적으로는 **완주 시간(초)** 을 기록해 `lowerIsBetter:true`로 셸에 넘긴다.
  - 완주자: `scores[i] = 골인 시각(초, 소수 2자리)`.
  - 제한시간 내 미완주(DNF): `scores[i] = 999 + (50 - dist)` — 완주자보다 항상 뒤, DNF끼리는 더 멀리 간 쪽이 앞.
- **가산/감산**: 점수 개념 없음. 유일한 페널티는 허들 충돌로 잃는 시간(§3, 1.2초 + 재가속 시간 ≈ 실질 2~3초 손실).
- **승리 판정**: 골인 라인(50 m)에 **먼저 닿는** 플레이어가 1위. 이후 도착 순으로 2·3·4위. [확인]
- **동점 처리**: 같은 프레임 골인 시 원작은 "tie" 인정(Who's The Champion? 모드에서 동시 승자 가능; GameFAQs "if you win a game (or tie for the victory)"). 우리는 `scores` 동일값 → 셸이 공동 순위 처리. dt 내 보간해서 정확한 골인 시각(`t - (dist-50)/speed`)을 쓰면 동점은 사실상 발생하지 않는다.
- **원작 점수 예시**: 화면에 숫자 점수는 없다. 기록 예시(추정): Normal에서 사람이 8회/s 연타, 허들 0회 충돌 → 약 18.5초 골인. 허들 1회 충돌 시 약 21초.
- **HUD 표시**: 각 레인에 현재 거리 `23 m` 와 순위 배지(골인 후 `1위` 등).

## 5. 난이도 곡선

**시간에 따른 변화 (원작)**: 트랙 자체는 가속하지 않는다. 난이도는 (a) 플레이어 자신의 속도가 빨라질수록 허들 반응 시간이 짧아짐(Twinfinite: "The faster you go, the faster your reflexes must be"), (b) **카메라가 계속 회전**해 허들이 보이는 각도가 달라짐, 두 가지에서 온다.

**허들 배치 (추정)**: 레인마다 독립 무작위(8bitpickle: "obstacles appear at different times for all Rattatas").
- **[영상 확인·정정]** 허들은 훨씬 잦다. 4경기 모두 **거의 모든 5 m 구간마다 1개**(5, 10, 15 … 45 m 표시선 근처)가 레인별로 서로 다른 위상으로 나온다. 재현: 구간 k(5k m, k=1..9)마다 확률 **85 %** 로 `5k + rand(-1.5, +1.5) m` 위치에 1개 → 레인당 **7~9개**. 인접 허들 최소 간격 3 m. 45~50 m `GOAL` 구간에는 없다.
- 난이도 설정에 따라 허들 수는 바뀌지 않는다(추정; 난이도는 CPU에만 영향).
- 허들은 주자 앞 **약 5 m**(벨트 앞쪽 끝, 영상에서 벨트 길이가 대략 5~6 m 분량) 지점에서 벨트에서 "솟아오르며"(0.25초 팝업 애니) 등장한다 → 2.5~3 m/s 속도에서 반응 여유 ≈ 1.7~2.0초. 원작 화면에서는 허들이 등장하면 곧바로 다가오므로 "보고 뛰는" 리듬이 약 2초 간격으로 반복된다.

**카메라 회전 ([영상 실측])**: 원작은 3D 궤도 카메라가 플랫폼 주위를 **한 방향으로 계속** 돈다 — 카운트다운 때 정면(레인 번호 1~4가 화면 아래)에서 시작해 골인 무렵 약 180° 돌아 반대편(골 라인이 카메라 쪽)에 오며, 동시에 서서히 줌인한다(약 **50초/1회전**, 등속). 2D 재현안: 전체 장면을 좌우 **±6° 기울임 + 약한 원근 스케일**을 `sin(t * 0.13)`(약 50초 주기)로 주거나, 배경만 회전시킨다. [2차 권고: 원작은 왕복이 아니라 **단방향**이므로 배경 시차는 `bgX = -t * 12 px/s`(등속 한 방향)로, 기울임만 `sin`을 쓴다.] 가독성을 해치지 않는 선에서 "흔들리는 느낌"만 재현. (완전 생략도 허용하나 리뷰어가 회전을 기대하므로 최소한 배경 시차 이동은 넣는다.)

**CPU 난이도 (원작 Easy / Normal / Hard / Hyper — 스타디움 1에는 Very Hard 없음; Hyper는 **"Who's The Champion?" 모드를 Hard로 5연승** 시 해금 — Bulbapedia 재확인)**

| 난이도 | 원작 행동 묘사 | 목표 완주 시간(허들 무충돌) | 연타율(회/s) | 허들 실수율 |
|---|---|---|---|---|
| Easy | "ridiculously feeble-minded" | 28~34초 | 3.5~4.5 | 25 % |
| Normal | "not embarrassingly easy, not a pushover" | 21~24초 | 6~7 | 10 % |
| Hard | "not exactly a breeze" | 18~20초 | 8~9 | 4 % |
| Hyper | "rarely make mistakes, will not slow down for any reason" / "hard on your fingers especially on Hyper" | 16~17초 | 10~11 | 1 % |

우리 셸에는 난이도 선택이 없으므로 **기본은 Normal~Hard 사이**: CPU 3명에게 슬롯 순으로 `Normal`, `Hard-`(연타 8.0회/s), `Hard` 를 배정해(§8과 동일 순서) 사람이 열심히 연타하면 이길 수 있게 한다. 사람 수 2 이상이면 남은 CPU에 Hard부터 배정.

## 6. 화면 구성

**원작**: 3D. 야외(Kids Club 공원, 잔디·하늘·나무·트랙 펜스)에 놓인 **높은 단상 위 4레인 러닝머신 플랫폼**(classicnerd: "a raised platform that looked like a grassy treadmill with four lanes"). 카메라는 플랫폼을 비스듬히 내려다보며 천천히 궤도 회전, 꼬렛은 화면 왼쪽→오른쪽(또는 안쪽) 방향으로 달림. 화면 상단에 플레이어별 진행 표시.

**우리 재현 (960×540)**:
- **시점**: 횡스크롤형 측면 뷰. 4개 레인을 위에서 아래로 1P→4P 순서(레인 높이 121 px, 상단 56 px부터). 각 레인 왼쪽 150 px 지점에 주자 고정(원작도 주자는 벨트 뒤쪽에 고정), 벨트와 허들이 왼쪽으로 흐른다.
- **레인 색**: 벨트는 초록 잔디 톤(`#7CC36B` / 줄무늬 `#68B25A`), 롤러/테두리 진회색, 레인 왼쪽 끝에 플레이어 배지(`drawPlayerTag`). 사람 레인은 배경을 살짝 밝게.
- **거리 표시**: 벨트 바닥에 5 m 간격 흰 가로선+숫자가 페인트되어 벨트와 함께 흐르고, 구간별로 바닥 색이 바뀐다(잔디→흙→모래→흙→`GOAL` 프린트). 50 m에 노란 결승선(테이프 없음).
- **HUD**:
  - 화면 최상단 44 px: 4명 진행 바(50 m 트랙 미니맵). 각 플레이어 색 점이 왼→오로 이동, 골인 시 순위 숫자.
  - 각 레인 오른쪽 끝: `NN m` 큰 숫자 + 순위(골인 후) 또는 `DNF`.
  - 1위 골인 후 화면 중앙 상단에 `남은 시간 2.5` → `0.0` 카운트다운(빨간색, 소수 1자리). [2차 정정: 9.8은 폐기된 10초 추정의 잔재]
- **배경**: 밝은 하늘 그라데이션(`#9ED9FF`→`#E8F7FF`), 먼 나무·펜스 실루엣이 카메라 흔들림에 따라 시차 이동. 색감은 원색·파스텔의 N64 Kids Club 분위기.
- **[영상 확인·정정] 원작에는 HUD가 전혀 없다.** 상단 진행 바·거리 숫자·타이머 없음. 정보는 (1) 플랫폼 앞면의 색 레인 번호 `1 2 3 4`(1P 파랑·2P 초록·3P 빨강·4P 노랑), (2) 벨트 바닥의 5 m 숫자, (3) 골인 시 레인 끝 순위 깃발뿐. 위 HUD(진행 미니맵·`NN m`)는 CONTRACT의 "각 플레이어 상태 상시 표시" 요건 때문에 넣는 **추가분**이며, 원작 감각을 위해 작게(상단 44 px, 반투명) 유지한다.

## 7. 연출

- **시작**: **[영상 확인]** 4명 벨트 위 `idle`, 카메라가 넓은 원경에서 줌인하며 화면 중앙에 분홍 3D 숫자 `3`(1.0초) → `2`(1.0초) → `1`(1.0초, 각 `sfx.count`) → `Go`(약 0.8초 표시, `sfx.go`). 문자 텍스트가 아닌 숫자 카운트다운이며 "Ready?" 문구는 없다. 출발 전 연타는 무효.
- **달리기**: 탭마다 `sfx.tap`(연타 리듬이 들리게, 사람만). `run` 포즈 애니 속도 = speed/MAX. 속도가 0.3 m/s 아래로 떨어지면 `idle`(벨트 위에서 제자리 흔들림).
- **허들 등장**: 벨트에서 0.25초 동안 솟아오름, `sfx.tick` 짧게(사람 레인만).
- **점프 성공**: `jump` 포즈 0.55초, 착지 시 작은 먼지 파티클(추정). 효과음 없음(성공은 조용히, 실패만 크게 — 원작 인상).
- **허들 충돌**: `sfx.bad`, 허들이 넘어지고 주자가 `hit` 0.4초 → `dizzy` 0.8초(머리 위 별 회전), 화면 텍스트 없음. CPU도 동일 연출.
- **골인**: **[영상 확인]** 테이프 없음. 주자는 결승선 너머에 앉아(`idle`) 멈추고, 레인 끝에 **순위 숫자가 적힌 작은 흰 깃발**이 꽂힌다(`sfx.good`, 1위는 `sfx.win`). 화면 중앙 텍스트는 없다. 1위 골인 순간 나머지에게 2.5초 카운트다운 시작(원작은 타이머를 표시하지 않지만 우리는 작게 표시).
- **제한시간 만료**: 미완주 주자 `sleep` 포즈 + `sfx.lose`, 레인에 `시간 초과`.
- **종료**: **[영상 확인]** 전원 골인 또는 시간 만료 즉시 화면 중앙에 **`1P WINS`**(파란 원형 `1P` 배지 + 노란 굵은 `WINS`; CPU 승리면 노란 `COM` 배지 + `WINS`, 3P면 빨간 `3P` 배지) 배너, 승자 주자가 제자리에서 **뛰어오르는 기쁨 동작**(`jump` 반복), 카메라가 플랫폼 옆으로 내려앉음. 약 **5초** 유지 후 메뉴. 우리는 `N P 승리!` 배너 + 승자 `fly`/`jump` 2.0초 → `g.finish()` → 셸 순위 화면. 음성 아나운서는 확인되지 않음(효과음만).

## 8. AI 행동 모델 제안

CPU는 사람과 같은 입력 파이프라인(가상 탭 + 가상 점프)을 통해 움직인다. 모델 파라미터:

| 파라미터 | Easy | Normal | Hard | Hyper |
|---|---|---|---|---|
| 평균 연타율 (회/s) | 4.0 | 6.5 | 8.5 | 10.5 |
| 연타율 흔들림 (±, 주기 2~4초 사인+노이즈) | ±1.2 | ±0.9 | ±0.6 | ±0.3 |
| 허들 인지 반응 지연 (ms, 허들이 판정 창 진입 후) | 380 ± 140 | 240 ± 90 | 160 ± 60 | 90 ± 30 |
| 점프 타이밍 정확도 (판정 창 내 점프 확률) | 0.75 | 0.90 | 0.96 | 0.99 |
| 실수 유형 | 늦게 뜀 60 % / 너무 일찍 40 % | 동일 | 동일 | 동일 |
| 충돌 후 재가속까지 추가 지체 (s) | 0.6 | 0.3 | 0.1 | 0.0 |
| 출발 반응 지연 (ms, "출발!" 후) | 500 | 300 | 180 | 80 |

- 반응 지연은 판마다 CPU별로 고정 샘플링(가우시안, 위 ± 값이 1σ)하고, 허들마다 다시 ±30 % 흔들림.
- "너무 일찍" 실수는 허들 2.5~3.5 m 앞에서 점프 → 착지 후 충돌. "늦게" 실수는 판정 창을 지나 충돌.
- Hyper는 "절대 느려지지 않음"을 재현하기 위해 흔들림 ±0.3, 실수 1 %.
- 셸 기본 배정(§5): 슬롯 순으로 `Normal`, `Hard-`(연타 8.0), `Hard` — 사람이 8회/s 이상 연타하고 허들을 안 맞으면 이길 수 있고, 한 번 맞으면 지는 균형.

9. **충돌 연출 확인** — 부딪힌 주자는 앞으로 구르며 넘어졌다가 제자리에서 일어남(약 1.0~1.5초), 뒤로 밀리지 않음. 판자는 접힘.
10. **동점 규칙 보강** — 순위는 골인 프레임 순. 같은 프레임이면 `t - (dist-50)/speed` 보간값이 작은 쪽이 앞이고, 완전 동일하면 낮은 슬롯 번호(1P) 우선(원작 표시상 동시 깃발은 관찰되지 않음).
11. **CPU 성능 실측 힌트** — 영상에서 CPU 3명은 1위와 0.5~4초 차이로 들어오고, 골인 못 한 CPU도 결승선 3~5 m 앞까지는 온다. §8 표는 유지하되 Hard-/Normal CPU의 완주 목표를 21~24초로 두면 실측 분포와 맞는다.

## 비평가 보강 (2차 · 독립 검증)

검증 방법(2차): Bulbapedia 미니게임 페이지·Kids Club 페이지, Serebii Kids Club, StrategyWiki(curl), KoopaTV, CBR을 **독립적으로 다시 열어** 1차 인용문이 실제 원문과 일치하는지 확인했다. 결과: 규칙·조작·제한시간 존재·4인 고정·Hyper 해금 조건 인용은 모두 원문과 일치. GameFAQs 50319·web.archive·pokemon.fandom은 이번에도 403/Cloudflare로 접근 불가(1차와 동일). 원작 수치(속도·정지 시간·허들 간격)는 텍스트 출처 어디에도 없으므로 1차의 영상 계측이 유일한 근거이며, 그 값들을 그대로 신뢰하되 **문서 내부 모순**과 **구현 시 어긋날 항목**을 아래처럼 고쳤다.

**정정(인라인 반영)**

1. **속도 상한 모순 해소** — §3에 3.3 m/s와 3.6 m/s가 섞여 있었음 → **3.3 m/s**로 통일. 정상상태 식 `0.55·rate/1.6` 기준 9.6회/s부터 상한에 걸리므로 KoopaTV의 "미친 듯이 눌러도 차이 없음" 인상이 수치로 재현된다.
2. **점프 판정 창을 속도 의존으로 정정** — "0.9 m 이내면 확실히 넘는다"는 저속에서 거짓(1.5 m/s에서 0.9 m 앞 점프 → 0.6 s 뒤 도달, 체공 0.55 s 초과 → 충돌). 안전 창 = `0 < gap ≤ 0.55·speed − 0.35`. CPU 인지도 거리 대신 **시간 기준**(§8 보강 참조)으로 바꿔야 저속 CPU가 매번 걸리지 않는다.
3. **HUD 잔여 타이머 9.8 → 2.5초** — §2·§7의 2.5초 결정과 어긋난 §6 문구 정정.
4. **CPU 배정 순서 통일** — §5와 §8이 달랐음 → 슬롯 순 `Normal`, `Hard-`, `Hard`.
5. **Hyper 해금 명칭** — "Who's the best"가 아니라 Bulbapedia 원문 **"Who's The Champion?"** 모드 Hard 5연승.
6. **제목 각주** — "달려라 플라밍고"는 7자로 8자 이내 조건을 충족한다(원문의 "8자 이내는 아니지만" 삭제).
7. **카메라 2D 대체** — 원작이 단방향 회전이므로 배경 시차는 `sin`이 아니라 등속 한 방향 드리프트로.

**추가(구현에 필요한데 빠져 있던 것)**

8. **골인 시각 기준점** — `scores[i]`의 완주 시간은 카운트다운을 제외한 **`Go` 표시 순간 = 0 s** 기준. 카운트다운(3·2·1 각 1.0 s + Go 0.8 s) 동안 `g.time`이 흐르지만 레이스 시계는 `Go`에서 시작한다. 셸 결과 화면의 `text`에는 `1P 20.84초` 처럼 1위 기록을 넣는다.
9. **허들·점프의 구체 치수(월드 단위)** — 허들 판자 높이 **0.5 m**, 두께 0.35 m(판정 폭 ±0.35 m와 동일). 점프는 포물선 `y(τ) = 4·H·(τ/T)·(1−τ/T)`, `T=0.55 s`, 정점 `H=0.8 m`(허들의 1.6배). 충돌 = `|hurdle.d − dist| < 0.35` **이고** `y < 0.5`. 픽셀 환산 `PXM=38 px/m` 유지(50 m = 1900 px, 화면에 보이는 벨트 = 약 20 m).
10. **허들 등장 거리 정정 보강** — §5의 "주자 앞 약 5 m 팝업"은 유지하되, 2D 화면에서는 벨트가 화면 오른쪽 끝(주자 +21 m)까지 보이므로 **허들은 벨트 위 존재는 하되 `gap ≤ 5 m`가 되기 전에는 그리지 않는다**(원작의 "솟아오름" 재현 + 반응 시간 유지). 5 m/3.3 m/s = 1.5 s가 최소 반응 여유.
11. **CPU 허들 인지 모델을 시간 기준으로** — §8의 "반응 지연 ms"는 **허들이 팝업(gap = 5 m)한 순간부터의 지연**이 아니라, CPU가 노리는 **점프 시점 = 허들 도달 예상 `0.30 s` 전(`gap ≈ 0.30·speed`)** 에 반응 지연(Easy 380 ms … Hyper 90 ms, ± 1σ 샘플)을 더한 순간에 `up`을 누르는 것으로 정의한다. 지연이 양수로 크면 "늦게 뜀"(창을 지나 충돌), 음수로 크면 "너무 일찍"(착지 후 충돌)이 자연 발생하므로 §8의 실수 유형 비율(60/40)은 σ의 비대칭(`+1.2σ / −0.8σ`)으로 구현하면 된다. 안전 창 폭이 속도에 비례하므로 빠른 CPU(Hyper)가 오히려 창이 넓어 실수가 줄어드는 것도 원작 인상("Hyper는 좀처럼 실수하지 않는다")과 맞는다.
12. **CPU 연타는 가상 탭 이벤트로** — 연타율 r(회/s)을 `speed` 목표값으로 직접 쓰지 말고 **포아송/지터 있는 탭 타이머**(간격 `1/r × rand(0.85,1.15)`)로 `tap()`을 호출해 사람과 같은 가산·감쇠 파이프라인을 태운다(CONTRACT "반응 지연·정확도 모델" 요건). 출발 반응 지연(§8)은 `Go` 이후 첫 탭까지의 지연.
13. **충돌 중 입력 처리** — 정지 1.2 s(hit 0.4 + dizzy 0.8) 동안 `a`·`up` 모두 무시하고 탭 효과음도 내지 않는다. 정지 해제 시 `speed=0`에서 재가속(시간상수 1/1.6 ≈ 0.6 s → 90 % 도달까지 약 1.4 s). 따라서 충돌 1회의 실질 손실 ≈ 1.2 + 1.4 ≈ **2.6 s**(§4 "2~3초" 확인).
14. **원작에 없는 요소 명시(추가 금지 목록)** — 특수 아이템·보너스·나쁜 허들·가속 패드·트랙 가속·라운드 반복·CPU 러버밴딩은 **없다**(Bulbapedia·Serebii·StrategyWiki·KoopaTV·CBR 어디에도 등장하지 않음). 유일한 장애물은 허들뿐. 구현자는 "재미를 위해" 이런 것을 넣지 말 것.
15. **연타 홀드 무효 확인** — CBR "requiring button-mashing rather than holding" 재확인. `down('a')`로 속도가 붙으면 안 된다.
16. **점프 입력** — Serebii는 "D-Pad 아무 방향", 공식 설명문·Bulbapedia는 ↑. 구현은 `hit('up')`(+ 관대하게 `hit('b')`)만. `down/left/right`는 점프로 인정하지 않는다(좌우 연타 구현과의 혼동 방지).
17. **전원 종료 후 흐름** — 1위 골인 + 2.5 s(또는 전원 골인) → `N P 승리!` 배너 + 승자 `jump` 반복 2.0 s → `g.finish()`. 배너 중에는 입력 무시. DNF 주자는 `sleep`, 점수 `999 + (50 − dist)`.
18. **화면 레이아웃 재확인** — 4레인을 위→아래 1P→4P, 레인당 121 px(56 + 4×121 = 540). 각 레인: 왼쪽 `drawPlayerTag`, x=150에 주자, 오른쪽 끝 `NN m` + 순위/DNF. 색은 원작 색(파·초·빨·노) 대신 **`palette.players[i]`(1P 분홍·2P 파랑·3P 노랑·4P 초록)를 배지·허들 체크·미니맵 점 모두에 통일**해 사용한다(원작의 "레인 색 = 플레이어 색" 규칙은 유지, 색값만 셸 팔레트).

**남은 불명(구현에 지장 없음)** — 제한시간의 난이도별 차이(2.5 s 고정 채택), 원작 속도 모델의 진짜 수식(실측 완주 시간 기준으로 보정 완료), 음성 아나운서 대사(효과음 대체).
